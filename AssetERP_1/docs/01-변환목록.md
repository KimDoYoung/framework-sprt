# 01. 변환목록 (작업 ID와 상태)

전체 작업목록이다. 작업 ID마다 상태를 적는 **유일한 상태판**이므로 상태는 여기에만 적는다.
ID 하나의 기록은 `work/{id}-작업방법.md`, `work/{id}-작업기록.md`, `work/{id}-결과확인.md`에 남는다(05·06의 템플릿으로 시작할 때 만든다).

- 상태: `대기` → `분석` → `백엔드` → `프론트` → `확인` → `완료`, 또는 `보류`(사유를 비고에 적음). B 작업은 `대기` → `진행` → `완료`.
- 진행 순서는 04를 따른다. A는 ID 번호 순서가 곧 진행 순서다.
- 상태를 바꿀 때마다 날짜를 `{id}-작업기록`에 남긴다. 여기에는 결과만 적는다.

### 요약 (2026-10-07, B01~B03 기준)

- 36개 중 원본에 소스가 있는 것 35개(`Sys03`은 메뉴 키 오타, `Sys96`은 메뉴 키와 클래스 이름이 다름), 소스 없음 1개(`Sys60_Tab_FilePolicy`).
- 화면이 쓰는 테이블 중 asseterpdb에 없는 테이블은 없다(색인 `## 테이블` 절 기준). 화면 UI 절의 `⚠DB없음`은 그리드 컬럼 이름이 DB 컬럼과 다른 표시이므로 분석 단계에서 본다.
- OMS에서 변환한 적 있는 것 21개, 처음 변환하는 것 15개(보류 2개 포함).
- B02: A 화면 SQL 114개 중 asseterpdb에서 안 도는 것 4개(전부 collation, 비고에 `B02:` 표시).
- B03: 변환 34개, 보류 2개(A35·A36). sys 밖 도메인 클래스에 기대는 화면은 없다. 파일 첨부(`sys10_file`)를 쓰는 화면 7개는 B10 뒤에 한다(비고 `파일(B10)`).
