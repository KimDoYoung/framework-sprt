## 2. AS-IS 서버 동작 (그대로 옮길 것)

**올리기** `FileUpload` 서블릿 (`server/utils/file/FileUpload.java`)
- `service()` L95-129: `mode`로 나눔. 기본 → `uploadFile()`, `emp01` → `uploadEmpFile()`. `sys95`·`filebox`·`flt07`·`ics01`·`scm13`·`scm30`·`pay08`은 범위 밖.
- 저장 위치 `uploadFolder()` L927-936: `{filePath}/{로그인 회사코드}/{yyyyMM}`, 파일 이름은 **`{fileId}`(확장자 없음)**. `sys10_server_path`에 그 폴더 절대 경로를 넣는다.
- `makeFileModel()` L848-882: fileId = `getSeq`, 파일명·확장자(마지막 `.` 뒤)·크기(KB, 정수 나눗셈)·등록일 now·`fileYn`(파라미터). `sys10_file.insert`(person_id·seq·title_yn은 안 넣음, `print_yn='true'`, `ext_yn='false'` 고정).
- `uploadEmpFile()` L748-812: 사원(`emp01_person.selectById`)이 있고 이미지면 800×600으로 줄여 저장, 아니면 그대로.
- 응답은 문자열 "파일을 성공적으로 등록하였습니다." / "등록할 파일이 전달되지 않았습니다." / "파일 업로드 중 오류가 발생하였습니다."
- 원본 결함(옮기지 않고 제안): `uploadFile()` L144-176은 폼 항목마다 `makeFileModel`을 불러, 파일 아닌 항목이 섞이면 같은 파일이 여러 행으로 들어갈 수 있다.

**받기** `FileDownload` 서블릿
- `fileType=file` `downloadFile()` L162-184: `sys10_file.selectById` → `{serverPath}/{fileId}`. 없으면 "등록된 파일정보를 찾을 수 없습니다." / "서버에 등록된 파일정보가 없습니다: {파일명}". `attachment; filename="{URL 인코딩}"`, `application/octet-stream`.
- `fileType=image` `downloadGenericImage()` L195-215: `fileId` 또는 `parentId`(`selectOneByParentId` = 최근 1건). 없으면 `{filePath}nonamed.jpg`. Content-Type `image/{ext}`.
- 권한 검사가 없다(fileId만 알면 받음).

**삭제**
- 판정 `sys.Sys11_RelateFile.checkFileDelete(fileId, parentId)` L57-76: `sys11_relate_file`에 (fileId, parentId)가 있으면 그 연결만 지우고 status 1 / 다른 진행 중 결재문서(`apr01`·`apr99` 상태≠99)가 쓰면 status 2("해당 파일은 다른 상신문서에서 사용 중이므로 삭제할 수 없습니다", 화면 메시지) / 아니면 status 3.
- status 3이면 `FileDelete?fileId=` 서블릿 `deleteFile()` L154-192: 물리 파일 삭제(실패해도 로그만) → `sys10_file.delete` → "파일을 성공적으로 삭제하였습니다."

**SQL** (`sys10_file.xml`, `sys11_relate_file.xml`)
- `insert` L470, `selectById` L42(`sys11_relate_file` UNION), `selectByParentId` L82(UNION, ORDER BY에 `COLLATE "ko_KR.utf8"` — B02 실패, 05 §6 규칙대로 `"ko-KR-x-icu"`), `selectOneByParentId` L294, `delete` L589, `checkFileDelete01/02`·`deleteRelateFile`.

- `sys10_file` 1,407행(삭제일 있는 행 0), `sys11_relate_file` 1,193행.
- `sys10_server_path`는 운영 서버 절대 경로다: `c:\KIDMS\docs/{회사}/{yyyyMM}` 1,077+행, `/data1/IDMS_dev/docs/…` 124행, `/data1/asseterp/acd|dev/IDMS/docs/…` 등. 이 환경에는 그 파일이 없다(`/data1`에는 `oms`만).

## 6. 사용자 결정 (2026-10-13, 모두 추천안)
- 경로: 원본 규칙 그대로. 형식 검사: `allowed-types`(Tika) 적용. 받기 권한: 로그인만. 범위: API·부품 + A15-4 Sys54 연결(A15-4도 `완료`).

결정 전에 물은 것:
1. 새 파일 저장 경로: 원본 규칙 `{upload.dir}/{회사코드}/{yyyyMM}/{fileId}`, `sys10_server_path`에 절대 폴더 경로 — 추천.
2. 형식 검사: 원본에는 없다. `allowed-types`(Tika 내용 검사)를 적용할지 — 사용자가 설정을 둔 만큼 적용 추천(거부 메시지는 새로 정함).
3. 받기 권한: 원본은 검사 없음. TOBE는 로그인(JWT)만 요구 — `sys10_file`에 회사 컬럼이 없어 회사 범위 검사는 경로로만 가능.
4. 끝내는 범위: B10에서 API·부품까지만 할지, 첫 사용처로 A15-4 Sys54(E6·E7·E9)까지 붙여 A15-4를 `완료`로 할지.
