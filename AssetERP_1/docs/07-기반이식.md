# 07. 기반이식 (OMS → AssetERP_1)

B04~B08의 작업방법이다. 화면 변환(A)을 시작하기 전에 **화면과 관계없는 바탕**을 OMS에서 가져와 돌아가게 만든다.
05 §1의 B04~B08 행은 이 문서를 가리킨다. 기록은 `work/B04-작업기록.md` … `B08-작업기록.md`에 남긴다.

## 목표 상태 (B08이 끝났을 때)

- `AssetERP_1/`에 `backend/`, `frontend/`, `bm.sh`, `fm.sh`, `deploy.sh`가 있고 컴파일·빌드된다.
- 로그인 → MainFrame(TopBar · LeftMenuBar · StatusBar) → **MyPage**가 뜬다.
- 왼쪽 메뉴는 asseterpdb `sys06_menu` + 권한으로 AS-IS와 같게 나오고, 메뉴를 누르면 **"변환 전" 탭**이 열린다.
- **화면 페이지는 하나도 없다.** A01부터 화면 등록표에 하나씩 추가한다.
- Tomcat에 WAR로 배포해 같은 흐름이 된다.

## 왜 OMS에서 가져오는가 (03 원칙 7의 예외)

- 로그인·JWT·테넌트·STOMP·프레임·배포는 화면 변환이 아니라 TOBE에서 새로 만든 부분이다. OMS에서 이미 asseterpdb로 검증했다.
- 이번 작업의 목적은 **화면 변환 비용**을 재는 것이다. 바탕을 다시 만들면 그 비용이 섞인다.
- 그래서 **기반은 가져오고, 화면과 화면용 부품은 가져오지 않는다.** 경계는 아래 "가져올 것 / 가져오지 않을 것" 표로 정한다.

- `bm.sh`, `fm.sh`: 그대로 복사한다(경로가 스크립트 위치 기준이라 수정 없음).
