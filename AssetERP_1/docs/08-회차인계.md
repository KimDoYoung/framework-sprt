# 08. 회차인계 (AssetERP_1 → 다음 회차)

AssetERP 변환을 다음 회차(`AssetERP_2` …)에서 다시 할 때, 이 회차의 문서와 결과를 **무엇을 그대로 쓰고 무엇을 새로 만드는지** 적는다.
이 회차를 진행하면서 계속 고친다. ID를 하나 끝낼 때마다 다음 회차에 도움이 될 것을 아래 "교훈"에 한 줄 적는다(05 §0).

## 이 회차의 위치

- 브랜치 `AssetERP_1`, 폴더 `AssetERP_1/`. main에 합치기 전에는 이 브랜치에만 있다.
- 다음 회차 브랜치를 `AssetERP_1`에서 따면 이 폴더가 그대로 따라온다. 다른 곳에서 따면 `git show AssetERP_1:AssetERP_1/docs/<파일>`로 읽는다.
- 색인(`docs/as-is/`)은 git에 없다(사내 자료). 필요하면 05 B01 명령으로 다시 만든다.

## 문서별 재사용

| 문서 | 성격 | 다음 회차에서 |
|:---|:---|:---|
| `CLAUDE.md` | 틀은 공통, 경로·이름은 회차 고유 | 복사 후 `AssetERP_1` → `AssetERP_2`, 원본·대상 범위 문장을 고친다 |
| `01-변환목록` | **회차 고유** | 새로 만든다. 표의 열·상태값·B/A ID 체계는 그대로 쓴다 |
| `03-절대원칙` | 공통 | 복사. 변경 이력을 새로 시작하고 이 회차의 이력은 "이전 회차" 줄로 요약한다 |
| `04-작업순서` | 틀은 공통, 묶음 표는 회차 고유 | 전체 순서(B → A 레퍼런스 → A 묶음 → 정리)와 "ID 하나의 진행"은 그대로, 묶음 표만 새 범위로 |
| `05-작업방법` | 공통(이 회차에서 보강된 상태) | 복사. §5 공통 부품 등록표와 §6 AS-IS → TOBE 대응표는 이 회차의 결과를 **출발점**으로 쓴다 |
| `06-결과확인` | 공통 | 복사 |
| `07-기반이식` | 틀은 공통, 가져올 곳은 회차 고유 | 가져올 곳을 OMS 대신 **이 회차의 `AssetERP_1/`**로 바꾸는 것을 먼저 검토한다(이름 바꾸기 표: 폴더·WAR·컨텍스트 `/AssetERP_2`·Redis 접두사) |
| `work/{id}-*` | 회차 고유 | 복사하지 않는다. 같은 화면을 다시 할 때 비교 자료로 읽는다(특히 비용 절) |

## 다음 회차 시작 순서

1. 브랜치와 폴더 `AssetERP_2/`를 만든다.
2. 위 표대로 문서를 복사하고 이름을 바꾼다.
3. 대상 범위를 정한다(예: 다음 도메인, 또는 같은 sys 화면을 다른 방법으로). 범위 SQL은 `docs/작업1.txt`처럼 `sys06_menu`에서 뽑는다.
4. B01 색인을 `AssetERP_2/docs/as-is/`에 만든다(`-t`로 다른 회차·OMS 색인과 분리).
5. 이 회차의 B09 정리(비용·시사점)를 읽고 바꿀 점을 03·05에 먼저 반영한다.

## 교훈 (ID를 끝낼 때마다 추가)

| ID | 교훈 | 다음 회차에서 할 일 |
|:---|:---|:---|
| B01 | `yunhee index-src`는 출력 폴더를 지우고 다시 만든다. 루트 `docs/as-is/`(OMS)와 섞이지 않게 회차 폴더 아래에 `-t`로 만들었다 | 처음부터 회차 폴더에 만든다 |
| B01 | 메뉴 키(`sys06_class_nm`)와 원본 클래스 이름이 다를 수 있다(오타 `Sys03_Tab_ComapnyMenu`, 개명 `Sys96_Tab_OpenMenuLogAdmin`). 원본 `MenuOpener.java`가 실제 연결을 알려 준다 | 범위를 뽑은 뒤 MenuOpener와 대조한다 |
| B01 | 원본(`~/oms-data/src/Asset-ERP`)이 DB 메뉴보다 오래됐다. 최근 등록 메뉴(2025-10 이후)는 소스가 없거나 이름이 다르다 | 시작 전에 원본을 최신으로 받을 수 있는지 확인한다 |
| B02 | 원본 SQL의 `COLLATE "ko_KR.utf8"`이 asseterpdb에 없다(`ko-KR-x-icu`만 있음). sys 화면에서는 이것 말고 스키마 차이가 없었다 | collation 바꾸기를 05 §6 대응표의 고정 규칙으로 둔다 |
| B03 | 색인 UI 절의 `⚠DB없음`은 그리드 컬럼 이름과 DB 컬럼이 다르다는 표시이지 테이블이 없다는 뜻이 아니다 | 범위 판정은 `## 테이블` 절만 본다 |
| B03 | 첨부(`sys10_file`)를 쓰는 화면이 여럿이라 공통 작업(B10)으로 뺐다 | 범위 확정 때 공통 테이블(파일·코드·조직 등)을 먼저 세어 B 작업으로 만든다 |
| B04 | Redis 채널 이름(`asseterp:ws:events`)에는 `oms`가 없어서 "oms" grep으로는 못 찾는다. 공유 자원(Redis 키·채널, Tomcat 경로, JWT secret)은 이름이 아니라 **설정 항목 목록**으로 확인해야 한다 | 07 이름 바꾸기 표를 `application.properties`의 Redis·JWT 항목 전체와 대조한다 |
| B01~B03 | 문서 작성·B01~B03을 한 세션에서 했다(03 원칙 8과 다름). 화면이 아닌 분석 작업은 문맥이 겹쳐 한 세션이 효율적이었다 | 원칙 8을 "A는 ID 1개 = 세션 1개, B01~B03은 묶어도 됨"으로 바꿀지 B09에서 정한다 |
