# 01e. 변환목록 (누락 대장의 대기 32개: 관리자·KFS·I/F·ICAM)

`01d-변환목록.md` 다음 상태판이다. 변환 뒤 점검에서 TOBE에 없는 것으로 나온 화면 104개 중 사용자가 변환하기로 한 32개다(결정 2026-11-03, 근거 `13-누락대장.md`). 01a~01z와 01aa의 글자가 모두 쓰여 두 글자 접두사 `EE`(EE01~EE32, EE21 후처리 EE33, EE22 증빙자료 창 EE34, EE23 메일 발송창 EE35 추가)를 쓴다. 상태는 ID가 속한 파일에만 적는다.
ID 하나의 기록은 `work/EE/EE01-작업방법.md`, `…-작업기록.md`, `…-결과확인.md`.

- 상태: `대기` → `분석` → `백엔드` → `프론트` → `확인` → `완료`, 또는 `보류`(사유를 비고에).
- **다음 작업은 아래 표에서 상태가 `대기`인 첫 줄.** 하나씩 변환한다(사용자 지시 2026-11-03). 순서는 같은 도메인·같은 구조끼리 묶었다(문서 4 → 문서권한 5 → 관리회계·사원·펀드·회의실 → 시스템 개발 5 → KFS 계약사 4 → ICAM 9).
- 메뉴 번호는 `sys06_menu.sys06_menu_no`. 시험 계정은 `docs/테스트/테스트-회사-계정.md`를 따른다(비고의 계정은 그 메뉴가 보이는 계정).
- 모두 `_Tab_` 화면이므로 page-style(03 원칙 22)을 따른다. 하위 창(`_Lookup_`·`_Edit_`·`_TabPage_`)은 각 ID 분석 때 `yunhee analysis screen <화면> --list`로 나눠 같은 ID에서 함께 한다.
- **ICAM 4개(EE25 `Icam01_Tab_DataInfo`, EE26 `Icam02_Tab_Data`, EE27 `Icam02_Tab_DataAdmin`, EE28 `Icam02_Tab_CashFlow`)** 메뉴는 로그인할 수 있는 회사에 연결돼 있지 않다(사용 중지 회사 TEST·PTR 등에만 연결). 시작 전에 사용자가 `sys03_company_menu` 연결 여부를 정한다 — 03 원칙 1의 예외로 기록한다.
