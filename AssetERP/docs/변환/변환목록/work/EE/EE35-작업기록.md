## AS-IS와 다른 점 (사용자 확인용)
1. **[예] 경로(새 메일 시스템)**: 확인창은 그대로 두되 [예]는 "새 메일 시스템(외부 메일 작성창)은 아직 지원하지 않습니다" 안내 뒤 닫는다(사용자 결정). AS-IS는 `eml.Eml01_SendHistory.insert` → `SendMailSMTP.assetMailSend`(SSO 토큰으로 외부 작성창 URL을 받아 새 창). 새 ID 후보.
2. **발송 방식 하나**: AS-IS는 `testYn`이면 `mailSenderTest`(multipart mixed>related, 로고 `Content-ID`), 아니면 `mailSender`(옛 구조 — 본문이 google·naver에서 두 번 보이고 office365 첨부에 logo.png·AT00001.htm이 섞이는 문제가 있어 새로 만들었다고 AS-IS 주석에 적혀 있다). TOBE는 두 경로 모두 새 구조(`mailSenderTest`)로 보낸다. 옛 `mailSender`(L161-495)는 읽지 않았다.
3. **요청 사이에 값이 남는 AS-IS 결함 제거**: AS-IS 서버는 `publicCheck`·`privacyInfo`를 서버 객체 필드에 담아 두어, 한 번 공용메일/개인정보 서명으로 보내면 다음 요청이 값을 안 줘도 남았다(`if (request.getStringParam("publicCheck") != null) publicCheck = …`). TOBE는 요청마다 새로 정한다.
4. **첨부 파일 검사**: AS-IS는 화면이 보낸 파일 ID를 그대로 서버가 읽어 붙였다(다른 문서·다른 회사 파일도 ID만 알면 가능). TOBE는 로그인 회사 문서의 `selectApprRelateDoc` 목록에 든 ID만 허용하고, 아니면 "첨부할 수 없는 파일입니다". 이력 저장도 같다.
5. **서명 본문의 부서·직위**: AS-IS는 `emp00_trans_info.getPersonInfo`(큰 CTE) 결과의 마지막 행을 썼다. TOBE는 `emp03_trans`의 최신 발령(`ORDER BY 발령일 DESC, 발령ID DESC`) 한 행에서 `f_org_parent_full_nm`·`f_cdnm('EmpPosCode')`만 읽는다(같은 함수 호출). 겸직·퇴직 발령이 섞인 사원은 AS-IS와 다른 행일 수 있다.
6. **서명 문자열 이스케이프**: 사원명·부서·주소 등을 HTML 이스케이프해서 넣는다(AS-IS는 그대로 이어 붙임). 보통 값은 결과가 같다.
7. **SMTP 시간 제한**: 연결·응답·쓰기 15초(AS-IS 없음, `CmpMailBookService.check`와 같은 값).
8. **`MailRetrieve`의 callback**: AS-IS `Emp10_Lookup_MailRetrieve`는 callback을 받아 두기만 하고 어디서도 부르지 않아 [본인메일]에서 주소를 바꿔도 발송창의 본인 메일 칸이 다시 읽히지 않는다. 그대로 옮겼다(제안 1).
9. **본인 메일 비밀번호가 화면으로 내려옴**: `GET /emp/persons/me/mail`이 복호화한 메일 비밀번호를 준다(AS-IS `selectByPersonId`의 `decPassword`가 그대로 화면으로 갔다). 로그인 사원 본인 것만 준다.
10. **일괄 발송 보낸이 칸**: AS-IS는 이력의 `senderEmail`에 메일서버 이름(`LoginUser.getMailInfo()` — 예 `office365`)을 넣는다. 그대로. 일괄은 `privacyInfo = "true"`라 사원에게 내선·휴대폰이 없어도 검사 없이 "T. null / M. null"이 서명에 들어간다 — TOBE는 빈 칸으로 나간다(`esc(null) = ""`).
11. **일괄 발송 사이**: 행마다 0.5초 쉰다(AS-IS `Timer.schedule(500)`). 실패(-1)하면 AS-IS는 메시지 팝업 뒤 [닫기]를 켜고 진행창은 마지막 줄 그대로 둔다 — 같다.
12. **버튼 0/2**: AS-IS 확인창은 GXT `HtmlMessageBox`의 기본 [예][아니오]라 클래스에 버튼이 없다. TOBE는 [예][아니오] 두 개를 그렸다.

## 설정 (사용자 확인 필요)
- 서명의 전화·팩스·주소와 로고는 AS-IS가 서버 설정(`IdmsConfig`, `{회사위치}.tel/.fax/.address/.mailSignImage`)에서 읽었다. TOBE는 `asseterp.mail.sign.{회사위치}.tel|fax|address|image`(`application.properties`에 예시 주석)로 옮겼고 **값이 아직 없다** — 비어 있으면 서명의 그 칸이 비어 나가고 로고(`cid:image`)는 빠진다. 로고 파일은 `{asseterp.upload.dir}/{회사위치}/{image}`.
- 메일서버 설정(`config/mail/{sys01_mail_info}`)과 회사 `sys01_mail_log_yn`(보낸 계정에 `[AssetERP-발송메일]` 사본)은 DB·리소스가 이미 있다(kfstest = office365, 사본 true).

## 제안 (승인 전 반영 안 함)
1. `Emp10_Lookup_MailRetrieve`가 [검증→저장]·[초기화] 뒤에 callback을 불러 발송창의 본인 메일 칸을 다시 읽게(AS-IS 의도로 보임).
2. [예] 경로(외부 메일 시스템)를 별도 ID로.
3. 일괄 발송의 이력 보낸이를 실제 보낸 메일 주소로(지금은 `office365` 같은 서버 이름이 들어간다).
4. 일괄 진행창 제목이 "파일 재생성"(다른 화면에서 복사한 문구) — 그대로 옮겼다.
