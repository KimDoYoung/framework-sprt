## 공통 절차와 다른 점
- 열 때 조회하지 않는다(원본 `// this.retrieve()`가 주석 처리). `Scm30_Lookup_SelectMulti`·`Biz13_Lookup_WithCorp` 조회창도 열 때 조회하지 않는다(원본 `open()`에 조회 호출이 없다).
- 개발자 [삭제]에 선택이 없으면 원본은 오류가 난다 → "삭제할 개발자를 선택해주세요" 안내만 더했다.
- 요청사 트리거(`corpName`)·`Biz13_Lookup_WithCorp`: 폼에 칸이 붙어 있지 않아 열 수 없지만 클래스 대조(06 항목 10)를 위해 조회창을 만들고 폼에는 숨은 상태로 둔다 → 작업기록 "제안"
- 진행상태 창의 저장은 원본이 삭제와 저장을 따로 부른다. 여기는 한 호출(`PUT dev-steps`)에 삭제 목록(`deleteIds`)과 줄 목록을 함께 보내 한 트랜잭션으로 처리한다(원본은 두 호출이라 중간 실패 시 어긋날 수 있음).
- `Scm01_Edit_DevMng.updateRow`는 모델 전체를 보내지만 서버는 화면이 바꾸는 열만 UPDATE한다(EE15와 같은 방식).
