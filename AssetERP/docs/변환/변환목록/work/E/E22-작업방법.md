## 공통 절차와 다른 점
- **색인이 잘못 가리킨다**: `pay04_formula`는 같은 namespace 매퍼가 둘(`pay04_formula.xml`, `pay04_formula_20230620.xml`)이고 색인·`yunhee analysis sql`은 옛 `_20230620`을 보여 준다(`selectByDate`가 항목 조인 없이 나옴). ConfigMyBatis에 등록된 것은 `pay04_formula.xml`이라 그쪽 원문을 읽어 옮겼다. **yunhee 개선 제안**: 같은 namespace 중복 시 ConfigMyBatis에 등록된 파일을 우선.
- 원본은 서버 검사가 없어 NOT NULL 열(항목구분·코드·항목명 / 율 구분·적용시작일·율 / 적용일·항목코드)이 비면 DB 오류가 나므로 서버가 안내 문구로 먼저 막는다(05 §6, E21과 같음). 저장·삭제·생성은 관리자 회사만(`isSysAdmin`) — 원본 화면도 관리자에게만 버튼을 연다. 다른 회사 데이터 조회(`companyId`)도 관리자만.
- 원본 insert(적용일 생성)·basicDataCreate의 복사는 **비고를 옮기지 않는다**(원본 SQL이 `pay04_note`를 안 넣음) — 그대로.
- 오른쪽 산출식 그리드(`eastFormGrid`)의 산출식·비고는 원본에서도 편집기가 있지만 저장하는 곳이 없다 — 편집 열만 그대로 두고 저장은 연결하지 않았다.
- 한 번 연 탭을 숨기기만 하는 것(상태 유지)과 탭 선택마다 조회하는 것은 원본의 동작을 합친 것이다.

## SQL 이식
`yunhee analysis sql … -o sql`로 원문을 확인하고 `SELECT *`는 DTO 열 별칭으로 풀었다. 같은 namespace 매퍼가 하나뿐이라 색인이 맞다(1단계의 `pay04_formula`와 다름). 저장(UpdateDataModel)은 명시 SQL: pay23 INSERT·UPDATE(초과·이하·율1·율2·누진세액·비고), pay24 UPDATE(초과·이하·공제금액·공제율·비고)·INSERT(dataCode는 서버), pay25 INSERT·UPDATE(구분·금액·비고). `sql-check` 전 statement ✅.

## 공통 절차와 다른 점
- **엑셀업로드 순서는 원본 그대로**: [엑셀업로드]를 누르면 해당 적용일의 천만원 이하 표를 **먼저 지우고** 파일 선택창이 열린다 — 파일을 고르지 않고 닫으면 표가 지워진 채 남고 화면 목록도 갱신되지 않는다(원본 동작). 원본은 적용일을 안 골랐으면 NPE라 TOBE는 "기준 적용일을 선택해주세요"로 막는다. 원본 서버의 `excelDelete`는 방금 받은 새 ID로 지우므로 항상 0건이라 부르지 않는다(E-Sch10 `sch10_ipo.excelDelete`와 같은 판단).
- 원본은 서버 검사가 없어 NOT NULL 열(초과·이하 / 구분)이 비면 DB 오류가 나므로 서버가 안내 문구로 먼저 막는다(05 §6). 생성·저장·삭제·엑셀업로드는 관리자 회사만(`isSysAdmin`), 조회는 로그인한 누구나(원본 화면도 관리자에게만 버튼을 연다).
- 원본 적용일 생성은 중복 적용일을 검사하지 않는다 — 같은 적용일을 두 번 만들면 행이 두 배가 된다(그대로, 1단계 제안 ③과 같음).
- 새 행은 목록 맨 아래에 붙는다 — 화면 확인 스크립트는 그리드를 맨 아래로 밀어야 시험 행을 누를 수 있다(가상화).
- 코드 구조: 세 목록 탭의 조회·첫 행 선택·삭제는 `usePayDateList`(pages/pay, 화면 전용 훅)로 묶고 JSX·이벤트는 클래스 파일마다 둔다(UI 대조표가 클래스 파일 단위로 센다).

# 3단계 (E22-3) — 탭7 과세표준 구간별 기본세율 · 탭8 근로소득 세액공제 · 탭9 기타설정

범위: 남은 탭 7~9, 클래스 9: 버튼 3+2+3 + 3+2+6 + 3+2+3 = 27, 이벤트 6+3+5 + 6+3+9 + 6+3+5 = 46, 그리드 1+0+1 + 1+0+2 + 1+0+1 = 7. 서버 `Pay26_TaxCalcTable`·`Pay27_TaxDeductTable`·`Pay28_TaxDeductLimit`·`Pay29_OtherSetup`. 2단계와 같은 구조(적용일 목록 탭 + 상세 탭 + 생성 팝업)라 같은 방식으로 했다.

## 화면 구성
- 적용일 목록 탭 3개: 2단계와 같음(`[조회]` + 관리자 회사만 `[등록][삭제]`, 적용시작일 그리드 15% | 상세 85%). 탭9는 아래에 안내문("※ 국민연금 상ㆍ하한액 적용예시 …").
- 탭7 상세: 툴바 `[등록][저장][삭제]`(관리자) + 셀 편집 그리드(머리글 묶음 "과세표준(원)" 초과 150·이하 150 + 기본세액 150·초과금액 적용세율(%) 200·비고 500, 체크박스 없음).
- 탭8 상세: 위 "세액공제" 툴바(같은 세 버튼) + 그리드(머리글 "산출세액" 초과·이하 130 + 기본공제 130·적용율(%) 130·비고 500) / 아래 50% "세액공제 한도" 툴바(`limit*` 세 버튼) + 그리드(머리글 "총급여액" 초과·이하 + 최소한도·최대한도·적용율(%)·비고).
- 탭9 상세: 그리드 머리글 묶음 3개(최대분할회차: 건강보험·고용보험 / 건강보험 상ㆍ하한액: 상한액·하한액 / 국민연금 상ㆍ하한액: 상한액·하한액) + 표준세액공제·비고, 폭 150·비고 500.
