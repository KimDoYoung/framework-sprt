## 공통 절차와 다른 점
- **본문 재료를 서버가 읽는다**: 원본은 호출 화면의 그리드 모델(`Flt10_TrModel`·`Flt11_BookModel`·`Flt13_BookInitModel`·`Flt06_AccountCloseModel`)을 `linkParam`에 담아 넘겼다. TOBE는 `ids`만 받고 서버가 같은 질의로 다시 읽는다(화면이 값을 조작해 남의 행·거짓 값을 넘기지 못하게). 그 결과 A09의 보유내역(`flt11_book.selectByDate`)과 가족계좌 여부는 원본처럼 호출 때 읽는다.
- **TempData(`closeDate`·`periodString`)**: A09의 제목·시행일자·본문 제목은 마지막으로 [조회]한 때의 `TempData` 값이다. TOBE는 `getDate`에서 `closeDateRef`·`periodStringRef`를 같이 갱신해 같은 동작이 되게 했다.
- A09는 고른 매매가 없어도 열린다(원본의 "선택된 매매내역이 없습니다. 매매내역 없이 진행하시겠습니까?" → [예]) — `ids`가 비면 거래내역 표는 `-` 한 줄, "거래내역이 없음 (O)".
- B05의 setupDate·regReason은 고른 행 중 **첫 행**(`getSelectedItem()`)의 값이다. TOBE `selected()`는 그리드 행 순서라 GXT의 선택 순서와 다를 수 있다(둘 이상 고를 때만).
- 스타일: 세 화면 모두 이미 변환된 화면이라 레이아웃은 건드리지 않았다(`page-style --compare` GG·GG 일치, `Flt06_TabPage_AccountClose`는 `_TabPage_`라 대상 아님).
