# V40 Apr01_Edit_ApprDoc 링크: 복리후생비 지출결의 A46~A48·A50·A51 — 작업방법

호출 화면 `Emp17_Tab_BenefitManager`(1222, 이미 TOBE에 있음). 코드는 신청구분 설정(`emp55_benefit_info.emp55_expense_link_cd`)이 정한다: 010BN→A46, 020AN→A47, 030AN→A48, 040AN→A50, 900BY→A51.

## 범위 결정
- 사용자 선택(2026-11-01): 복리·지출결의 묶음. 분석에서 **A21~A23·A37·A49(복리후생비 신청)는 호출 화면 `Emp17_Tab_Benefit`(Y06)가 TOBE에 없고**, 본문 치환 값(`TempData.getBenefitMapping`)을 그 화면의 `Emp17_Lookup_Benefit`(L401)이 만들어 → V41(Y06 변환 때)로 넘김.

## API
- `GET apr/apprs/link-seed?classTreeId&linkCode=A46..&ids&yyyy&mm&benefitName&benefitCode` (기존 엔드포인트에 `benefitName`·`benefitCode` 인자 추가). AS-IS는 그리드 행 모델(`gridList`)·합계·계정과목 이름을 화면에서 만들어 보냈지만, TOBE는 행 ID(그리드 순서)·기준년월·신청구분 이름·코드만 받고 서버가 행을 다시 읽고 합계·계정과목(`emp55_benefit_info`)·발생부서(로그인 사원 소속)를 계산한다.
- 응답: 제목 `yyyy년 mm월 직원 이름 지급결의서`(고칠 수 있음), 본문 `BenefitManagerHtmlData.getHtmlContent`, 시행일자 오늘, `relateApprs` = 행의 복리후생비 신청 문서(`Apr03_Page_Relate.insertEmp17RelateApprList`).
