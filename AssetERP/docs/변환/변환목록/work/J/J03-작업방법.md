## 공통 절차와 다른 점
- **(해소됨, 2026-10-21 저녁)** 사용자가 집 DB에도 협의승인 열 4개를 추가해 매퍼(`selectTrList`·violate 조각)를 원본 열로 되돌렸다. 사무실과 집 DB는 별도 사본이라 집에는 열이 없었던 것이다. 아래는 되돌리기 전의 기록이다.
- **협의승인 열(`flt10_add_confirmer_id`·`flt10_add_confirm_reason`)이 asseterpdb에 없었다.** J02 작업기록에는 사용자가 DB에 추가했다고 적혀 있으나 이 세션 시점(2026-10-21)에는 `information_schema`에 없다(`like '%add_confirm%'` 0행, J02의 `approvals` API도 500). 원본 SQL이 이 DB에서 안 돌아 I08과 같이 두 열을 NULL로 본다(03 원칙 4의 예외). 사전승인 칸의 협의승인 표시는 이 DB에서 나올 수 없다. 열이 있는 DB에서는 매퍼 `addConfirmReason` 조각 근처의 `CAST(NULL …)`을 되돌린다.
- 엑셀은 RD 양식이 아니라 그리드 열 순서의 단순 xlsx다. RD 양식과 같은지, 금감원양식이 열을 어떻게 다르게 잡는지는 확인하지 못했다(preTrYn=false로 사전신고 열만 뺀다).
- 일반 [엑셀다운로드]는 AS-IS가 체크박스와 무관하게 `preTrYn=true`를 보낸다(`createRdExcel`). TOBE도 같다(`report=false` → 사전신고 열 포함). 그리드만 체크박스를 따른다.
- AS-IS의 조회에서 `unApprYn`이 "false"이므로 상태가 00(미신청)이고 매매일이 없는 사전신고 행은 나오지 않는다(I08과 다름).
