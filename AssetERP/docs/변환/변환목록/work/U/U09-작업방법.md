## 공통 절차와 다른 점
- **원본 결함 보정(사용자 확인 필요)**: AS-IS `createJournal`은 지출결의서 행이 아직 없는 예정내역을 새 `getSeq` ID로 INSERT한 뒤에도 DB 함수에는 **예정내역의 임시 ID**(`4000000 + row_number()`)를 넘겨, 새 행이 전표에 묶이지 않는다(함수가 `pay50_expense_id`로 행을 찾는다). TOBE는 새로 넣은 행의 ID로 부른다. 다르게 두려면 `PayExpenseService.createJournals`의 `ids`를 `row.expenseId()`로 되돌린다.
- **삭제 입력**: AS-IS는 화면 행의 `journalFixYn`·`occDate`·`companyId`를 서버에 보내고 서버가 믿었다. TOBE는 전표 ID만 받고 `selectJournalInfo`로 DB 값을 다시 읽는다. 한 건이라도 거절되면 전체를 되돌린다(AS-IS는 앞 건이 처리된 채 멈췄다).
- 공통 부품 변경 없음. `tools/page-style-check.py` GG 점검 대상에 이 화면 추가.
