## 공통 절차와 다른 점
- **다른 도메인 클래스를 같은 ID에서 함께 만들었다**: 결제등록·일괄·History가 이 화면의 본업이라 U03~U10의 "안내만" 선례를 따르지 않았다. 남은 다음 단계는 History [전표변경]의 `Act02_Lookup_ModiJournal` 하나.
- **`payName.getCode()`**: AS-IS는 `payName.setText("지급")`만 하고 코드를 안 정해 `getCode()`가 null → payCode "%" 로 읽었다(사업비지출 거래만 보는 조건이라 결과는 같다).
- **서버가 믿는 값**: 결제 취소는 결제 ID만 받아 DB의 사용자·거래 코드로 분개를 지운다(AS-IS는 화면 행 값을 보냈다). 일괄 결제의 금액(accruedAmt)·거래 코드는 AS-IS처럼 화면 행에서 받는다.
- **공통 부품**: `Sys15_Lookup_Corp`에 `empYn` 추가(11a·05a 갱신).
