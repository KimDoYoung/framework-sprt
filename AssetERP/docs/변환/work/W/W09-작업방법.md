## 공통 절차와 다른 점
- **조회(`GET ast/evals`)를 쓰기 가능 트랜잭션으로 둔다**: 아직 평가하지 않은 줄의 거래ID를 SQL의 `COALESCE(ast06_tr_id, f_create_seq())`가 만드는데, `f_create_seq()`는 `nextval`을 쓰는 plpgsql이라 읽기 전용 트랜잭션(서비스 기본)에서는 예외를 삼키고 NULL을 돌려준다. 그대로 두면 평가하지 않은 줄의 거래ID가 모두 NULL이라 그리드 행 키·평가처리가 깨진다 → `search`만 `@Transactional(readOnly = false)`.
- **서버가 하는 일**: AS-IS는 클라이언트가 `checkClose`(Act04_GenLedger)를 먼저 부르고 `updateEval`을 부른다. TOBE는 `process`·`cancel` 안에서 첫 선택 행 일자로 `ActJournalService.checkClose`를 하고 한 트랜잭션으로 끝낸다(실패하면 전부 되돌아간다). `process`는 처리한 줄을 `selectEvalList`로 다시 읽어 돌려준다(AS-IS는 `ast06_tr.selectById`로 읽어 그리드 행을 바꾼다).
- **시세입력 기준일**: AS-IS `Sys12_Calendar.selectBizDate2(0, 기준일, "-0", true)`가 쓰는 `f_get_biz_date2`는 기존 `GET sys/calendars/biz-date`(`f_get_biz_date`)와 다른 함수라 `GET ast/evals/price-date`를 따로 만들었다. 평가주기(`sys01_ast_eval_cycle_cd`)도 로그인 사용자 정보에 없어 `GET ast/evals/cycle`을 만들었다.
- 평가년월 칸은 antd `Input`("YYYY.MM", 폭 100 — 12 원칙 7)이고 형식이 틀리면 조회·시세입력·출력에서 "평가년월을 확인하세요. (YYYY.MM)" 안내(AS-IS는 파싱 예외로 아무 일도 안 한다).
- 출력/다운로드는 조회된 목록이 없으면(AS-IS는 `getStore().get(0)` NPE) "조회된 내역이 없습니다." 안내.
- 원본 이상한점 #125(출력 때 `Ast13_Tab_DepnBook`을 넘김)·#126(분개 실패 메시지가 "Y")·#127(익일 반제거래의 금융상세가 남음). #126만 TOBE가 분개 결과 메시지를 쓴다(원본과 다름, 승인 필요).
- 레이아웃은 STP 견본을 뼈대로(결과확인 13).
