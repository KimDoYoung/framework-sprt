## 열리는 조건 (LoginPage.checkExt)
회사 설정 `sys01_company.sys01_secondary_auth_yn='true'` 이고 로그인 사용자가 회사관리자가 아닐 때: `GET sys/secondary-auths/required`. `App`의 `SecondaryAuthGate`가 로그인 뒤 한 번 확인하고, 필요하면 인증 전에는 `MainFrame`을 열지 않는다. 창을 닫으면(X) AS-IS처럼 화면이 안 열린다(→ 로그아웃). 같은 로그인(jti) 안의 새로고침은 다시 묻지 않는다(`sessionStorage`).

## 공통 절차와 다른 점
- **서버가 번호를 만들고 보낸다**: AS-IS는 번호·전화번호를 화면이 만들어 서버에 보냈다(아무 번호나 보낼 수 있음). TOBE는 로그인한 사원의 등록 번호로만 보낸다.
- **보강**: 발급 후 5분 이내의 가장 최근 번호만 맞는 것으로 보고, 확인은 5회까지(Redis).
- **화면에서만 막는다**: AS-IS처럼 인증 전에도 서버 API는 열려 있다(JWT는 이미 발급). 서버가 인증 전 API를 막으려면 로그인 판정(토큰 클레임)을 바꿔야 해 이번엔 하지 않았다 — 제안.
- **문자 발송 연동이 없다**(2026-10-15 지시): [발급]이 "SMS 발송 연동이 아직 없어…"로 거절된다. 이 회사 설정이 켜진 회사도 로컬 DB에는 없다(`sys01_secondary_auth_yn`이 모두 false/null) → 로그인 문이 열릴 일이 없다.
