| SQL ID | 테이블 | 그대로 / 수정(사유) |

## 화면 구성
- 위(300): 제목 줄("회의실 예약현황 (기준일자 : yyyy년 MM월 dd일)" + 새로고침) + `SingleGrid` 9열(예약 시작일 90·종료일 90·시간 120·회의제목 320·예약자 100·회의실명 160·참석자 320·상세보기 60·삭제 60, 체크 단일).
- 아래: 왼쪽 300 달력(antd `Calendar fullscreen=false`, 예약 있는 날은 굵게 + 주황 밑줄) + [예약하기], 오른쪽 라디오 + `SingleGrid` 7열.
- 팝업 880 EditModal: 일시(날짜 2 + 시 콤보 `HourCode` + 분 콤보 `MinuteCode`) + 예약자 / 장소(`MeetingRoomCode`) + 참석자 / 제목 / 메모(85) / 시간막대 300, 푸터 [저장][변경][닫기][첨부파일(n)].

## 공통 절차와 다른 점
- `Mrb01_TimelineChart`는 Google Charts Timeline이다. 새 의존성을 넣지 않고 `Car03_TimelineChart`와 같은 CSS 막대로 그렸다(행 이름 = 회의실명, 막대 글 = 회의제목).
- 날짜 열 폭: UX-08(읽기 전용 90)을 따라 원본 100을 90으로.
- 이 화면은 `Bbs02_Lookup_File`에 `admin` prop(원본 `open()` = 올리기·삭제)을 더했다. 기본 false라 H01·sch의 기존 사용(`openUser`)은 그대로.
- AS-IS `selectByList`에 `empId` 파라미터가 넘어가지만 SQL이 쓰지 않는다 — 그대로(전체 예약현황).
- `LoginUser.getIsManager()`는 다른 화면과 같이 `user.userId < 0`, 작성자 판정은 `empId === user.userId`(`getPersonId()`).
