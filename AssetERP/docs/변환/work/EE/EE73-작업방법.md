## 시간 다시 계산 (recalcFrom L393, 화면에서)
- 대상 행이 첫 행이면 시작 = 야간근무는 야간 시작, 그 밖은 정책 퇴근시간. 첫 행이 아니면 앞 행의 종료시각(`endTimeStr`, 서버에 없는 화면 값)에서 이어 붙인다 — 조회로 읽은 행은 `endTimeStr`이 없어 0분(00:00)으로 시작하는 AS-IS 그대로.
- 연장근무 행이 [시작 < 야간 시작 < 끝]이면 그 행은 야간 시작까지만 남기고(`overtimeMin = 야간시작 − 시작`), 넘은 부분을 같은 사유·보상의 야간근무 행으로 바로 아래에 넣는다.
- 근태 정책이 정확히 1건이 아니면(AS-IS `getModel` size==1 조건) 계산하지 않는다.

## API / SQL
새 API 7개(`AttMyOvertimeReqController`, `/api/v1/att/overtime-reqs/me`; 매퍼 `AttMyOvertimeReqMapper` 13문장): `selectByPersonId`(그리드가 안 쓰는 주간·월간 CTE·소속·직급 열 뺌) · `selectByYearMonth`(날짜 문자열만) · `getInfo`(AS-IS 그대로, `t.pay01_person_id = emp.emp01_company_id` 포함) · `settings`(`att01_work_policy.getModel`+`pay34_work_time_config.getModel`+`att05_pm_work.getWorkDateInfo`, 없으면 22:00~06:00·12시간) · 저장(`notInOvertimeReqIdList`+`checkWeekMaxTime`+`UpdateDataModel` insert/update + 삭제를 한 트랜잭션) · 삭제 · `updateApprId`. 상신 양식은 V24 `HrLinkSeedProvider`의 A74(refId=overtimeReqId)를 그대로 쓴다.
- `UpdateDataModel`의 INSERT/UPDATE는 모델 기반이라 매퍼에 문장이 없다 → 열 8개(`work_date·overtime_min·reason·work_type_cd·work_reward_type_cd` + 새 행에 `id·company_id·person_id`)로 직접 작성.
- 주간 최대 시간은 AS-IS가 화면이 보내던 값(`weekMaxAddHours`)을 서버가 직접 읽는다(결과 같음).
화면: `Att03_Lookup_OvertimeReq.tsx`(`LookupModal`+`CellEditGrid`: 근무일자 100 · 구분 100 · 연장시간(분) 100(편집) · 근무시간 200 · 사유 350(편집) · 보상 150(편집, 콤보) · 상태 100 · 상신(보기) 80). 공통: `useGridCrud.addRows(inits, markDirty, afterId?)` 추가(야간근무 행을 base 바로 아래에), `QuickMoveDateField`는 EE72 것을 그대로(달력 표시 `markedDates`까지 처음 씀).
