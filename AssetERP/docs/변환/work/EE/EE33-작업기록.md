## AS-IS와 다른 점 (사용자 확인용)
1. **펀드 상세가 없을 때**: AS-IS는 `getMaxSize`가 null이라 NPE가 나 엑셀 파일이 만들어지지 않는다(예외를 삼킴). TOBE는 행을 필요할 때 만들어 **요약(발생기간·총보수·펀드발생·청구금액)만 있는 엑셀**을 만든다. ICAM 발생보수를 옮기지 않아(EE21 사용자 결정) 새로 만든 자료는 biz21 상세가 없으므로 엑셀의 펀드 내역·PDF의 펀드 표는 비어 있다.
2. **기존 파일 삭제 범위**: AS-IS는 `sys10_file.selectByParentId`(sys11 연결 포함)로 실제 파일까지 지우고 행은 `deleteByParentId`로 지워 연결 파일의 실제 파일만 지울 수 있다. TOBE는 청구보수 ID가 부모인 파일(행 + 실제 파일)만 지운다.
3. **zip이 비었을 때**: AS-IS는 빈 zip을 내려 주고 E16이 응답 글을 안내로 띄운다. TOBE는 공통 zip 처리(`getZipEntries`)대로 "파일 리스트가 없습니다."(404)를 안내로 띄운다.
4. **금액이 null일 때**: AS-IS는 일부 칸에서 NPE로 그 행의 엑셀이 빠진다. TOBE는 0으로 읽는다.
5. **계산상세 엑셀 합계 숫자 칸**: AS-IS 코드가 합계 숫자 칸 서식(`#,##0`·오른쪽 정렬)을 다른 스타일에 두 번 넣어 합계 숫자 칸은 서식·정렬이 없다 — 그대로 옮겼다(원본-이상한점 후보). 엑셀 머리에는 일임보수 묶음이 없다(화면 그리드에는 있음) — 그대로.
6. **A20 분기 값**: AS-IS는 `feeChargeModel.getNote()`(화면의 분기)를 쓴다. TOBE는 상신 문서가 열려 있는 동안 화면의 분기를 쓴다(창이 모달이라 바뀌지 않음).
7. 파일 저장 시점: AS-IS는 상신 문서 저장 직후 서버가 붙인다. TOBE는 문서 ID가 정해진 뒤 화면이 한 번 부른다(A41 카드 엑셀·EE21 `updateApprId`와 같은 방식).

## 제안 (승인 전 반영 안 함)
- zip이 비었을 때 AS-IS처럼 빈 zip + 안내를 줄지(지금은 오류 안내).
- ICAM 발생보수 연결이 풀리면(EE21 미완) 이 엑셀·PDF가 실제 펀드 내역을 갖게 된다 — 그때 `Biz21_Excel`의 첫 칸 `No.` 아래 펀드 블록을 눈으로 다시 본다.
