## 원본 이상한 점
- **저장(`update`)이 원본 서버에 없다** — 화면에서 셀을 고쳐도 저장되지 않는다. 데이터는 [파일업로드]로만 들어온다. 원본 그대로 거절.
- 업로드가 칸0(코드)로 `selectByCodeName`을 부르는데 이 SQL은 **발행기관명 LIKE**라 코드로는 거의 못 찾는다 → 항상 새 행(같은 파일을 두 번 올리면 중복). 같은 이름이 여러 건이면 `selectOne`이 실패해 전체 롤백.
- 조회 SQL에 회사 조건이 없다(DB 1000건이 모두 회사 79인데 다른 회사 계정에도 다 보인다). 원본 그대로.
- 빈 줄이 파일 중간에 있으면 코드가 빈 행이 하나 생긴다(원본 동작).
- 국가코드 콤보의 Collapse 핸들러 본문이 주석 처리돼 있고, 목록 이름 열은 `EmpNationCode`, 콤보는 `NationCode`로 코드 종류가 다르다.

## 제안 (03 원칙 5)
- 저장을 동작하게 하려면 `fnd07_issuing_entity.insertUpdate`(이미 매퍼에 있는 업서트)를 그리드 저장에 쓰는 서비스를 만들면 된다. 사용자 승인 전에는 반영하지 않았다.
- 업로드가 코드로 기존 행을 찾으려면 `selectByCodeName`이 아니라 코드 비교 SQL이 필요하다(지금은 항상 신규).
