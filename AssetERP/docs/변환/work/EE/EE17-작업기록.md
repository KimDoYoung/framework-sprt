## 제안 (03 원칙 5 — 사용자 승인 전에는 반영하지 않음)
- 진행단계가 0건일 때: 원본은 처리 폼을 이전 개발의 내용 그대로 둔다. 여기는 폼을 막고 비운다(AS-IS의 `result == null` 갈래). 원본 그대로가 맞다면 알려 달라.
- 버튼 색: `ColorButtonBottom`의 진행중·완료·이행불가가 button-types 표에 없다 — 지금은 `assign`·`save`·`cancel`로 구분만 했다. 표에 정식 항목을 추가할지 사용자 결정.
- 서버 보안: 상태 변경·저장 API는 원본처럼 "로그인한 사람이 그 단계 담당자인가"를 서버에서 검사하지 않는다(화면이 `mine`으로 막음). 서버에서도 막을지 사용자 결정(EE16 제안과 같음).
- 데이터 정리: 변경프로그램 [삭제]는 프로그램을 `use_yn=false`로만 하고 첨부파일·scm30 행은 남긴다(원본 그대로). 정리 규칙이 필요하면 사용자 결정.
- 확인 도구: 시험 행(scm30·scm13·sys10)을 같은 세션 안에 지울 방법이 없어 파일일괄등록·등록 흐름을 시험하지 못했다. `yunhee api`에 `--rollback` 같은 트랜잭션 되돌리기가 있으면 03 원칙 2를 지키며 확인할 수 있다(yunhee 제안).
