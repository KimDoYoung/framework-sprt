## API / SQL
새 API 3개(`SysMailController`·`SysMailService`·`SysMailMapper`, DTO `SysMailRes`·`SysMailSaveReq`):
- `POST /api/v1/sys/mails`(새 메일) · `PUT /api/v1/sys/mails/{mailId}`(고침) = AS-IS `Sys22_Mail.modelUpdate`(비밀번호 `to_encrypts`, 새 ID `f_create_seq()`, 회사 = 로그인 회사. `UpdateDataModel` 동적 INSERT/UPDATE를 메일주소·비밀번호·비고 문장으로 풀었다).
- `POST /api/v1/sys/mails/check` = `SendMailSMTP.checkCompanyMail` — G13 공용메일이 옮겨 둔 `CmpMailBookService.check`를 그대로 불러 쓴다(같은 코드).
SQL 고침 없음(03 원칙 4). 회사 조건은 UPDATE·SELECT에 더했다(로그인 회사 밖 행을 못 건드리게).

## 공통 절차와 다른 점
- 없음. 단, AS-IS `checkMail()`은 서버 메시지가 `"정상적인 접속입니다"`와 같을 때만 성공 안내를 띄우는데 서버(`checkCompanyMail`)는 그 문장을 만들지 않아, **AS-IS에서도 저장 뒤 항상 "오류 / 메일 또는 비밀번호를 확인해주세요"가 뜬다**. 그대로 옮겼다(작업기록 "제안").
