## 화면 흐름 (원본 확인)

- 화면 열림: 기준일 = 오늘 → 조회. 트리는 서버가 `ORDER BY path` 전위 순서 + `treelevel`(깊이)로 주고 `TreeUtil.makeOrgTree`가 깊이로만 부모를 정한다 → TOBE는 평평한 목록 그대로 `useTreeGrid`(depth). 조회 뒤 최상위만 펼침, 방금 등록한 조직(updatedModel)이 있으면 펼치고 선택.
- 루트 등록 버튼(`createRoot`)은 원본에서 주석 처리 → 최상위 조직은 회사 초기화가 만든다(kalpa에 루트 1건 있음).
- [하위조직등록] → 선택 없으면 "먼저 상위 조직을 선택해주세요" → `Org01_Edit_OrgCode`(insertData). 원본은 팝업 전에 `getSeq`로 codeId=infoId를 채번 → TOBE는 서버가 POST에서 채번(05 §6 행 추가).
- 그리드 [수정] 칸(ImageCell) → `Org02_Lookup_OrgInfo`(왼쪽 이력 그리드 420 + 오른쪽 `Org02_Edit_Info` 폼 560, 980×500). 저장·삭제 뒤 본 화면 다시 조회.
- `Org01_Edit_OrgCode`의 수정 모드(삭제 버튼)는 이 화면에서 열리지 않는다(호출처는 insertData뿐). `Org02_Edit_Info.deleteCheck`도 호출처 없음. 둘 다 원본 그대로 컴포넌트에 둔다(버튼·이벤트 수 맞춤).

## 화면 구성

- 본 화면: 툴바 `기준일 [날짜] [조회] [하위조직등록] [조직도보기]` + 트리 그리드(SingleGrid + useTreeGrid, 행번호 없음 — `getTreeGrid`가 `setRowNumHidden(true)`). 컬럼: 조직명 450(트리) / 조직코드 100 / 조직구분 100 / 조직 장 120 / 조회순서 100 / 최근변경일 100 / 수정 80(아이콘 버튼) / 변경사유 300 / 개설일 100 / 폐쇄일 100.
- `Org01_Edit_OrgCode`: Modal "조직상세 정보" 폼 폭 560, 라벨 70. 버튼(아래 가운데) [삭제(수정 모드)] [저장] [닫기].
- `Org02_Lookup_OrgInfo`: Modal "조직정보 History" 980. 이력 그리드 SingleGrid(행번호, 개설(변경)일 100 / 조직(부서)명 300). 버튼 [삭제] [저장] [닫기].
