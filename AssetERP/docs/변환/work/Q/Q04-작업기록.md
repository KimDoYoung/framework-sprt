## 결정
- 공모주 달력의 yyyyMM 칸 Enter는 원본이 마지막 `rvMap`을 그대로 다시 열 뿐 칸 값을 반영하지 않아(L117-121) 그대로 옮겼다. 사용자에게 어색하면 제안 1.
- [출력/다운로드]는 RD(`Sch10_Rd_IpoList`)로 했다(엑셀 대체 안 함) — RD 시뮬레이터로 mrd·rv를 대조.
- `Sch12_Lookup_IpoCorpList.retrieve`의 `status == 1` 분기("해당 주간사에 대한 주소가 없습니다…" 뒤 `hide`)는 결과가 비었을 때로 해석했다(안 그러면 항상 뜬다). 근거: 같은 문구가 `siteCell`의 `result.getResult().size()==0` 분기에도 있다. **미확인**.

## 제안 (사용자 승인 전에는 반영하지 않음)
1. 공모주 달력 yyyyMM 칸의 Enter가 칸에 친 달을 반영하게 한다(원본은 반영하지 않음).
2. yunhee `analysis screen --section events`가 `this.getButtonBar().add(cancleButton)`로 붙은 창 아래 버튼을 "도달 불가"로 표시한다(`Sch12_Lookup_IpoCorpList` E2) — 창 버튼 줄(`getButtonBar().add`) 판정은 0.5.5의 043-9·13이 고쳤다고 했지만 이 경우(`this.getButtonBar()`)는 여전히 표시됨.
3. yunhee `port-save --cols`에 camelCase 속성 이름을 주면 INSERT/UPDATE 열 이름이 `demandSdateAlarmYn` 그대로 나온다(DB 컬럼 `sch11_demand_sdate_alarm_yn`으로 풀어야 함). 속성↔컬럼 대응은 `analysis model`이 이미 안다.
4. 공통 `RdViewer`에 위 툴바 슬롯(`toolbar` prop)을 두면 `RdViewer_Sch10`·Biz10·Car04·Emp31 모드를 한 부품으로 쓸 수 있다(부품 제안, 세 번째 화면에서 승인 요청).
5. `sch11` 알람 6칸이 `varchar(5)`('true'/'false')라 저장 때 불리언을 그대로 넘기는 현재 방식은 PG 할당 캐스트에 기대고 있다 — 다른 `*_yn` 열(O01 알람 등)도 같다.
