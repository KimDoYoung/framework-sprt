## 원본과 다른 점 / 결정 (03 원칙 4·5)
- 확정(`confirmChk(I)`+`insertManlOrg`)·확정취소(`confirmChk(D)`+`deleteByManlJobId`)는 AS-IS가 서버를 두 번 부르지만 TOBE는 한 트랜잭션 한 호출. 검사 메시지·순서는 같다.
- 확정은 작성시작일 검사를 insert 앞에서 한다(AS-IS는 insert 뒤 `result.fail`이라 insert가 롤백되는지 불확실).
- 서버 `current_setting('app.current_user')`를 쓰던 SQL 5곳(tdm44 insert·clearEndYn·updateOrgIdByTaskId, tdm42 insert·insertByManlJobId, tdm43 updateOrgIdByTaskId)은 `#{updName}`으로(N15·TdmRoleAllcMapper 전례).
- 부서변경(`changeOrgId2`)은 화면 모델 목록 대신 `{manlJobId, roleId, orgId, items[{taskId, orgId}]}`를 받고 `exctId`는 서버가 기존 부서의 확정 행에서 읽는다.
- 확정/확정취소 뒤에는 위 목록을 다시 읽지 않는다(AS-IS 그대로).
- 그룹 그리드 체크 열은 보기 전용, 행 클릭이 selectYn을 뒤집는다 — AS-IS는 `CheckBoxCell`과 `RowClick`이 둘 다 값을 바꾸는 구조라 체크 칸을 정확히 눌렀을 때 결과가 불확실했다. TOBE는 어디를 눌러도 한 번 뒤집힌다.
