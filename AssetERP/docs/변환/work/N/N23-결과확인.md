## 남은 문제
- 항목 7·7-1 브라우저 시험은 일괄. 본 화면의 묶음 헤더 3개와 금지 아이콘(승인의견·보고의견 열), 마지막 행 자동 선택, 아래 두 그리드의 단추 상태(승인시작·일괄승인의 활성 조건), 승인 의견 창의 [등록]/[반려] 전환, 승인상세 창의 모양은 눈으로 못 봤다.
- **`f_get_tdmSubmitPossibleYn`이 이 DB에서는 boolean이다.** AS-IS 소스(`Tdm59_ChckApprCmnt.checkTdmSubmitPossibleYn`)는 'Y' 또는 불가 사유 문구를 돌려받는 것으로 읽는데, 이 DB의 함수는 true/false만 돌려준다(DB 변경 금지, 03 원칙 1). 서비스가 둘 다 받고 boolean이면 AS-IS 클라이언트의 옛 문구("제출이 가능한 상태가 아닙니다"·"제출취소가 가능한 상태가 아닙니다")를 쓴다. 운영 DB의 함수와 사유 문구는 확인하지 못했다.
- 증빙자료 창과 [AI]는 이 화면 범위가 아니다(2단계). 승인 쪽은 증빙 건수만 보여 주고 누르면 안내한다.
- 시험 흔적: DB 테스트는 모두 롤백. API는 GET만 불러 흔적 없음.
