## 공통 절차와 다른 점
- 비품원장(`updateDepn`)과 일반(`update`)을 클라이언트가 서비스 이름으로 고르던 분기를 서버 `AstTrIntrinsicService.save`가 한다(종목 대분류 50·55 또는 소분류 952002).
- 원장 입출고 거래가 아니면 `!isBookYn()`일 때 장부금액 = 거래금액·취득거래ID = 자기 자신을 서버가 새 거래ID가 만들어진 뒤 채운다(`selfPur`, 이상한점 #147).
- 거래 삭제 전 검사(감가상각 → 회계마감)를 행마다 차례로 한다(원본은 비동기 카운터, #146). 삭제 자체는 U04 `POST ast/trs/delete`를 재사용한다.
- `ast.Ast07_Settle.update`의 NEW와 MODI(`updateSettle`)가 같은 뒷부분(전표 승인 검사 → 미수/미지급 원화금액 정리 → 분개 생성)을 쓰도록 `AstSettleService.finishSettle`로 뽑았다. `Ast07_Lookup_Settle`에는 거래 기준 `target`(NEW/MODI)을 더했고, MODI의 [닫기]는 원본처럼 `callback(settleModel)`이라 분개를 다시 읽는다.
- 12 원칙: 편집창은 AS-IS 600폭보다 40 넓은 640(라벨 120 + 입력 450 + 여백), 보유자산 조회창 1000(AS-IS 그대로).
- `GET ast/book-depns`는 감가상각 원장 탭(`AstBookDepnController`)이 이미 써서 보유자산 조회창은 `GET ast/book-depns/hold`로 만들었다.
- `selectByPayCode`의 `bookIoCheck`(거래 불러오기: 입출고 구분 1·9만)와 검색어(거래유형+거래처(계좌)+자산분류+종목+적요) 대조는 AS-IS와 같다.
