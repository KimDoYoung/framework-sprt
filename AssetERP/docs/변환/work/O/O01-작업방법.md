- 본 화면: 위 조회줄(분류·주기구분·검색·체크 2) + 툴바 [조회][등록][삭제][담당자 변경], 아래 그리드(`MultiGrid`: 수정 아이콘 45 · 분류 150 · 스케줄명 300 · 주기구분 120 · 처리일정보 150 · 공유부서 130 · 공유자 120 · 알람설정 200 · 데일리여부 80(가운데) · 비공개여부 80(가운데) · 사용여부 80(`addBooleanString` — 값이 true면 `true`/`false` 글자)).
- 등록·수정 창: `LookupModal` 850폭, 위 행 구성은 위 표. 모달 폭은 03 원칙 21(열 합계) 대신 AS-IS 850을 그대로(안쪽 그리드가 380+100+180 이하).
- 팝업: 위 6개 새 창 + 재사용 부품.

## 공통 절차와 다른 점
- `GridInsertRow`의 새 행 ID: AS-IS는 클라이언트가 새 ID를 받아 창을 열자마자 `update01()`으로 INSERT하고, 닫기에서 롤백(DELETE)한다. TOBE는 `POST`로 먼저 만들고 `DELETE`로 롤백하는 같은 순서를 따른다.
- 공유 그리드 저장·삭제는 AS-IS가 `GridUpdate`·`GridDeleteData`를 동시에 부르고 둘 다 끝나면 `updateEnd`를 부른다. TOBE는 저장 → 삭제 → 다시 읽기 순서로 부른다(결과는 같다).
- `SchWriteGroup*`의 공유 API는 `infoId` 자리에 작성그룹 ID를 쓰고 `requireGroup`을 건다 → 이 화면의 공유는 별도 엔드포인트로 같은 매퍼 SQL(`insertShare`·`updateShare`·`deleteShares`)을 쓴다.
