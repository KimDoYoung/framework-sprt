**의존 (다음 단계)**

- `Crm09_Lookup_SelectSingle`("emp" 모드로 열림) — 상대방 회사명·성명을 채운다. crm 도메인.

**제안(승인 대기)**
- **`insertCheck` 버그(위 ②)**: [등록]을 한 번 누르면 이후 아래 목록의 저장·삭제가 위 목록(인원·재고)을 새로 읽지 않는다. 원본 그대로 두었다. 고치려면 콜백에서 `insertCheck.current = false`를 하거나 조건 없이 `retrieve()`.
- **구매수량 0**: `bmt01_buy.selectByCompanyId`·`selectById`의 `buy_amt / buy_qty`는 수량이 0이면 SQL 오류(division by zero)라 조회가 통째로 실패한다. 원본 SQL 그대로 두었고 화면 저장도 수량 0을 막지 않는다(`null`만 막는다). 저장 때 0을 막거나 SQL에 `NULLIF`를 넣는 안.
- **UX-02**: 툴바에 조건 2개 + 체크 1개 + 버튼 4개라 초기화를 넣지 않았다. 일괄 화면시험에서 한 줄이면 `onReset={sp.reset}`만 켜면 된다.
- **제공금액**: 새 제공내역 행의 금액은 `구입금액 ÷ 구매수량`(Long 나눗셈 = 버림)이다. 구매수량이 없거나 0이면 JS는 비워 두고 원본은 `ArithmeticException`이라 저장이 안 된다.
