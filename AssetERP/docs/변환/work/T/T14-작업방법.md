## SQL 이식
| SQL ID | 테이블 | 그대로 / 수정(사유) |
|:---|:---|:---|
| `selectByPublicJournal` | car03_booking, car01_info, car04_journal | 본문 그대로. 열 순서를 `CarPublicJournalRes`에 맞추고 주행 전·후를 `NULL`로 추가(record 생성자 자동 매핑). `fix_yn`·`close_yn`은 불리언으로 변환. infoId 분기 `<if>` |
| `checkBookingId` | car04_journal, car01_info | 행 수만 필요해 `COUNT(*)`, 로그인 회사 조건 추가(보안 보강) |
| 확정·확정취소 저장 | car04_journal | `updateFix`와 같은 열이되 주행 전·후는 `NULL`(AS-IS 조회에 없고 updateCheck가 null로 보냄). 새 일지는 `insertPublicFix` |

## 공통 절차와 다른 점
- 확정·확정취소는 AS-IS가 클라이언트에서 행마다 `updateCheck`를 부르던 것을 서버 한 번(`public-fix`)으로 했다(T11 `fix`와 같은 방식). 결과(행마다 UPDATE 또는 INSERT)와 마감 거절 메시지는 같다.
- 원본 필수 검사는 행선지·목적이 비면 거절한다(T11 편집창과 달리 일반업무용 거리 조건 없이 항상).
