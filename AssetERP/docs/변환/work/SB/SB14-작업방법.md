# SB14 BatchMain `extrFund` — 작업방법

골격은 `SB01-작업방법.md`, 펀드 반영 공용 부분은 `SB13-작업방법.md`(`AssetErpFundSync`).

## extrFund 분기
- 원본 `BatchMain.extrFund` L1282-1476. `GET·POST /api/v1/batch/extrFund?companyId=ALL|숫자&ifCode=ALL|SFTP_SHFP_01…&worker=…`
- **ICAM을 읽지 않는다.** 전부 asseterpdb: `ifi30_fund`(타사무 SFTP 수신 펀드) ⨝ `ifi29_am_corp_mapping`(운용사→회사 맵핑, 기간).
- 기간: **오늘 송신분만**(원본의 전영업일~전일 계산은 주석 처리).
- 처리 순서
  1. `fnd03_consignment.insert3` — 수신 수탁사 중 회사에 없는 것 추가(외부 코드는 ifCode에 따라 etc01·etc06).
  2. `ifi30_fund.selectOfficeWork`(아직 맵핑 안 된 사무수탁사 코드)마다: 회사 0에서 `selectByExtrCode`로 자체코드 찾기 → 없으면 알림 후 AS-IS처럼 실패(#209) / 2개 이상이면 알림 후 첫째 사용 → `countByCode`=0이면 `fnd06.insert3`(회사 복사), 아니면 알림.
  3. `ifi30_fund.selectByCompanyId`의 펀드마다 `icam03` 모양으로 옮겨 `AssetErpFundSync.sync(회사, 펀드, icamYn=false)`.
- 옮기는 규칙: 기준일=송신일, 해지여부 N이면 해지일 null, 빈 문자열 날짜는 null, 정식명=펀드명, 수탁은행 null, 차등분배 null, 사무수탁사 자체코드는 회사의 맵핑이 **정확히 1개**일 때만(0개·2개 이상은 알림).
- 한 트랜잭션, 실패 시 원인 문구만(`BusinessException`). 결과 문구(그대로): `extrFUND 작업완료..commit`.
