# SB07 BatchMain `ipoMismatch` — 작업방법

골격은 `SB01-작업방법.md`. 이 ID는 `BatchAction` 구현체 `IpoMismatchAction`(`biz.batch.action`)다. 공모주 일정 로직은 `biz.batch.ipo`(`BatchIpoService`·`IpoScheduleParser`)를 SB05~SB07이 공유한다.

## AS-IS → TOBE
- 원본: `BatchMain.ipoMismatch L693-708` (`/BatchMain?actionCode=ipoMismatch`)
- 처리: `sch14_ipo_mismatch.createIpoMismatch`(DB 함수 `f_create_ipoMismatch`) 실행 후 commit
- 호출: `POST /api/v1/batch/ipoMismatch` — `data`는 큰 문자열이라 **POST 폼 본문**으로 보낸다(GET은 URL 길이 제한). Tomcat 폼 본문 기본 상한 2MB(`server.tomcat.max-http-form-post-size`) 안이어야 한다.
- 결과 문구(그대로): `공모주일정 미일치내역 생성 완료.. commit`
- **두 번 commit**: 저장과 후처리를 AS-IS처럼 별도 트랜잭션으로 나눴다(`BatchIpoService`의 메서드마다 `@Transactional`, Action이 순서대로 호출). 후처리가 실패해도 크롤링 저장분은 남는다.

## SQL 이식
`BatchIpoMapper.xml` — 원본 SQL 그대로(원본 위치는 파일 머리 주석). 달라진 곳: `SELECT *`를 쓰던 `sch13_ipo_crawling.selectByTrackId`·`sch10_ipo.selectByIssCorpCode`는 쓰는 열만 별칭으로 적었다(조건·정렬 그대로). `updateCancelYn`의 주석 처리된 옛 조건은 뺐다. 날짜는 `LocalDate`로 넘긴다.

## 공통 절차와 다른 점
- `data`가 없으면 AS-IS는 NullPointerException으로 롤백된다 → 입력 검사로 `INVALID_INPUT "data가 없습니다."`(문구만 분명하게, 동작은 같게 실패).
- 응답은 `ApiResponse<BatchRes>`(SB01 결정).
- 원본-이상한점 #203(끝 열이 비면 실패)·#204(날짜 칸이 비면 NPE) — 그대로 옮김.
