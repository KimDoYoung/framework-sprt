# SB22 BatchMain `changedItemName` — 작업방법

골격 `SB01`. ICAM을 읽지 않는다(내부 DB만).

## changedItemName 분기
- 원본 `BatchMain.changedItemName` L2913-2964. `GET·POST /api/v1/batch/changedItemName` (파라미터 없음, `worker`는 읽기만 하고 쓰지 않는다)
- 기준일 = `f_get_biz_date2(0, 오늘, '-1', 'true')`(AS-IS `sys12_calendar.bizDate2`; 공통 매퍼에 `selectBizDate2` 추가).
- 처리: `icam20_price.selectChangedItemName`(그 날 주식 시세 중 같은 표준코드의 다른 날 종목명과 다른 것; `SELECT *`는 열 별칭으로 풀었다) → 행마다 ① `icam20_price.updateItemName`(기준일이 아닌 시세) ② `flt10_tr.updateItemName`·`updateTrItemName` ③ `flt11_book`·`flt12_book_month`·`flt13_book_init`의 `updateItemName`. 한 트랜잭션. 새 매퍼 `BatchItemNameMapper`(+XML).
- 결과 문구(그대로): `종목명 변경 작업완료..commit`. 오류: 원인 문구만.
- `icamPrice`(SB20)가 같은 날 먼저 돌아야 의미가 있다(시세를 읽는다).

## 시험
시뮬레이터 CSV 없음(ICAM 읽기 없음). 시험이 `f_get_biz_date2` 결과로 기준일을 구해 가짜 시세·flt 행을 넣는다.
