# SB12 BatchMain `icamData` + ICAM 읽기 공통 부품(`IcamReader`) — 작업방법

골격은 `SB01-작업방법.md`. 이 ID가 ICAM 연계 15개(SB12~)의 공통 부품을 만든다.

## 결정 (사용자, 2026-11-04)
- ICAM은 **읽기 전용**이다. 원본 코드를 거의 그대로 옮기고, "ICAM에서 읽는 한 줄"만 `IcamReader`로 바꾼다.
- `application-<profile>.properties`의 `asseterp.icam.mode`로 고른다: `simulator`(CSV) / `real`(Tibero, 운영) / `disabled`(기본, 거절).
- 시뮬레이터 데이터는 `AssetERP/data/icam-simulator/{icam|icam2}/{쿼리ID}.csv`. (옛 안 "PostgreSQL `icam_sim` 스키마"는 03 원칙 1 때문에 폐기)

## 공통 부품 (`biz.icam.reader`)
| 클래스 | 역할 |
|:---|:---|
| `IcamReader.read(IcamServer, 쿼리ID, params)` → `List<IcamRow>` | AS-IS `DatabaseFactoryICAM(2).openSession().selectList("쿼리ID", param)` 대체 |
| `IcamServer` | `ICAM`(운용) / `ICAM2`(자문) = CSV 하위 폴더 `icam`·`icam2` |
| `IcamRow` | 열 이름→문자열. `getString/getDate/getLong/getDecimal`, 빈 값은 null. **열 이름은 AS-IS SELECT 별칭 그대로** → real 구현이 같은 이름으로 돌려주면 액션은 안 바뀐다 |
| `CsvIcamReader` | simulator. 헤더 `@이름` 열은 조건 전용(같은 이름 파라미터가 오면 일치 행만, `%`는 LIKE) |
| `DisabledIcamReader` | disabled(기본) |
| `RealIcamReader` | real — 자리만(Tibero JDBC는 운영 전환 때) |

CSV 규칙은 `data/icam-simulator/README.md`. 설정: `asseterp.icam.mode`(기본 disabled, 환경변수 `ASSETERP_ICAM_MODE`), `asseterp.icam.simulator-dir`(개발 프로필 기본 `../data/icam-simulator`).

## icamData 분기
- 원본 `BatchMain.icamData` L1042-1124 (원본 주석 "(사용안함)"). `GET·POST /api/v1/batch/icamData?companyId=ALL&worker=…&stdDate=…`
- 처리: `companyId=ALL`→`%`. `worker=batch`이면 기준일 = 직전 영업일(`sys12_calendar.bizDate`), 아니면 `stdDate`. ICAM 회사(`sys01_company.selectIcamCompanyCode`)마다 `icam02_data.selectIcamData`(ICAM)를 읽어 `icam02_data.insert`. 한 트랜잭션(AS-IS commit/rollback).
- 결과 문구(그대로): `DATA 작업완료...commit`.
- SQL: `BatchIcamMapper.xml` — `selectIcamCompanyCode`·`insert`는 본문 그대로(별칭만 DTO 필드). ICAM 쪽 `selectIcamData`(Tibero SQL)는 옮기지 않고 CSV 열로 대신한다.
