# SB13 BatchMain `icamFund` + `AssetErpFundSync` — 작업방법

골격은 `SB01-작업방법.md`, ICAM 읽기 부품은 `SB12-작업방법.md`.

## icamFund 분기
- 원본 `BatchMain.icamFund` L1126-1277. `GET·POST /api/v1/batch/icamFund?companyId=ALL&worker=…`
- 처리: `companyId=ALL`→`%`. 기간 = 직전 영업일(`sys12_calendar.bizDate` type -1, 회사 0) ~ 어제. ICAM 회사(`selectIcamCompanyCode`)마다, 기간의 **달력 날짜마다** `icam03_fund.selectIcamFund`(ICAM)를 읽는다.
  - 0행이면 `sys97_notice_log`에 `icamFundList(icam03) size : 0` (별도 트랜잭션).
  - 각 행: `icam03_fund.delete`(회사·기준일·펀드) → `insert` → `AssetErpFundSync.sync(companyId, 행, icamYn=true)`.
  - 회사가 끝나면 `fnd03_consignment`·`fnd09_trust_bank`·`fnd06_office_work`의 `insert2`(없는 코드만 추가).
- 한 트랜잭션. 실패하면 모두 되돌리고 `errMsg / 원인`(AS-IS 단계 문구 그대로)을 `BusinessException(INTERNAL_ERROR)`으로 던진다 → `sys97_notice_log`에 오류가 남는다.
- 결과 문구(그대로): `FUND 작업완료..commit`.

## AssetErpFundSync (= assetErpFundInsert, SB14 extrFund와 공용)
1. fnd01(회사+펀드코드) 없음 → 새 번호(`dbConfig.getSeq`), 상품여부 false, ICAM관리 = 인자. 반영(Y).
2. 있으면 기준일 이전 가장 최근 fnd02와 **29개 항목**을 비교(펀드명·정식명·수탁사·사무수탁사·운용부서명·협회분류 7종·만기예정일·수탁은행·운용역 2·통화·다음결산일·다음보수인출일·예탁원 2·보수율 4·설정액·순자산·차등분배). 하나라도 다르면 반영(Y). null↔값도 다름.
3. 반영(Y)이면 fnd01 upsert(해지일이 있으면 해지구분 true) → 같은 기준일의 fnd02 삭제 → fnd02 insert.
- 숫자는 값으로 비교한다(2.50 = 2.5). AS-IS는 Java `Double.equals`.
- 원본-이상한점 #207(fnd02 없으면 NPE → 롤백)·#208(운용부서명 항상 null이라 매번 변경 판정).
