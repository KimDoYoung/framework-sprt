# SB02 BatchMain `sch04Insert` — 작업방법

골격은 `SB01-작업방법.md`. 이 ID는 `BatchAction` 구현체 `Sch04InsertAction`(`biz.batch.action`) 하나다.

## AS-IS → TOBE
- 원본: `BatchMain.sch04Insert L87-135` (`/BatchMain?actionCode=sch04Insert`)
- 처리: stdDate가 비면 직전 영업일 `f_get_biz_date(0, 오늘, '-1')`(`sys12_calendar.bizDate`), 있으면 `yyyy-MM-dd` 파싱 → 사용 중인 회사(`sys01_company.selectByUseYn`)마다 `sch04_list.selectInsert`(292줄 INSERT…SELECT) → commit
- 호출: `GET·POST /api/v1/batch/sch04Insert` (파라미터 `stdDate`가 필요한 작업만 사용). 인증은 API key + IP.
- 결과 문구(그대로): `미처리 스케줄 Sch04에 Insert 작업완료.. commit`
- 한 트랜잭션: 모든 회사를 `@Transactional` 하나로 묶는다(AS-IS도 한 SqlSession, 마지막에 commit, 예외 시 rollback). 실패하면 `sys97_notice_log`에 `BatchMain.sch04Insert` 오류가 남는다(`BatchService`).

## SQL 이식
`sys12_calendar.bizDate` → `BatchCommonMapper.selectBizDate`; `sys01_company.selectByUseYn` → `BatchCommonMapper.selectUseCompanies`(이름·ID만 읽음, 조건 그대로); `sch04_list.selectInsert` → `BatchSchMapper.insertSch04List`(**본문 원본 그대로 복사**, 파라미터 `companyId`·`stdDate`만)
날짜 파라미터는 DB 함수 시그니처가 `date`라서 `LocalDate`로 넘긴다(AS-IS의 `java.util.Date`와 같은 값).

## 공통 절차와 다른 점
- 응답은 `ApiResponse<BatchRes>`(SB01 결정).
- `stdDate` 형식 오류는 AS-IS처럼 null이 된다(원본-이상한점 #201).
