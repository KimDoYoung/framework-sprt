## SQL 이식
- `selectByCompanyId`·`selectById`: `SELECT a.*`를 DTO 열로 풀었다(계정속성명 `f_cdnm`, 상대 대표계정명 서브쿼리는 원본 그대로). 검색은 `UPPER(코드||이름) LIKE UPPER(검색어)`, `ORDER BY 코드`.
- `insertInitData`: 열 목록 없는 `INSERT … SELECT`를 열 순서대로 적었다(원본은 `${companyId}` 문자열 치환, 여기서는 `#{}`). 관리자 회사(0)의 같은 코드만 복사한다.

## 공통 절차와 다른 점
- 회사 범위: 저장·삭제는 로그인 회사만(SQL에 회사 조건, 05 §6). 기초데이터생성은 **관리자 회사만** 서버가 검사한다(원본은 버튼 노출만 막았다). 고객사마다 서비스를 따로 부르던 것을 한 트랜잭션으로.
- 필수 열(코드·이름·속성)은 원본이 DB NOT NULL 오류를 그대로 보여 줬다 → 서버가 "대표계정코드는 필수입력 항목입니다"·"대표계정명은 필수입력 항목입니다"·"계정속성은 필수선택 항목입니다"로 막는다(E19와 같은 처리, 작업기록 제안 ④).
- 상대대표계정코드 칸은 글자를 직접 넣을 수 있다(LookupTriggerField) — 셀 편집기는 글자 입력, 확정하면 `%글자%` 검색.
- 조회창에는 초기화(UX-02)를 넣지 않는다: 600폭에서 툴바가 두 줄로 넘어간다(높이 72 확인).
- 계정속성 콤보 셀은 E26 평가등급(`CompareCode`)과 같은 방식(이름을 보이고 `valueSetter`로 코드를 저장).
