## SQL 이식
- `act11_tr_map.selectByCompanyId`·`selectById`: `act11_tr_map.*`를 DTO 열로 풀었다(거래명 JOIN·입출고구분명 `f_cdnm`·손익대표계정명 서브쿼리는 원본 그대로). **`selectById`는 원본이 `INNER JOIN ast05_tr_code`라 거래코드가 없으면 저장 직후 행이 비어 `LEFT OUTER JOIN`으로 바꿨다**(저장 응답이 항상 있어야 한다)
- `act12_journal_map.selectByJournalGroup`·`selectById`: `act12_journal_map.*`를 DTO 열로 풀었다(차대구분명 `f_cdnm`, 대표계정명 JOIN 그대로)
- `insertInitData` 둘: 열 목록 없는 `INSERT … SELECT`를 열 순서대로 적었다. 거래맵핑은 (거래코드, 분개그룹), 분개맵핑은 **분개그룹 전체**를 지우고 다시 복사한다(원본 `deleteByJournalGroup`에 거래코드 조건이 없다)
- `ast05_tr_code.selectBySearchText`: 조회창에 쓰는 열(`trCodeColumns`, E29)만 남기고 `act11_tr_map`·분류 JOIN 계산 열은 뺐다. `ast05_asset_type like`·`COALESCE(finance_yn…)`·수령/지급 LIKE·`useYn "true"` 조건은 그대로

## 공통 절차와 다른 점
- 회사 범위: 거래맵핑·분개맵핑 저장·삭제는 로그인 회사만(SQL에 회사 조건), 기초데이터생성은 **관리자 회사만** 서버가 검사한다(원본은 버튼 노출만 막았다). 고객사마다 서비스를 따로 부르던 것을 한 트랜잭션으로
- 필수 검사는 서버도 같은 문구로 한다(거래코드 / 분개그룹·순번·대표계정코드·차대구분 — 원본은 화면 검사뿐이라 DB NOT NULL 오류를 막는 효과)
- 조회창은 모달 폭을 620으로 했다: antd 모달 안쪽 여백(24×2) 때문에 600에서 사용여부 열이 잘린다. 초기화(UX-02)는 넣지 않는다(툴바가 600폭 안에서 줄바꿈 위험)
- `edit` 모드(저장·행 추가·삭제)는 E30 화면에서 열 곳이 없다 — 다른 화면이 변환될 때 쓴다. 이번엔 컴파일·`analysis ui` 대조·DB 테스트(저장·삭제 API는 E29)로만 확인
