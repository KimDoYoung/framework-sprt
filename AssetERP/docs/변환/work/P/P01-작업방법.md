## 범위 (분석에서 정함)

- 클래스 3개 모두 이 ID에서 한다(전자결재 등 다른 도메인 의존 없음 → 1단계로 쪼개지 않음).
- `Fnd01_Edit_FundPlan`은 별도 창이 아니라 **Tab 아래(South 310) 폼**이다. 폼은 목록에서 고른 행을 보여 주고 선택이 없으면 비활성이다. 폼의 [저장]이 서버 `Fnd01_FundCode.update`를 직접 부른다(Tab에는 저장 버튼이 없다).
- `Fnd00_Lookup_FundCode`는 `Fnd01_Edit_FundPlan`의 확정펀드 칸에서만 열린다(`analysis screen`이 `open() 호출처 없음`으로 표시하는 것은 호출처가 다른 클래스라서). 일반 펀드(임시펀드 제외)를 고르면 확정펀드로 넣고 펀드상태를 "종료펀드"(`closeYn=true`)로 바꾼다.
- 폼의 `Fnd01_Edit_FundPlan.deleteRow()`(L345)는 버튼·이벤트에 붙어 있지 않아 도달 불가 → 만들지 않음. 폼에 있지만 레이아웃에 올리지 않은 칸(`fundFullName`·`emp1Name`·`emp2Name`·`managementRate`·`salesRate`·`consignmentRate`·`officeWorkRate`·`planSalesDscr`)도 화면에 없어 만들지 않았다. `orgCodeName`(운용부서)은 조회창 연결(`openLookupOrg`)이 주석 처리돼 값을 보기만 한다 → 읽기 전용 칸.
- 툴바의 [등록]이 `buttonBar`에 두 번 `add`되지만 같은 위젯이라 한 번만 나온다(버튼 3개).
- 열 때 조회한다(생성자 끝 `retrieve()`).

| SQL ID | 테이블 | 그대로 / 수정(사유) |

| `fnd01_fund_code.selectByFundPlan` | fnd01_fund_code, fnd02_fund_info | 그대로. `t1.*, t2.*` 대신 화면이 쓰는 열만 별칭(record `FundPlanRes`), 날짜 열은 `CAST(… AS date)`(DTO `LocalDate`). 정렬 `ORDER BY t1.fnd01_fund_cd`(별칭 모호성만 해결). 공통코드 이름은 AS-IS와 같은 `f_cdnm` |

## 공통 절차와 다른 점
- 03 원칙 4 예외(보안 보강) 셋: ① 저장·삭제에 회사·임시펀드 조건 ② 삭제 대상·ICAM 여부를 서버가 DB에서 확인 ③ 저장 뒤 다시 읽기(`selectPlanById`)에도 회사 조건. 모두 O04 `confirmUpdate`와 같은 성격.
- 폼에 올라 있지 않은 모델 열(운용부서 ID·운용역 ID·보수율 등)은 저장 SQL에서 건드리지 않는다 — AS-IS도 폼이 값을 바꾸지 않으므로 DB 값은 그대로다.
- 새 임시펀드의 `fnd02_fund_info.fnd02_fund_code_id`: AS-IS는 `UpdateDataModel`이 코드 ID를 채우는 순서에 기대는데 TOBE는 코드 ID를 먼저 채번해 `fnd01` → `fnd02` 순으로 넣는다(결과 같음, 순서만 다름).
