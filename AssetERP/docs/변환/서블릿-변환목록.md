# 서블릿 변환목록 (인벤토리)

작성 2026-11-04. AS-IS 서블릿(`web.xml` 매핑)을 **분기(fileType·mode·uploadType·actionCode) 단위**로 나눈 목록이다. 화면 변환 목록(`변환목록/01*`)과 달리 서블릿은 한 URL이 여러 업무 기능을 가지므로 분기 한 개를 ID 하나로 본다. 규칙은 `03-절대원칙.md`·`05-작업방법.md`를 그대로 따른다.

- 원본: `~/work/IDMS-IC/application/src/main/java/myApp/server/…` (`web.xml`은 `application/src/main/webapp/WEB-INF/web.xml`)
- 분기와 호출 화면은 `yunhee outline`·`yunhee cat`(분기 `service()` 구간)·`yunhee grep`(GWT `client/` 쪽 URL 문자열)로 뽑았다. `yunhee analysis servlet`은 `FileDownload`만 부분 동작해(`image` 한 분기만 출력) 쓰지 않았다 — yunhee 수정사항 후보.
- **TOBE 후보**는 컨트롤러에 대응해 보이는 엔드포인트가 *있다*는 뜻이지 AS-IS와 같다고 확인한 것이 아니다. 상태가 `대체추정`인 ID는 Phase 1에서 분기별로 대조(헤더·열·시트·메시지·SQL)해 `완료`/`대기`로 바꾼다.
- 화면 변환 때 이미 서블릿 호출이 REST로 바뀐 경우가 많다. 그래서 "서블릿 변환"은 새로 만드는 일보다 **빠진 분기 찾기 + 원본 대조**가 큰 비중이다.

## 상태 값
`대기`(TOBE 후보 없음) · `대체추정`(후보 있음, 대조 필요) · `설계필요`(세션·배치·외부연계처럼 구조가 달라짐, 먼저 설계 결정) · `호출없음`(GWT에서 호출하는 곳을 못 찾음, 사용자 확인 후 제외) · `제외`(RPC·백업·주석) · `완료`

BatchMain은 GWT 화면이 아니라 **외부 cron이 URL로 부르는 배치 진입점**이다(사용자 확인: 대부분 cron). AS-IS에는 세션·권한 확인이 없다. ICAM 시험 화면(Icam02·03·10·99)도 같은 URL을 부른다. 분기는 27개.

**결정**
1. **REST로 유지하고 인증만 바꾼다**: `POST /api/v1/icam/batch`(및 스케줄·알림·스크래핑 대응 경로). JWT 대신 **서버 간 API key + 호출 IP 제한**. 키·허용 IP·ICAM 접속 정보는 `application-<profile>.properties`(개발·운영 프로필별)에 둔다. 코드에 하드코딩하지 않는다. 내부 스케줄러(`@Scheduled`)로의 이전은 cron 전환(`대체` 작업) 때 따로 판단한다.
2. **`ConfigMyBatis-ICAM.xml`·`ConfigMyBatis-ICAM2.xml`은 TOBE에서 쓰지 않는다.** 접속 설정은 application 쪽 프로퍼티로 옮긴다(`대체/README.md`에 기록).
3. **ICAM 연결은 시뮬레이션한다.** 아래 "ICAM 접속 사실" 참고. `IcamBatchRunner`(D07·D08·D10에서 만든 자리) 구현체를 프로필로 고른다: `simulated`(개발 기본) / `real`(운영) / `disabled`(지금).

**ICAM 접속 사실 (AS-IS 설정 파일 `application/resources/config/mybatis/ConfigMyBatis-ICAM*.xml`에서 확인, 접속 계정은 여기 적지 않는다)**
- ICAM = **Tibero**(`com.tmax.tibero.jdbc.TbDriver`, 내부망 IP). asseterpdb(PostgreSQL)와 다른 DB 종류다. 운용 서버(`DatabaseFactoryICAM`)와 자문 서버(`DatabaseFactoryICAM2`) **두 곳**이다.
- BatchMain 말고도 읽는 곳이 있다: `Biz20_FeeCharge`(8곳), `Icam50_Source`·`Icam13_FeeBookCheck`·`Icam10_Fee`·`Icam06_FundBook`·`Icam00_Common`, `Fnd01_FundCode`·`Fnd03_Consignment`·`Fnd06_OfficeWork`·`Fnd09_TrustBank`. 이 화면들이 TOBE에서 ICAM을 어떻게 다뤘는지(`Disabled`·생략)는 각 ID 작업기록 확인 필요.
- Tibero JDBC 드라이버는 공개 저장소에 없는 상용 드라이버다 → 운영 연동(`real`)에서만 필요. 개발은 시뮬레이터로 드라이버 없이 간다.
- ICAM 쪽 SQL은 Tibero 방언이다. `simulated`는 PostgreSQL 방언으로 옮긴 읽기 쿼리를 쓴다(`yunhee port-sql`).

**시뮬레이션 방식 (사용자 결정 2026-11-04, SB12)** — ICAM은 읽기 전용이므로 원본 코드를 거의 그대로 옮기고 "ICAM에서 읽는 한 줄"만 `IcamReader`로 바꾼다. `application-<profile>.properties`의 `asseterp.icam.mode`로 고른다: `simulator`(개발) / `real`(운영, Tibero — 아직 자리만) / `disabled`(기본). 옛 안 `icam_sim` 스키마는 03 원칙 1(DB에 테이블 생성 금지) 때문에 폐기.
- simulator 데이터는 `AssetERP/data/icam-simulator/{icam|icam2}/{AS-IS 쿼리ID}.csv`(규칙은 그 폴더 README). 열 이름은 AS-IS SELECT 별칭, `@이름` 열은 조건 전용. 쓰기 쪽(`assetErpFundInsert` 등)은 asseterpdb에 원본대로 넣으므로 운영과 같은 로직이 시험된다.

**IPO 데이터 흐름 (AS-IS 코드 확인)** — IPO 일정 화면(`Sch10_Tab_IpoAdmin` E20 등)이 보여주는 일정의 원천이다.
1. 수집: `scrapingIpo`(L582)가 IPOStock 사이트(`ipostock.co.kr/sub03/ipo04.asp`)를 직접 읽어 오거나, **다른 서버가 수집한 데이터를 `data` 파라미터(행은 `\n`, 열은 `|`, 한 줄 = 종목 18열)로 밀어 넣는다**: `ipoScrap`(L629, IPOStock)·`ipo38Scrap`(L348, IPO38). 둘 다 `sch13_ipo_crawling`(스테이징)에 넣는다.
2. 대조: `ipoMismatch`(L693) 또는 `ipoScrap` 끝에서 DB 함수 `sch14_ipo_mismatch.createIpoMismatch`를 불러 `sch10`(IPO 일정)과의 **미일치 내역**을 만든다. `ipo38Scrap`은 `upsertSch10`(L425)으로 `sch10`도 직접 갱신한다.
3. 외부 의존: PostgreSQL만 쓰는 것은 `ipoScrap`·`ipo38Scrap`·`ipoMismatch`(받은 데이터를 저장 → 시험은 샘플 텍스트로 가능). **`scrapingIpo`만 외부 사이트 접속**(`IpoScraper`)이 필요하다.
4. **실제 경로 (2026-11-04, 사용자 확인)**: 119서버가 수집해 push하는 경로(`ipoScrap`·`ipo38Scrap`)와, 이 서버가 IPOStock을 직접 읽는 경로(`scrapingIpo`)가 **둘 다 쓰인다**(사용자: 운영 cron에 `scrapingIpo` 호출이 있을 것). 코드 근거: 분기 주석이 "IPOStock(홈페이지 스크래핑)"과 "119서버에서 Data 전달받아 생성"으로 나뉘고, `crawlingIpo`(IPO38 직접 스크래핑)만 2025-09-25 권한 문제로 중단·주석 처리됐다. → 변환 대상 **4개 모두**.
5. `scrapingIpo` 변환 메모: 파서는 `utils/scraper/IpoScraper`(99줄)·`IpoDetailPageParser`(182줄), HTML 파싱은 **jsoup**이라 TOBE에도 그대로 쓸 수 있다(`org.jsoup:jsoup` 의존성 추가). 외부 HTTP는 운영에서만 열린다 → 개발·자동 시험은 **저장한 HTML 샘플(목록·상세)**로 파서를 시험하고, 실제 사이트 접속은 `application-<profile>.properties`의 `asseterp.ipo-scrap.enabled`·`asseterp.ipo-scrap.base-url` 설정(SB27에서 이 이름으로 구현)으로 끄고 켠다. 사이트 HTML 구조가 지금도 맞는지는 운영 전환 전 실제 한 번 호출해 `sch13_ipo_crawling` 결과 행 수·열을 AS-IS와 대조한다.
