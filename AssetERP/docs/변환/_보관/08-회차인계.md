# 08. 회차인계 (AssetERP → 다음 회차)

AssetERP 변환을 다음 회차(`AssetERP_2` …)에서 다시 할 때, 이 회차의 문서와 결과를 **무엇을 그대로 쓰고 무엇을 새로 만드는지** 적는다.
이 회차를 진행하면서 계속 고친다. 

## 이 회차의 위치

- 브랜치 `AssetERP`, 폴더 `AssetERP/`. main에 합치기 전에는 이 브랜치에만 있다.
- 다음 회차 브랜치를 `AssetERP`에서 따면 이 폴더가 그대로 따라온다. 다른 곳에서 따면 `git show AssetERP:AssetERP/docs/<파일>`로 읽는다.
- 색인(`docs/as-is/`)은 git에 없다(사내 자료). 필요하면 05 B01 명령으로 다시 만든다.

## 문서별 재사용

| 문서 | 성격 | 다음 회차에서 |
|:---|:---|:---|
| `CLAUDE.md` | 틀은 공통, 경로·이름은 회차 고유 | 복사 후 `AssetERP` → `AssetERP_2`, 원본·대상 범위 문장을 고친다 |
| `01a-변환목록` | **회차 고유** | 새로 만든다. 표의 열·상태값·B/A ID 체계는 그대로 쓴다 |
| `03-절대원칙` | 공통 | 복사. 변경 이력을 새로 시작하고 이 회차의 이력은 "이전 회차" 줄로 요약한다 |
| `04-작업순서` | 틀은 공통, 묶음 표는 회차 고유 | 전체 순서(B → A 레퍼런스 → A 묶음 → 정리)와 "ID 하나의 진행"은 그대로, 묶음 표만 새 범위로 |
| `05-작업방법` | 공통(이 회차에서 보강된 상태) | 복사. §5 공통 부품 등록표와 §6 AS-IS → TOBE 대응표는 이 회차의 결과를 **출발점**으로 쓴다 |
| `06-결과확인` | 공통 | 복사 |
| `07-기반이식` | 틀은 공통, 가져올 곳은 회차 고유 | 가져올 곳을 OMS 대신 **이 회차의 `AssetERP/`**로 바꾸는 것을 먼저 검토한다(이름 바꾸기 표: 폴더·WAR·컨텍스트 `/AssetERP_2`·Redis 접두사) |
| `work/{id}-*` | 회차 고유 | 복사하지 않는다. 같은 화면을 다시 할 때 비교 자료로 읽는다(특히 비용 절) |

## 다음 회차 시작 순서

1. 브랜치와 폴더 `AssetERP_2/`를 만든다.
2. 위 표대로 문서를 복사하고 이름을 바꾼다.
3. 대상 범위를 정한다(예: 다음 도메인, 또는 같은 sys 화면을 다른 방법으로). 범위 SQL은 `docs/작업1.txt`처럼 `sys06_menu`에서 뽑는다.
4. B01 색인을 `AssetERP_2/docs/as-is/`에 만든다(`-t`로 다른 회차·OMS 색인과 분리).
5. 이 회차의 B09 정리(비용·시사점)를 읽고 바꿀 점을 03·05에 먼저 반영한다.
