# 01s. 변환목록 (경영관리 — 경영공지·사원·휴가출장·연봉·급여: Bbs/Emp/Pay)

`01r-변환목록.md` 다음에 이어지는 상태판이다. 상태는 ID가 속한 파일에만 적는다. ID는 `S` 접두사(S01~S29)로 01a~01r의 A~R과 겹치지 않는다.
ID 하나의 기록은 `work/{ID 첫 글자}/{id}-작업방법.md`, `…-작업기록.md`, `…-결과확인.md`(예: S03 → `work/S/`).

- 상태: `대기` → `분석` → `백엔드` → `프론트` → `확인` → `완료`, 또는 `보류`(사유를 비고에).
- **다음 작업은 아래 표에서 상태가 `대기`인 첫 줄**(01a~01r이 끝난 뒤). 순서는 사용자 지정(2026-10-28).
- **화면번호 열(신규, 2026-10-28)**: 사람들은 화면번호로 소통하므로 `sys06_menu.sys06_menu_no`(4자리)를 `화면번호` 열에 따로 적는다. 앞으로 새로 만드는 목록은 모두 이 열을 둔다. 기존 목록(01a~01r)은 그대로 둔다 — 거기 메뉴 열의 `#숫자`는 `docs/as-is/menus.tsv` 첫 열 값이다(이번 조회에서 이 값이 화면번호와 같음을 확인).
- 패키지는 도메인별(클래스 접두사 기준, 예: `biz.emp`, `biz.pay`; 공지는 `biz.bbs`). 소스 색인은 `{도메인}/screens/`. 하위 클래스(팝업·조회창)는 분석 단계에서 `yunhee analysis screen <화면> --list`로 확인해 같은 ID에서 함께 한다. 다른 도메인 컴포넌트(예: 전자결재 편집창 `Apr01_Edit_ApprDoc`)는 링크만 있으므로 **1단계만** 할지 분석 때 정한다.
- 같은 클래스가 여러 메뉴에 걸리면 나머지는 비고에 적고, 결과확인 항목 9(메뉴 여러 개)에서 같이 확인한다.
- 이 목록은 사용자가 준 클래스 목록을 `sys06_menu`에서 찾아 만들었다(2026-10-28, 29개 모두 메뉴 1개씩 일치, 전부 사용). 순서는 사용자가 준 목록 순서 그대로다.
- **민감·개인정보 메뉴**(`sys06_sensitive_info_yn`·`sys06_personal_info_yn`)가 연봉·급여 화면에 있을 수 있다. 분석 때 확인해 권한 처리를 정한다.
- 이미 변환한 같은 접두사 클래스의 API·조회창은 분석 때 먼저 확인해 재사용한다. 줄·서비스·테이블 수는 분석 단계에서 채운다.
