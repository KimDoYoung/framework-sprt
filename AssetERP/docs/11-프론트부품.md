# 11. 프론트 공통 부품

화면을 만들 때 **이 문서를 먼저 읽고, 여기 있는 부품의 소스는 열지 않는다**(03 원칙 15). props·반환값·함정이 여기 있다. 소스는 이 문서에 없는 동작이 필요할 때만 `yunhee outline`으로 줄을 찾아 그 줄만 읽는다.
05a 등록표는 "어느 ID가 무엇을 언제 만들었나"의 이력이고, 이 문서는 "지금 어떻게 쓰나"의 요약이다. 둘이 다르면 소스가 정답이고, 그 자리에서 이 문서를 고친다.
경로는 모두 `frontend/src/` 기준. 그리드 이름표는 `docs/grid-types.md`, 버튼 이름표는 `docs/button-types.md`.

## 1. 그리드 (`components/grid`)

```ts
import { SingleGrid, MultiGrid, CellEditGrid, ModalEditGrid, gbFor } from '@/components/grid';
import { iconCell } from '@/components/grid/iconCell';
const gb = gbFor<Row>();
```

| 부품 | AS-IS 신호 | 핵심 props |
|:---|:---|:---|
| `SingleGrid<T>` | 편집기·`setChecked` 없음 | 한 행 선택·읽기 전용. `onSelect(row)` |
| `MultiGrid<T>` | `setChecked(MULTI)`, 편집기 없음 | 체크박스 다중. `onCheckedChange(rows)`. 조회창은 `rowClick`(행 클릭 선택, 11a) |
| `CellEditGrid<T>` | 컬럼에 편집기 | `crud={useGridCrud(...)}` 필수 — 행·저장·삭제를 이 훅이 든다 |
| `ModalEditGrid<T>` | 편집기 없음 + 더블클릭 → `*_Edit_*` 팝업 | `onEdit(row)`, `editButton`(수정 열 추가) |

공통 props(`BaseGrid`): AG Grid props 그대로 + `gridRef`, `rowNumber`(기본 true, `setRowNumHidden(true)`면 false), `density`, `vCenter`(셀 세로 가운데, 기본 **true** — 03 원칙 20. AS-IS는 전 컬럼 vertical center. 체크박스 열은 제외. 끄려면 `vCenter={false}`), `sortable`(기본 **false** — 03 원칙 13), `animateRows`(행 이동·나타남 애니메이션, 기본 **false** — AG Grid 기본 true라 조회할 때마다 행이 움직여 보여서 끔. 필요한 그리드만 `animateRows`를 준다), `zebra`(홀수 행 줄무늬, 기본 **true** — 트리 그리드는 `useTreeGrid().gridProps`가 false를 넣는다. 색은 `theme.ts` `GRID_COLORS.oddRow`), `headerColor`, `sumRow={{labelField, label, sum[], avg[], count[]}}`(맨 아래 합계 행. `count`는 행 개수를 넣는 열 — AS-IS `getAggregationGrid`. 합계 행에도 아이콘 열이 그려지므로 `iconCell`에 `cellRendererSelector: p => p.node.rowPinned ? {component: () => null} : undefined`를 얹는다 — 예 `Apr01_Tab_TotalList`), `wrapperStyle`. 행이 없으면 "조회된 내용이 없습니다."(`localeText.noRowsToShow`, 화면에서 `localeText`를 주면 그쪽이 우선).
**두 그리드 사이 행 끌기**: 각 그리드 `onGridReady`에서 `api.addRowDropZone({getContainer: () => 반대편 div, onDragStop: p => …})`, 그리드에 `rowDragEntireRow`·`rowDragMultiRow`, 열에 `rowDrag: true`. 예: `Ast15_Page_TrCodeWindow`.
**함정**: `rowSelection`을 렌더마다 새 객체로 넘기면 부모가 다시 그릴 때 선택이 풀린다(E04 제안, 공통 부품 수정은 승인 대기) — 상수로 빼서 넘긴다. 가로로 화면 밖인 열은 DOM에 없다(가상화).

### 컬럼 헬퍼 `gb.*(field, 폭, '제목', opts?)` — AS-IS `addXxx`와 1:1
- 문자: `text`·`textCenter`·`textRight`·`textArea`(줄바꿈 유지)·`textStatus`·`textHtml`(AS-IS `addTextHtml` — 값의 HTML을 보여 준다. 굵게·기울임·밑줄·줄바꿈·색 태그만 살리고 나머지는 글자로, `sanitizeHtml`). 별 표시: `bookmarkYn`(AS-IS `addBookMarkYn`, 값 true/'true'면 노란 별). 숫자: `long`·`longCenter`·`longColor`·`longSecond(f,w,h,color)`·`double`·`doubleCenter`·`doubleColor`. 날짜: `date`(yyyy-MM-dd)·`dateMonth`·`dateTime`.
- 논리: `boolean`(체크박스, `{editable: true}`로 편집)·`booleanYn`(O/X)·`booleanYn2`(체크 표시)·`booleanIcon`(잠금). 묶음 헤더: `gb.group('제목', [열…])`(묶음 오른쪽 끝에 두 행을 관통하는 세로선이 자동으로 그려진다 — 마지막 열에 `gb-grp-last` 클래스 — 2행 걸친 열의 구분선과 같은 2px·rgb(240,240,240)·위아래 16px, 마지막 열에 `headerClass` 함수를 주면 선이 빠진다).
- `opts.editor`: `'text'|'largeText'|'number'|'date'|'select'`(`values`) — 있으면 파란 글씨 편집 열. 그 밖 opts는 `ColDef`에 덮어쓴다. 제목의 `<br>`은 두 줄 헤더.
- **조회창 트리거 열(AS-IS `LookupTriggerField`)**: 전용 헬퍼 없음 — `gb.text(f, w, '제목', { cellStyle:{color:'#1677ff'}, cellRenderer: p => <><AntButton type="text" size="small" icon={<SearchOutlined/>} onClick={e=>{e.stopPropagation(); open(p.data)}}/>{p.value}</> })`. 예: `Dcr30_Tab_LinkAdmin`·`Sys05_Page_UserRole`.
- **아이콘 열(AS-IS `addCell(ImageCell)`)**: `iconCell<Row>('edit'|'view'|'upload'|'down'|'add'|'delete'|'check'|'move'|'send'|'history', colId, 폭, '제목', row => …)`. 같은 제목이 둘 이상이면 `colId`를 다르게. 행 선택은 바꾸지 않는다.
- **값이 없으면 금지 표시인 아이콘 열(AS-IS `addDynamicCell(…, true)`, N23)**: `dynamicIconCell<Row>(kind, colId, 폭, '제목', row => …, row => 값이 있는가)` — 값이 있는 행만 아이콘 버튼, 없으면 `BanIcon`(회색 네모 안 금지 표시, AS-IS `GridBuilder.banIcon`). 예: `Tdm59_Tab_CheckAppr`(승인의견·보고의견), `Tdm52_TabPage_CheckManl`(점검).

### `useGridCrud<T>` (`hooks/useGridCrud.ts`) — 셀 편집 CRUD
```ts
const crud = useGridCrud<Row>({ idField:'xId', search, save, remove, newRow, firstEditField?, insertAt?, validate?, deleteConfirm?, reloadAfterSave?, onChanged? });
<CellEditGrid crud={crud} columnDefs={cols} />
<Button type="save" count={crud.changes} onClick={crud.saveRows}>저장</Button>
```
- 옵션: `search()→T[]`, `save(changedRows)→T[]`(요청과 같은 순서), `remove(ids)`, `newRow()`(기본값), `validate(changed, all)→메시지|undefined`, `deleteConfirm`(문구·함수·`false`=확인 없음), `reloadAfterSave`(저장 응답이 목록 전체거나 부수 효과가 있으면 true → 다시 조회), `onChanged`(저장·삭제 뒤 목록 밖 갱신).
- 반환: `gridRef, rows, loading, retrieve, addRow, addRows(inits, markDirty), updateRow(id, patch), replaceRow(id, row), removeRows(ids), clear, saveRows, deleteChecked, hasChanges(), getChanged(), changes, gridProps`.
- 규칙: 행 ID는 숫자, 추가 행은 임시 음수 ID(서버는 0 이하를 신규로 INSERT). `addRow`는 **변경으로 치지 않는다**(AS-IS `GridInsertRow`) — 셀을 고치거나 `addRows(…, true)`/`updateRow`로 넣어야 저장 대상. 변경 0건이면 `저장(0)`이 비활성(UX-03)이라 클릭할 수 없다. 변경 0건 저장은 서버를 부르지 않고 메시지도 없다.
- **행추가 위치(03 원칙 17)**: `addRow`·`addRows`는 기본으로 **항상 맨 아래**에 넣고, 새 행이 화면 밖이면 자동 스크롤한다(여러 행이면 마지막 행 기준). `insertAt`으로 바꾼다: `'last'`(기본) / `'first'`(맨 위) / `'afterSelected'`(선택한 행 아래, 없으면 포커스된 행, 그것도 없으면 맨 아래 — AS-IS `GridInsertRow` 기본 동작). `useGridCrud`를 쓰지 않고 행을 직접 넣는 화면도 `setRows(prev => [...prev, row])` 뒤에 `setTimeout`으로 `api.ensureIndexVisible(rowIndex)`(행은 `getRowNode(String(id))`)를 한다 — 예: `Sys15_Tab_Corp`.
- `editableCol(col)`: 편집 열 표시(파란 글씨). 읽기 전용 권한이면 `editable:false`.

### `useTreeGrid<T>({idField,parentField,depthField})` (`hooks/useTreeGrid.tsx`) — AS-IS `getTreeGrid`
서버가 **전위 순서 평평한 목록(depth)** 을 주면 접힌 조상 행을 필터로 숨긴다. `setRows(list)`, `treeCol(f,w,'제목')`, `expandAll/collapseAll/toggle(id)/expandAncestors(id)/expandDeep/ancestors(id)/descendants(id)`, `cascadeToggle(api,row,'useYn')`, `isTreeToggleClick(event)`. 트리는 `rowNumber={false}`.

## 2. 버튼·검색 (`components/button`, `components/search`)

- `<Button type="search|save|delete|register|close|select|change|…" count? onClick>` — 타입 32종(`button-types.md`). **antd `Button` 대신 이것만**. UX-01: `onClick`이 Promise를 돌려주면 끝날 때까지 스피너·중복 클릭 무시. UX-03: `count={crud.changes}` → `저장(n)`, 0건이면 비활성.
- `<SearchBar onSearch onReset? searchText? extra? loading? disabled?>` + `<SearchBar.Field label>` + `<SearchBar.Input>`(Enter=조회, 지우기 버튼 기본, **Ctrl+Delete = 내용 전체 비움**, `placeholder` 등 antd `Input` prop은 그대로 전달). 조회 버튼 문구는 `searchText`(예: `"찾기"`). 원본 툴바의 나머지 버튼(저장 등)은 `extra`. 값은 `useSearchParams(() => ({…}))`(`values`·`set`·`reset`). 초기화(UX-02)는 조건이 **3개 이상**이고 버튼을 넣을 **공간이 있을 때만**(줄바꿈되면 `onReset`을 뺀다) — 3개 미만이면 부품이 그리지 않는다.
- `<SearchPanel onSearch loading? searchText? disabled? fieldsWidth?>`(`components/search/SearchPanel.tsx`, R03) — **두 줄 이상 검색 영역**(원본 `buttonBar1`·`buttonBar2`). 왼쪽 입력 줄 `<SearchPanel.Row>`(안에 `<SearchPanel.Field label grow?>` — 라벨은 `일자 :`처럼 콜론·오른쪽 정렬, 입력이 남은 폭을 채우려면 `grow` + 입력 `style={{flex:1}}`)와 오른쪽 버튼 줄 `<SearchPanel.Actions>`를 같은 번호끼리 짝지어 격자로 놓는다(`fieldsWidth` 기본 520). **첫 Actions 줄 맨 앞에 [조회]가 자동**으로 들어가고(UX-01 중복 클릭 무시), `SearchPanel.Input` = `SearchBar.Input`(Enter 조회·지우기·Ctrl+Delete). 한 줄이면 SearchBar. 초기화 버튼(UX-02)은 없다. 예: `Chk03_Tab_DailyListConfirm`.
- `<ExpandCollapseButtons onExpandAll onCollapseAll textVisible? size? disabled? expandText? collapseText?>`(`components/button/ExpandCollapseButtons.tsx`, UX-09) — 모두펼치기·모두접기 아이콘 한 덩어리. 기본 아이콘만(툴팁), `textVisible`이면 문구도. `size`는 antd 크기. 펼침 상태는 화면이 들고 두 콜백에서 바꾼다.

### 4a. 편집창 EditModal (03 원칙 16, 사용자 결정 2026-10-27)

값을 입력하고 저장하는 모달(`*_Edit_*`)의 규격이다. 검색 후 선택하는 조회창(`LookupModal`, 위 절)과 구분한다. **공통 부품 파일은 아직 없고 규격을 따라 각 파일이 만든다** — 견본: `pages/chk/Chk02_Edit_DailyList.tsx`(복사본 `docs/page-style/SGP/`).
- 모달은 antd `Modal` + `maskClosable={false}`(편집 중 바깥 클릭으로 입력이 날아가지 않게), 닫기는 `onCancel={onClose}`.
- **머리말 아래 선**: `styles.header = { borderBottom: '1px solid #d9d9d9', paddingBottom: 12, marginBottom: 0 }`.
- **푸터 위 선**: `styles.footer = { borderTop: '1px solid #d9d9d9', paddingTop: 12, marginTop: 0 }`. 푸터는 가운데 정렬 [저장][닫기](`<Button type="save|close">`, 저장은 `loading`).
- **본문 위아래 간격 12**: 본문 래퍼 `padding: '12px 2px'`(머리말 선–첫 줄 = 마지막 줄–푸터 선), 줄 사이 `gap: 10`.
- **라벨 오른쪽 정렬**: 라벨은 고정 폭(AS-IS `setLabelWidth`, 예 105) + `textAlign: 'right'` + `paddingRight: 10`.
- 필수 검사·확인 문구는 AS-IS 그대로, 읽기 전용 열기(AS-IS `open()`)는 `readOnly` prop으로 [저장]을 숨기고 칸을 비활성한다.
- 새 편집창은 이 규격으로 만든다. 기존 `*_Edit_*`는 일괄 변경하지 않고 고칠 때 맞춘다.

**antd Tree 함정**: 가상 목록은 숨은 측정용 `.ant-tree-treenode`가 앞에 있어 화면 확인 스크립트에서는 `.ant-tree-node-content-wrapper`로 고른다. 타입은 `GetRef<typeof Tree>`(`rc-tree`의 `TreeRef`는 내보내지 않는다).

## 5. 그 밖

- `useLoginUser()`·`isSysAdmin(user)`(`hooks/useLoginUser.ts`): 화면에서 버튼을 막을 때만 쓴다 — 실제 권한은 서버가 검사한다.
- `useLocalStorage`, `useAppSetting`: 화면 설정 저장.
- 탭 헤더 hover 툴팁은 `MainFrame.tsx`의 `tabTooltip()`이 정한다(`onRenderTab`). 개발 중에는 클래스명(`config.classNm`). 개발이 끝나면 없애거나 화면번호+타이틀 등으로 바꿀지 정한 뒤 그 함수만 고친다.
- **화면 레이아웃 뼈대 (03 원칙 18)**: 바깥 `div`는 `height: '100%', padding: 20, boxSizing: 'border-box'`. 그 안의 분할(`Splitter`)·패널·테두리 박스는 `height: '100%'` + **테두리나 `padding`이 있으면 `boxSizing: 'border-box'`**(예: `Sys06_Tab_Menu`). 툴바 + 그리드는 `display: 'flex', flexDirection: 'column'`에 그리드 쪽을 `flex: 1, minHeight: 0`으로 둔다. `99%`·`calc(100% - 2px)` 같은 값으로 줄여 스크롤바를 피하지 않는다. 스크롤바가 2개 보이면 먼저 테두리 있는 `div`에 `boxSizing`이 빠졌는지 본다 — 같은 모양이 `Sys06_Tab_MenuView`·`Sys07_Tab_Company`·`Sys08_Tab_CodeKindAdmin/Client`·`Sys95_Tab_Manual/ManualAdmin`에도 있다.
- **테두리 박스 안쪽 여백 (사용자 결정 2026-10-20, F02 #1002)**: 테두리 박스 안에 검색줄(`SearchBar`)과 그리드를 넣을 때는 박스에 붙이지 말고 안쪽 래퍼에 `padding: 10`, 요소 사이 `gap: 8`(`display: 'flex', flexDirection: 'column'`)을 준다. 기준 모양은 `Dcr01_Tab_DcrWrite`의 center 박스(`border 1px #d9d9d9, padding 10, gap 8`). 공용 컴포넌트(`Apr01_Grid_DocList`)는 기본 모양을 두고 `padded` 옵션으로 켠다(예: `Dcr01_Tab_DcrUser` → `Dcr01_Tab_DcrManager` → `Apr01_Grid_DocList`). 공용 컴포넌트를 쓰는 다른 화면은 확인 뒤에 따로 켠다. `boxSizing: 'border-box'`는 03 원칙 18대로 함께 쓴다.
- **다른 메뉴 탭 열기 + 값 넘기기 (AS-IS `TempData` + `MenuOpener.openTabCallback`, G16→G17)**: `utils/tempData.ts`. 보내는 화면 `if (!openMenuByNo('1011')) { message.warning(…); return; } TempData.publish('apr.subList', 값)`, 받는 화면 `useEffect(() => TempData.subscribe<값>('apr.subList', v => …), [])`(해제 함수를 돌려준다). 탭이 열려 있으면 바로 전달·그 탭 선택, 새로 열리면 마운트 때 받는다 — 받는 화면은 자동 조회를 하는 화면이면 `subscribe`가 값을 받았는지 보고(`handled`) 기본 조회를 건너뛴다(`Apr01_Tab_SubList`). 화면번호는 `sys06_menu_no`이며 내 메뉴에 없으면 `false`. `MainFrame`이 `registerMenuOpener`로 한 번 등록한다.
- 화면 등록은 `pages/screens.ts`에 메뉴 키(클래스 이름)와 import 한 줄.
- API는 `api/<도메인>.ts`의 `xxxApi` 객체, 타입은 `types/<도메인>.ts`. 응답은 `res.data.data`.
