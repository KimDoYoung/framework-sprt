## 결정
- 레이아웃 여백은 11 §5 뼈대(바깥 20). 위/아래·좌우 분할은 AS-IS `BorderLayoutData` 분할 기본값(위 200, 왼쪽 400)을 antd `Splitter`로.
- 서버에서도 삭제 권한(박스 생성자·파일 등록자)과 파일의 회사 소속을 검사한다(원본은 화면만 검사하거나 아예 안 함). 결과는 원본과 같다.

## 제안 (사용자 승인 전 반영 안 함)
- **파일 삭제가 첨부를 지우지 못한다**(원본 결함): `FileDelete.deleteFileBox`가 fbx03 파일 ID(= 첨부의 parent id)를 첨부 행 ID·물리 파일 이름으로 써서 `sys10_file` 행과 서버 파일이 남는다. 첨부(`sys10_file.selectByParentId(fileId)`의 행 ID)로 행과 물리 파일을 지우면 디스크가 새지 않는다 — 하려면 사용자 승인.
- `fbx02_history.insert`의 `seq`가 `max(seq)`(+1 아님)라 같은 박스에서 값이 거의 같다. 현재 어느 화면도 `seq`를 쓰지 않아 영향 없음(원본 그대로).
- 박스 삭제가 그 박스의 `fbx03_file`·기록을 남긴다(원본 그대로) — 연쇄 삭제 제안.
- 등록 직후 날짜 편집기가 시각을 버리는지(`YYYY-MM-DD`만 보냄) — 서버는 `T00:00:00`을 붙여 저장한다. 수정하지 않은 행은 원래 시각이 유지된다.
