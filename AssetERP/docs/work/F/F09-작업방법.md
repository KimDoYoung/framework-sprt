## 공통 절차와 다른 점
- **PDF 만들기 생략**: 원본 `makePDF()`는 사내문서(`inoutCode == "20"`)이고 본문 파일이 아직 없는(`titleCount == 0`) 문서마다 서버가 전자결재 문서를 PDF(iText)로 만들어 `sys10_file`에 본문으로 저장한 뒤 zip을 내려준다. `Apr10_StampPDF7.makeDocument`(L699-1115, 결재선·인감·관련펀드·증빙 파일 등 SQL 15개+)는 전자결재 도메인의 PDF 생성기라 이번에 옮기지 않았다. 따라서 TOBE는 **이미 있는 본문·첨부파일만** zip에 담는다(사용자 확인 필요 — 작업기록 제안).
- 원본 `fileDownload()`/`makePDF()`의 `selectList` 끝 쉼표 분기(`i == size`)는 항상 거짓 → TOBE는 ID 배열.
- 원본은 zip 다운로드가 서블릿 POST라 `insertHistory`가 서버 응답과 무관하게 즉시 호출된다. TOBE는 zip 저장이 성공한 뒤 기록 API를 부른다(실패해도 사용자에게 알리지 않음 — 원본 콜백이 비어 있음).
