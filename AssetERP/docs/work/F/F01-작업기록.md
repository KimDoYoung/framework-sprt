## 결정 (사용자 확인 필요 없는 것)
- [신규문서 작성]의 `dcr.Dcr08_OftenUse.insertUpdate`(최근 사용 횟수 올리기)는 편집창을 열 때 같이 한다(F01-2). 1단계는 창이 없어 횟수만 올리지 않는다.
- 도움말 링크(작성요령)는 세부분류를 고르기 전에는 AS-IS도 `classDetailModel`이 비어 있어 아무 일이 없다 → 같게 둔다.
- AS-IS `refreshCode`는 위 단계 목록을 다시 읽고 빈 콤보의 `getCode()`를 `Long.parseLong`해 예외가 나는 경로가 있다 → TOBE는 고른 단계의 **아래 목록만** 읽는다(결과 같음).
- 안내 문구 3개는 1단계 임시(F01-2에서 지움).

## 제안 (사용자 승인 전 반영 안 함)
- **등록기간 끝 날짜(`closeDate`) 당일 문서**: SQL이 `apr01_reg_date BETWEEN #{startDate} AND #{closeDate}`(timestamp)라 끝 날짜가 날짜만이면 그날 00:00 이후 등록건은 빠진다. AS-IS 클라이언트가 어떻게 보내는지 확인 못 함 — 사원 계정으로 오늘 등록 문서가 조회되는지 일괄 시험 때 본다. 빠지면 `closeDate + 1일 미만`으로 고치자고 제안.
- `f_class_tree_nm_allpath`의 구분자가 이 DB에서 `/`라 AS-IS의 `" > "` 가정과 다르다(위 "다른 점"). 운영 DB 함수는 `" > "`일 수도 있다 — 확인되면 서버에서 ID를 주는 현재 방식 그대로 두면 둘 다 동작한다.
- 공통: `Dcr08`·`Apr50` 같은 "최근/북마크 목록" 조회창은 F02·F05·F06에도 나올 수 있으니 `components/lookup/`으로 옮길 후보(IM-02) — 그쪽 변환 때 판단.
