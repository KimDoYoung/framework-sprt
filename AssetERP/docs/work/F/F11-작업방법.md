- 레이아웃: 바깥 여백 20. 위(분할, 기본 높이 200): 테두리 박스 = SearchBar(제목 350 · [조회]) + extra [등록][저장][삭제] + 파일보관함 그리드. 아래: 왼쪽(기본 400) 테두리 박스 = SearchBar(문서분류 120 · [찾기]) + extra [+][-] + 트리, 오른쪽 파일 목록(그리드 + 아래 가운데 [파일업로드])
- 박스 그리드 `CellEditGrid`(체크박스 단일, 행번호): 등록일 100(date 편집) · 상태 80(select 편집, FbxBoxStatus) · 제목 550(text) · 비고 450(text) · 파일갯수 80(정수) · 기록 80(아이콘 history)
- 파일 그리드 `SingleGrid`(체크박스 단일): 등록일 100 · 문서분류 500 · 파일명 300 · 등록자 100(가운데) · 미리보기 80 · 파일받기 80 · 파일삭제 80(아이콘)
- 기록 창 `Fbx02_Popup_History`(850폭, `LookupModal`): 일자 150(일시) · 동작 80 · 내용 320 · 생성자 100 · 부서 100 + [닫기]

## 공통 절차와 다른 점
- `iconCell`에 `history`(기록 보기) 아이콘을 더했다(공통 부품 변경 → 11 §1·05 §5 등록).
- 삭제: 원본 `FileDelete.deleteFileBox`는 `sys10_file.selectByParentId(fileId)`로 찾은 첨부의 물리 파일을 `서버경로/fbx03 파일ID`로, 첨부 행을 `sys10_file.delete(fbx03 파일ID)`로 지우려 하지만 첨부 행 ID와 fbx03 파일 ID(parent id)가 서로 다른 값이라 둘 다 실제로는 아무것도 지우지 못한다(fbx03 행과 기록만 남는 결과). 원칙 4에 따라 이 결과 그대로 옮겼고 개선은 제안으로 남긴다.
- 문서분류 찾기(`search()`): 원본은 일치한 노드의 직접 부모만 펼친다. TOBE는 보이게 하려고 조상을 모두 펼친다(`ancestorKeys`, F02·E16 찾기와 같은 방식).
- 업로드의 `sys10_file.note`("파일보관함: boxId…")는 `SysFileService.upload`가 안 쓰는 열이라 채우지 않는다(어느 화면에도 안 나옴). 허용 형식 검사(Tika)는 파일 공통(B10)의 TOBE 추가 사항이 그대로 적용된다.
