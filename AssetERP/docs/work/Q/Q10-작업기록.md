## 제안 (03 원칙 5 — 사용자 승인 전에는 반영 안 함)
1. "신청(10)·승인(20)된 건은 수정·삭제 불가"는 원본이 클라이언트에서만 막는다 — API로 직접 부르면 승인된 수행내역도 고치고 지울 수 있다. 서버 저장·삭제에 같은 상태 가드를 두면 된다(Q11의 승인 처리와 함께 보는 편이 좋다).
2. 수행내역을 지워도 증빙(`est04_pf_file`)은 남는다(원본도 그렇다) — 지운 수행내역의 증빙이 고아 행으로 쌓인다. 삭제 때 같이 지우거나 FK 성격의 검사를 두는 것을 제안한다.
3. 저장·승인신청·신청취소가 성공해도 안내가 없다(원본 그대로). 사용자가 반영됐는지 폼의 승인상태로만 알 수 있다 — 짧은 성공 안내를 제안한다.
4. 증빙 그리드의 등록(파일 올리기) 뒤 [저장]을 누르지 않고 수행내역을 바꾸면 올린 파일이 `sys10_file`에만 남고 증빙 행은 없는 고아 파일이 된다(원본 그대로).
5. 수행번호 중복 검사(`checkNo`)는 같은 용역계약 안에서만 본다(서로 다른 용역계약의 같은 번호는 허용) — 원본 그대로이며 의도에 맞는지만 확인하면 된다.
