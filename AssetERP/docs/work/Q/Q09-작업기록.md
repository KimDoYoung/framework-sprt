## 제안 (03 원칙 5 — 사용자 승인 전에는 반영 안 함)
1. 태그 목록(Q08 제안 1 해소): `createMapping`이 채우는 키 8개(`용역수행회사`·`사업장명`·`사업장 주소지`·`수수료명`·`용역 수행기간`·`문의처`·`용역 수행계획`·`첨부파일`)가 `Com11`의 기본 목록과 같다 — `TempData`를 덮어써도 목록 내용이 같으므로 `com11Tags.ts`의 기본 목록으로 충분하다(순서만 GWT `HashMap` 순서라 다를 수 있음). Q12(`Est02_Tab_PfResultReport` L289)도 같은지는 그때 확인. 값 채우기(`createMapping`의 `mapping` 값)는 결재 연결 단계에서 필요하다.
2. "작성자 또는 작성자의 조직원만" 검사는 원본이 클라이언트에서만 한다 — API로 직접 부르면 같은 회사의 다른 조직 계약도 고치고 지울 수 있다. 서버에서도 검사하려면 `managerOrgId`와 로그인 조직을 비교하는 가드를 서비스에 두면 된다.
3. 조회 기준일의 초기값이 오늘이라 오늘 수행 중이 아닌 계약은 열자마자 안 보인다(원본 그대로) — 시험 DB의 계약이 모두 2025년이라 첫 화면은 비어 있다.
4. 첨부파일 열(`fileListHtml`·`fileListResultHtml`)은 결재 문서 양식 채우기용이라 조회 SQL에서 뺐다 — 결재 연결 단계에서 `selectByText`에 다시 더한다.
