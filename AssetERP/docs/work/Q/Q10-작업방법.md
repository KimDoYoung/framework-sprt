## 공통 절차와 다른 점
- **증빙 저장과 수행내역 저장을 한 요청·한 트랜잭션으로 묶었다.** 원본은 증빙(`GridUpdate`·`GridDeleteData`)을 먼저 저장해 두고 수행내역 저장에서 중복 번호 검사로 멈출 수 있어(증빙만 남는다) — TOBE는 중복이면 아무것도 저장하지 않는다. 검사·메시지·순서(필수 검사 → 증빙 형식 검사 → 저장)는 같다.
- 새 증빙 행의 ID는 [행 추가] 때 서버 새 번호를 받는다(원본 `GridInsertRow`의 `getSeq`와 같다 — 등록 아이콘이 이 ID를 `parentId`로 파일을 올린다). 저장 때 DB에 없으면 INSERT, 있으면 UPDATE.
- 파일을 올린 뒤 원본은 파일명 칸만 바꿔 `fileId`가 빈 채라 저장·다시 읽기 전에는 받기·보기가 안 된다 — TOBE는 올린 파일의 `fileId`도 함께 넣는다(받기·보기가 바로 되도록. 기능 추가가 아니라 같은 동작을 끝까지 되게 한 것).
- `deleteList`(원본은 필드라 다른 수행내역을 눌러도 남는다)는 수행내역을 바꿀 때 비운다. 서버는 `est04_pf_history_id`가 같은 증빙만 지운다.
- 삭제를 선택 없이 누르면 원본은 NPE — TOBE는 "삭제할 행을 선택하세요."(05 §8 공통 결정). 저장·승인신청·신청취소를 행 없이 누르면 "수행내역을 선택하세요."(원본은 NPE).
- 수행내역 저장이 성공해도 원본은 안내 없이 폼만 다시 채운다 — 그대로 안내를 두지 않았다.
