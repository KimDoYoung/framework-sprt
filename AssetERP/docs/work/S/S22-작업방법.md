## SQL 이식 (모두 `docs/as-is/src/pay/sql/` → `PayRetireMapper.xml`, `EmpTransInfoMapper.xml`, `PayRelateApprMapper.xml`)
- 계산은 DB 함수(`f_calc_leave_pay_retire`·`f_calc_4insure_retire`·`f_calc_income_tax_retire(_c)`·`f_calc_rem_leave_days`)가 한다 — 매퍼는 `SELECT 함수(…)`를 그대로 부른다. 인자는 모두 varchar라 `checkYn`은 `"true"`/`"false"`/null.
- `pay12_retire_insure.updateModel`·`pay14_retire_tax_item.updateModel`은 `WITH upsert AS (UPDATE … RETURNING *) INSERT … WHERE NOT EXISTS`를 그대로, 새 ID는 `f_create_seq()`.
- `pay13_retire_tax.updateAmt`의 `menuNum` 분기는 `<choose>`로 옮겼다(2·3·5·6·8·10).
- `pay15_retire_leave.getRetireLeave`의 `<=`는 `&lt;=`로.
- `selectRetireEmpList`는 TOBE의 `emp00` CTE(기준일 최신 발령)를 재사용한다: AS-IS 공통 뷰도 같은 `transDate`로 걸러지므로 결과가 같다(`compare` 15=15).

## 결정 (TOBE 추가·차이)
- **저장·삭제 대상 확인**: 4대보험 행·소득세 항목은 요청의 `monthId`(로그인 회사의 03 급여)에 속한 행만 저장·삭제한다(`countMonth(companyId, monthId, personId)`, `deleteInsure(monthId, id)`, `deleteTaxItem(monthId, id)`). 사원 ID는 로그인 회사 소속만(`countPerson`).
- **[문서분류지정] 노출**: AS-IS는 `LoginUser.getIsUserManager()`(로그인 때 `Sys05_UserRole.getAdminCheck`)일 때만 보인다. TOBE에는 그 정보가 없어 **늘 보인다**(S18과 같게). 제안: 로그인 정보에 UserManager 여부를 더한다.
- **삭제 실패 문구**: AS-IS `delete()`는 서버가 실패해도 "삭제가 완료되었습니다"를 띄운다. TOBE는 실패하면 서버 문구만 보이고 완료 문구는 띄우지 않는다(원본 버그, 제안).
- **성명 입력**: AS-IS `LookupTriggerField`(직접 입력 + 돋보기)를 S13과 같이 antd `Input` + 돋보기 아이콘으로, Enter·blur가 `onChange` 뒤의 `selectRetireEmpList`(있으면 첫 사원, 없으면 조회창)를 한다.
- **`Pay12_Lookup_RetireCreate`**: `analysis screen`이 "도달 불가(open() 호출처 없음)"로 표시하지만 `checkRetire`가 3인자 `open(personId, "insert", callback)`을 부르므로 만들었다.
- **`Pay31_Lookup_Insert1`**: `Pay10_TabPage_Retire.insertRow()`만 연다. 이 메서드는 어디서도 호출되지 않고(Tab_Retire의 [생성]은 `checkRetire`) 만들지 않았다(S17 `Pay10_Lookup_Insert`와 같은 이유). 대조표에 사유로 적는다.
