- TOBE에서 더한 서버 검사(원본은 화면에서만): 생성(03 아님)·삭제·항목 저장·소득세 재계산·근로시간은 서버도 `checkAppr`를 한다, 사원이 로그인 회사 소속인지, 항목 삭제는 급여 범위(`month_id`)까지 건다.
- 원본과 다르게 둔 것: `selectApprovedAnnual`의 금액 열은 `COALESCE(…, 0)`(원본은 NULL이면 NPE로 전체 실패), `getAdjustPay`가 NULL이면 0으로 보고 건너뛴다. 이미 있는 급여(생성 건너뜀)에 4대보험 연말정산을 시도하면 원본처럼 `monthId`가 NULL이라 금액이 0이 아닐 때 insert가 NOT NULL로 실패한다 — **그대로 이식**(아래 제안).
- yunhee 0.5.9 사용 메모: `port-sql --raw`는 `<insert id>`(`insertLatestInfo`)를 못 찾는다("<select id>를 찾을 수 없습니다") → `analysis sql … -o sql`로 보고 손으로 옮김. `analysis method Pay10_Month.insert --server`는 줄 범위를 243-682로 내 뒤 메서드(modelUpdate·deleteAll·update·delete)까지 본문에 붙인다(실제 insert는 243-614). `analysis method <클래스>`(메서드 없이)는 형식 오류. `analysis method`는 여러 메서드를 한 번에 줄 수 있어 서버 메서드 4개를 한 호출로 읽음.

## 제안 (03 원칙 5)
- (S16 구현) 이미 있는 급여에 4대보험 연말정산(221·231·241)을 시도할 때 `monthId`가 NULL이라 금액이 0이 아니면 insert가 실패해 생성 전체가 되돌려진다. 이미 만든 급여의 `monthId`를 쓰도록 고치면 이 경우에도 연말정산 항목이 붙는다. 승인 전에는 원본 그대로.
- `Pay10_Month.insert`의 사원마다 monthId 생성·소득세 계산이 DB 함수 호출 순서에 의존한다. 이식은 같은 순서로 하고 개선하지 않는다.
