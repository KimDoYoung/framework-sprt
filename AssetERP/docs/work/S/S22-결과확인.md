## 남은 문제
1. **시험 부작용(원래 값 확인 못 함)**: 4번 시험 중 `PUT pay/retire-taxes/amounts`(menuNum 2)에 `pyItemAmt: 0`을 보내 월 `202307251561752`(사원 29049)의 `pay13_py_income_deduct`가 NULL → 0으로 바뀌었고 `f_calc_income_tax_retire`가 전년도 금액을 다시 계산했다(`pay13_py_income_amt` 57,850,000). 곧바로 `pyItemAmt: null`로 되돌려 `py_income_deduct`는 NULL, 재계산된 `py_income_amt`도 NULL이 됐다(저장 전 값 `pyIncomeDeduct None`은 확인했으나 `pyIncomeAmt`는 시험 전에 읽지 않았다). 같은 입력으로 함수를 롤백 안에서 돌렸을 때 나머지 금액이 그대로였으므로 원래 값으로 돌아왔을 가능성이 높지만 **증명하지 못했다.** 사용자 확인 요청.
2. [상신]의 결재문서 작성과 [문서보기]는 다음 단계 — 지금은 검사 뒤 안내 메시지.
3. [문서분류지정] 노출 조건(UserManager)이 TOBE에 없어 늘 보인다.
4. 일반 사원 계정의 메뉴 노출·접근 미확인(8). 브라우저 시험(7·7-1)과 RD 리포트 `Pay10_Rd_Retire`·`Pay12_Rd_RetireInsure`·`Pay13_Rd_RetireTax` 렌더는 일괄 시험에서 확인한다.
5. [생성]·[삭제]·4대보험 [저장]·소득세 [저장] 실제 동작은 DB 함수가 실데이터를 바꾸므로 시험하지 않았다(롤백 SQL로 함수 실행만 확인).
