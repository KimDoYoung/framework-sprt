## 결정·TOBE 추가 (모두 서버 쪽 보강, 화면 동작은 원본 그대로)
- 저장: 서버가 monthId로 급여 행(회사·지급일·사원)을 다시 읽는다 — 클라이언트의 personId·payDate를 믿지 않는다. [저장]의 `checkAppr`도 서버가 한다(구분·지급일 조합마다 1번).
- 금액 null은 `400 금액을 입력해주세요`(원본은 DB 오류). 일괄생성 항목은 `pay20_item`에 있는 구분·코드 쌍만.
- **일괄생성은 중복 검사가 없다(원본 그대로)** — 같은 항목을 두 번 누르면 항목이 두 줄이 된다. 시험 월에서 190이 이미 복사돼 있어 두 줄이 된 것을 확인했다. **제안**: 이미 같은 코드가 있는 급여에는 건너뛰기(03 원칙 5에 따라 승인 전에는 반영하지 않음).
- `sys99_print.deleteByPersonId`는 원본이 `window_class_nm LIKE`였으나 고정 클래스 이름이라 `=`로 옮겼다(S14와 같음).
