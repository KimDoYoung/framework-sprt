- 바깥 `div`(여백 20, border-box), 위/아래 2단(`Splitter` 세로): 위 = 툴바(`조회기간: [시작]~[종료] [☑재고없음 제외] [조회][등록][저장][삭제]`) + `CellEditGrid`(10열: 구매일자·구매품목·구매수량·구입금액·인원·인당 경제적가치·재고량·담당자·상신상태·결재요청), 아래 = `Biz01_TabPage_List`(툴바 "이익제공내역: [등록][저장][삭제][상대처 관리 바로가기]" + 체크 다중 `CellEditGrid` 6열).
- 위 그리드는 체크박스 없는 셀 편집(`setChecked` 없음 → `rowSelection={{ mode: 'singleRow', checkboxes: false }}`). 아래 그리드는 체크박스 다중. 아래 `Biz01_TabPage_List`는 `crud` 훅 대신 상위가 `buyModel`·`callback`을 넘기는 부품 모양(원본 `retrieve(selectedItem, callback)`)이라 `forwardRef` 핸들 `retrieve(buy, callback)`을 둔다(11 `Sys13_TabPage_Code`와 같은 방식).

## 공통 절차와 다른 점
- **재고 조건(`leftYn`)**: 체크 "재고없음 제외"가 켜져 있으면 서버가 재고 있는 건만 준다 — 원본 `<when>` 가지를 그대로 옮긴다.
- **아래 목록은 상신상태가 "완료"인 구매내역에만 켜진다**(원본 그대로). 상신이 아직 없는 TOBE에서는 상신 흐름이 끝나기 전까지 아래 목록을 쓰려면 이미 완료된 건(kfstest 28000 데이터)이 필요하다. 결재요청 이후는 다음 단계.
- **제공금액**: 원본 `getBuyAmt()/getBuyQty()`는 `Long` 나눗셈(버림)이다. 구매수량 0이면 JS는 0으로 나눠 예외가 나는데 원본도 같은 결과(저장 불가)라 서버에서 막지 않고 화면에서 구매수량이 없으면 제공금액을 비운다 — 작업기록에 확인 필요로 남긴다.
- **상대처(거래상대방) 회사명/성명**은 `Crm09_Lookup_SelectSingle`로만 채울 수 있어 **다음 단계 전까지 이 두 칸은 새 값을 넣을 수 없다**(기존 값은 표시). 원본과 다른 임시 입력 칸을 만들지 않는다(03 원칙 4).
