## SQL 이식
- `selectEmpICT` → `BmtEmpIctMapper.xml#selectEmpIct`. 조회와 출력 적재(`insertPrint`)가 같은 `<sql id="empIctQuery">`를 쓴다(AS-IS도 같은 SQL을 서버에서 다시 돌린다).
- **원문과 다른 점(03 원칙 4 예외)**: 원본은 `t.*`에 `bmt12_pc_history.*`를 그대로 넣는다. 이 안에 행번호 별칭 `bmt12_pc_history_id`와 같은 이름의 열이 있어 TOBE 매퍼에서 바깥 SELECT가 `column reference … is ambiguous`로 실패했다(`sql-check`). 그리드가 쓰는 두 열(`bmt12_internal_ip`, `bmt12_etc`)만 고른다. 결과 열·행은 같다(`compare` 7=7).
- 출력 적재 열: long01=행번호 ID, string01 사원명, text01 메신저, text02 웹사이트, string02 IP, string03 PC명, text03 세부사양, text04 기타(AS-IS `insertRdEmplct` L3957-3999). 원본의 `sys99_print.insert`는 모델 전체 열을 넣지만 나머지는 NULL이라 쓰는 열만 넣었다.
- 정렬은 `ROW_NUMBER() OVER (ORDER BY … COLLATE "ko_KR.utf8")`만 있고 바깥 ORDER BY는 없다(원본 그대로).
