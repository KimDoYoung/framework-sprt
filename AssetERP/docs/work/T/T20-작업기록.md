## 기록
- 2026-10-29 T20 단독 세션(T19 뒤 이어서, 같은 대화). 클래스 1, 새 API 2(`GET`·`POST rd-print`), 새 매퍼 1.
- 출력 적재는 기존 `EmpYearLeave` 방식(`selectNextId` → `deletePrint` → `insertPrint`)을 따랐다(참고만, 복사 아님 — 코드는 이 화면 SQL에 맞게 새로 썼다).
- SQL 한 곳을 원문과 다르게 고쳤다(`bmt12_pc_history.*` → 쓰는 두 열). 사유와 결과는 `T20-작업방법.md` "SQL 이식".
- 실제 `POST rd-print`는 호출하지 않았다(sys99_print 시험 행을 지울 방법이 없음, 03 원칙 2). 적재 SQL은 `mapper-run --rollback`으로, RD 호출은 시뮬레이터로 확인했다. 시뮬레이터 주소 확인에는 `curl`을 썼다(05 §7 "yunhee로 못 하는 것"에 허용된 방식).
- 도구 사용: 중간에 `cat`·`grep -A` 훅 차단이 3번 있었다(TOBE 소스를 읽으려던 실수). 이후 `outline`·`analysis tobe` + `Read(offset/limit)`로 바꿨다.

## 제안 (사용자 승인 전 미반영)
- 출력(`rd-print`) 시험 행을 지울 수 있게 `yunhee sql`에 `--rollback`이 걸린 쓰기 호출용 API 시험(요청 전체를 트랜잭션으로 감싸고 롤백) 지원.
- 원본 SQL의 `bmt12_pc_history.*`는 같은 이름 열이 두 번 나온다(행번호 별칭 `bmt12_pc_history_id`). 원본에서 정리하면 좋다(원본 변경은 우리 몫이 아님).

## 비용
- 배포 1회, `tsc` 1회(성공), 컴파일 2회, `sql-check` 전체 2회(1회 TOBE 매퍼 ❌ → 수정). 훅 차단 3회. 실패 0건(빌드·배포 기준).
