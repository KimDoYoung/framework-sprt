## 결정
- 실제 사용자에게 영향을 주는 동작(알림·강제 로그아웃)은 어떤 확인에서도 서버로 보내지 않는다: 화면은 `route` 가짜 응답, 서버 동작은 가짜 `PresenceService`·`PushService`·`AuthService`를 쓰는 DB 테스트, API는 400·403·오프라인 대상(영향 없음)만.
- 알림 제목 "알림" 고정, 접속자가 없으면 빈 목록(작업방법 "다른 점").

## 제안 (사용자 승인 전에는 반영하지 않음)
- "전송 및 로그아웃"은 이름과 확인 문구("5분뒤 자동 로그아웃됩니다")와 달리 **5분 뒤에 실제로 로그아웃시키는 코드가 원본에 없다** — 알림을 보내고 화면에 남은 시간만 센다. 의도가 자동 로그아웃이면 서버에서 5분 뒤 `forceLogout`을 예약하는 기능을 더해야 한다(사용자 결정).
- "전체로그아웃"은 요청한 관리자 자신과 모든 고객사 사용자를 한꺼번에 로그아웃시킨다(원본 동작). 고객사 콤보로 대상을 좁히는 기능은 원본에 없다.
- 이 DB·환경에서는 사원 계정의 비밀번호를 알 수 없어(시험용 1111이 아님) 사원 접속 → 알림 수신 → 강제 로그아웃의 실제 왕복은 시험하지 못했다.
