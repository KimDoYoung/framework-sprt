## 결정
- 요청의 personId가 로그인 회사 사원인지 서버가 검사한다(다른 회사 사원이면 `DATA_NOT_FOUND`) — 05 §6 회사 조건 규칙.
- 잠금해제 API는 `lockYn = false`만 한다(원본 화면이 false만 보냄).
- 원본에는 메뉴 권한 외의 역할 검사가 없어 TOBE도 로그인 + 로그인 회사 범위만 본다(관리자 역할 검사를 새로 더하지 않음 — 제안 참고).

## 제안 (사용자 승인 전에는 반영하지 않음)
- 비밀번호 초기화·잠금해제 API에 관리자 역할 검사(`ROLE_ADMIN`)를 더할지: 원본처럼 메뉴 권한만 믿으면 그 메뉴를 가진 일반 사원 계정도 같은 회사 누구의 비밀번호든 비울 수 있다.
- 초기화는 비밀번호를 NULL로 만들 뿐이라(원본 그대로) 로그인 쪽이 NULL을 어떻게 다루는지(첫 로그인 때 새 비밀번호 설정 등)는 이 화면 범위 밖이다 — 로그인 기반(B04)에서 확인 필요.
- 이 DB에는 잠긴 사원이 한 명도 없어 상태(잠금 아이콘) 칸을 실제 데이터로는 못 봤다.
