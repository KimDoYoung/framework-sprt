## 결정
- 본 화면 API는 AS-IS 서버 메서드 단위로 만들되 `FltTrController`(사전신고)에 더하지 않고 `FltRealTrController`로 나눴다(컨트롤러·서비스가 이미 길다). 매퍼 XML은 같은 AS-IS 파일(`flt10_tr.xml`)이라 `FltTrMapper`에 이어 붙였다.
- 색인이 "도달 불가"로 표시한 E3(`toggleGroup`)은 라디오가 툴바에 붙어 있어 도달 가능 — 구현했다(yunhee 오탐으로 보인다. 아래 "yunhee 제안").
- 상신 문서 폐기(`deleteApprList`)는 원본이 클라이언트가 부르는 별도 서비스라 `DELETE /flt/real-trs/apprs`로 분리해 같은 순서(저장/삭제 뒤)로 부른다. 본인이 상신한 문서(`apr01_reg_emp_id`)만 폐기하도록 조건을 더했다(05 §6 회사 조건과 같은 보강).
- 삭제 대상에 사전승인(expectTrAmt)이 있는지는 원본이 클라이언트 값으로 가르지만(`deleteUpdate`), 서버는 DB 값으로 같은 판단을 한다(`updateTrData`에 `expect_tr_amt IS NOT NULL` 조건).
- `사전신고 Copy`는 `iconCell('move')`, 상세보기는 `iconCell('view')`.

## 제안 (사용자 승인 전 반영 안 함)
- `sys.Sys12_Calendar.selectByDay`(실거래일 영업일 점검)의 SQL에 회사 조건이 없다(`sys12_company_id != 0 AND sys01_use_yn = 'true' ORDER BY sys01_company_id`, 첫 행 사용). 파라미터 `companyId`를 넘기지만 쓰이지 않는다 → 회사별 달력이 다르면 다른 회사의 영업일로 판정된다. 원칙 4대로 그대로 옮겼다.
- `checkInvestLimit`(저장 때 한도 확인)는 `investAmtOverCheckYn`을 보지 않고 항상 비교한다(조회·작성 때의 `getInvestLimit`은 본다) — 그대로 옮겼다.
- yunhee 제안: `analysis screen --section events`가 툴바에 붙은 `Radio`를 `toggleGroup` 경유로 "도달 불가"라고 표시한다. `analysis screen --section layout`의 "읽기 전용·비활성" 목록이 `setEnableFalse()` 안의 호출을 포함한다(선언 때 비활성이 아님). `mapper-run -p myAccountYn=false`는 문자열 `'false'`로 가서 MyBatis `<if test="myAccountYn">`가 참이 된다(08 H06~H08의 같은 함정) — 파라미터를 생략하면 null.
