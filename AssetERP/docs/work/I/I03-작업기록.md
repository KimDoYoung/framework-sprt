## 결정
- API는 `FltTrController` 하나(`/api/v1/flt/trs`)에 모았다. AS-IS 서버 클래스 `Flt10_Tr`을 I04~I08이 같이 쓰고, 조회창 둘도 `trType`만 다르다. 계좌 그리드·종목유형 콤보도 이 컨트롤러(`/trs/accounts`·`/trs/item-types`)에 둬서 기존 I02·E08 컨트롤러를 건드리지 않았다.
- 상태 변경(`PUT /trs/status`)은 승인신청 `10`과 신청취소(null)만 받는다. 원본 SQL의 승인(`20`) 가지는 준감인 화면(J) 몫이라 옮기지 않았다.
- 수정·삭제·상태·미체결 SQL에 `flt10_company_id`·`flt10_person_id` 조건을 더했다(원본은 trId만, 05 §6 본인 데이터).
- 서버 오늘(`today`)과 회사의 사전신고 소급 설정(`sys01_flt_only_curr_yn`)은 `GET /trs/check` 응답에 함께 낸다(원본 `LoginUser.getToday()`·`getCompanyModel()`).
- `useGridCrud`의 `validate` 대신 화면 `preUpdate()`에서 검사한 뒤 `crud.saveRows()`를 부른다(원본이 한도 초과 확인창을 사이에 끼우기 때문). 저장 완료 문구는 공통 부품의 "n건 저장되었습니다."를 따른다(05 §8).
- 종목명 칸은 글자 입력 + Enter(확정) 시 창 열기 + 돋보기로 했다(원본 `LookupTriggerField`).
- 원본 `accountGrid.RowClick`의 YES는 `previousModel`을 바꾸지 않는다(NO에서 되돌릴 대상이 마지막 자동 선택 계좌) — 그대로 옮겼다.
- 원본 check()는 두 서비스 호출·retrieveLimit·retrieveAccount가 병렬이라 버튼 상태가 늦게 끝난 쪽에 따른다. TOBE는 check → 한도 → 계좌 순으로 직렬화했다(결과는 원본의 일반적인 순서와 같다).
