## 의존 (사용자 결정 대기)
- **주석 저장**: 원본은 클라이언트가 `comment on table X is '…'` 문자열을 만들어 `sp_DDLRun`에 넘긴다. 프로시저를 만들 수 없으므로(원칙 1) 서버가 `COMMENT ON … IS`를 직접 실행하는 방법이 있으나(식별자 검증·따옴표 이스케이프 필요) 원칙 4·5 예외 승인이 필요하다.
- **소스 생성 4종**: `sp_Java*` 본문이 없어 출력 형식을 알 수 없다. 원본 DB(운영) 쪽에서 프로시저 정의를 받거나, 형식을 새로 정해야 한다.
- **Table Print**: 서버 PDF `Dbm02_ColCommentsPDF`(iText) — C07의 PDF 의존과 같이 PDF 도구를 정할 때. **Report Print**: dcr 변환 때.

## 제안 (사용자 승인 전 반영 안 함)
- **원본 보안 결함**: `Dbm00_DDLRun.callByDDLRun(para)`는 클라이언트가 보낸 문자열을 `sp_DDLRun`(DDL 실행 프로시저)에 그대로 넘기고, `Dbm01_TabComments.update`·`Dbm02_ColComments.update`도 테이블·컬럼 이름과 주석을 문자열로 이어 붙인다 — 주석에 `'`를 넣으면 SQL이 깨지고, 서비스를 직접 부르면 임의 DDL이 돈다. TOBE에는 옮기지 않았다. 나중에 저장을 만들 때는 이름 검증 + 주석 이스케이프가 필요하다.
- 원본 `ColCommentsPDF`의 `tableName`이 선택 전 null이면 소스 생성 버튼이 `tableName=null`로 서버를 부른다. TOBE는 테이블 선택 전에는 아무것도 하지 않는다(안내 문구는 원본에 없어 넣지 않음).
- `analysis ui`가 컴포넌트 합계에서 `E0`를 주석이 없으면 미구현으로 센다 → 각 클래스에 `// [E0]` 주석을 달았다.
- UX보강 제안 없음.
