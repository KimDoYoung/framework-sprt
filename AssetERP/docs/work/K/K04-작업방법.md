## 공통 절차와 다른 점
- **출력/다운로드**: RD 리포트(`Ics10_Rd_Checklist`) 대신 한 시트 xlsx (K01과 같은 방식).
- **Sch02_Page_Share의 삭제**: 원본은 확인한 뒤 그리드에서만 빼고 [저장]에서 지운다 — 같게 했다. `useGridCrud`의 `deleteChecked`(바로 삭제)를 쓰지 않고 `removeRows` + 삭제 목록을 따로 든다. 저장(n) 대신 항상 켜진 [저장](삭제만 있어도 저장해야 하므로).
- **Sch22 [확인]**: 아직 저장 안 한 새 행(임시 음수 id)을 고르면 "저장 후 선택해주세요."를 낸다. 원본은 미리 받은 id(GridInsertRow)를 그대로 넘겨 DB에 없는 그룹을 ics11이 가리킬 수 있다 — 데이터 보호용 방어이며 작업기록에 제안으로 남긴다.
- 원본 로직상 고객사가 만든 체크리스트를 [사용여부설정]에서 미사용으로 저장하면 `ics10_use_yn`도 false가 되어, 조회 SQL(`ics10_use_yn = 'true'`)에서 둘 다 빠지므로 사용여부설정 창에서 다시 켤 수 없다. 원본 SQL 그대로라 고치지 않았다(작업기록 제안).
- 대분류 id(`checkLClassId`)를 응답에 더했다: 수정 창이 대분류 콤보를 채우려면 필요(관리자용 E04 응답과 같은 필드).
