## changeStep 이식 규칙 (AprApprNewService.addStampSteps)
- 기준 줄 수 n = 인감을 넣기 전 결재선(기본 결재선) 줄 수. 새 줄 순번 `%03d`(n + 3)이 세 줄 모두 같다(원본은 넣기 전에 정함, 이상한점 #35).
- 인감(40): `apr10_step_use_yn = 'true'`이고 인감책임자(`apr10_emp_id`)의 오늘 발령이 있을 때. 이미 결재선에 있어도 넣는다. 이름은 대결자가 있고 `stamp_yn`이면 `<b>부)</b>` + 부책임자(`apr10_second_emp_id`), 아니면 `<b>정)</b>` + 책임자. 항상 잠금.
- 준법감시인(합의 20, 직급 120)·컴플라이언스(참조 30, 직급 121): 인감책임자와 같은 사람이거나 기본 결재선에 이미 있으면 넣지 않는다. 이름은 대결자가 있으면 20은 대결/본결 두 줄, 30은 대결자만. 잠금은 회사 설정.
- 인감책임자가 비면 아무 줄도 넣지 않는다(원본 NullPointerException, #36).

## 공통 절차와 다른 점
- 원본은 준법감시인·컴플라이언스·인감 줄이 응답이 오는 대로 `GridInsertRow`로 들어간다. TOBE는 서버가 한 번에 순서(인감 → 준법감시인 → 컴플라이언스)를 정해 돌려주고 03 원칙 17대로 맨 아래에 붙는다.
- 트리거 칸은 `LookupTriggerField` 대신 읽기 전용(인감종류) / 입력 가능(대표회사, V07에서 이미 직접 입력 가능) `Input` + 오른쪽 돋보기(`addonAfter`)로 연다.
- `resetApprStep`이 연관문서 그리드를 비우는 것도 그대로 따른다(이상한점 #34).
- 새 문서의 결재선은 다시 그릴 때(`key` 바뀜) 쓰는 `seed`도 새 결재선으로 바꿔 둔다.
