## SQL 이식 (03 원칙 4)
`dcr00_doc_list.selectByText`는 연관펀드 UNION·권한(dcr03/dcr04/결재선/공람)·분류 아래 조회·검색 조건·정렬을 그대로 옮기고 `SELECT t.*`는 창이 쓰는 열로 줄였다. `${orgId}`·`${empId}`는 `#{}`로, 분류 조건은 `common.dcr_tree_down`을 푼 것(typeCode '%'). 펀드 열(`fundDisplayName`)은 AS-IS 모델 getter 규칙(코드 없으면 이름 또는 "-", 이름 없으면 "(코드)", 둘 다면 "(코드) 이름")을 SQL `CASE`로 옮겼다. `authYn`은 이 SQL에서 늘 true다. `sys10_file.selectByParentId` 정렬·`updateOthers`·`updateParentId`(note 가지)·`sys61_file_del.insert/selectByParentId`·`dcr05_doc_type.selectByClassTreeId/selectByName`은 그대로.
- 삭제는 파일을 지우지 않는다: 삭제 내역(`sys61_file_del`)을 만들고 `sys10_file.sys10_parent_id`를 그 내역 ID로 옮기며 비고에 `[삭제 empId:사원]`을 덧붙인다(`Sys61_FileDel.insert`). 그래서 삭제된 파일은 내역 창에서 보기·받기가 된다.
