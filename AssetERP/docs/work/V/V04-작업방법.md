## SQL 이식 (03 원칙 4)
`apr41_open_history.selectByApprIdPaging`·`Total`, `apr42_comment.selectByApprId`, `emp00_trans_info.selectByList`는 `SELECT *`를 그리드가 쓰는 열로 줄인 것 말고 조건·정렬·함수 호출 그대로. `Apr42_Comment.modelUpdate`/`delete`(UpdateDataModel)은 `yunhee port-save apr42_comment`로 열을 정하고 등록일·시간은 서버 시각(`f_sysdate()`, `TO_CHAR(…,'HH24:MI:SS')`). 매퍼는 `AprApprCommentMapper.xml`·`SmsSendListMapper.xml` — `sql-check` ✅.

## 공통 절차와 다른 점
- 댓글 그리드의 행 펼침(GridExpandBuilder): 행번호·펼침 단추 칸 없이, 모든 줄이 이미 펼쳐진 모양(머리 아래에 글)으로 그렸다. 행 높이는 글 길이에 따라 자동(`autoHeight`).
- 서버가 휴대폰 번호를 읽는다 — AS-IS는 화면이 들고 온 사원 모델의 번호를 보냈다. 번호 없는 사원은 건너뛴다(AS-IS는 서버 오류, 이상한점 #26). 같은 사원이 두 행이면 두 번 보낸다(원본 그대로).
- 문자발송에 [추가]로 넣은 사원은 조직 칸이 비어 있다(원본 그대로, 이상한점 #27). 03 원칙 17: 사원은 맨 아래에 넣는다.
- 첨부파일 창은 `Ics35_Grid_FileList`와 같은 모양이라 복사했다(세 번째면 부품 후보). 삭제 흐름은 `Tdm43_Tab_RelateFormFileUpload`와 같은 `checkFileDeleteResult` 3가지 결과.
- 댓글을 지워도 그 댓글에 올린 첨부파일(`sys10_file`)은 남는다(원본 그대로 — `Apr42_Comment.delete`는 댓글 행만 지운다).
