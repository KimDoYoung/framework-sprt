## 공통 절차와 다른 점
- **행은 서버가 ID로 다시 읽는다**(V22·V26과 같은 원칙). A63은 `ids`를 호출 화면이 정한 순서(발생일자 오름차순)로 보내고, 시행일자·계정과목·발생부서는 "고른 첫 행"(`refId`)에서 얻는다. 선택 순서는 TOBE 그리드가 행 순서만 줘서 `getSelectedRows()` 첫째를 쓴다(이상한점 #56).
- **첨부 연결 시점**: AS-IS는 결재창을 열 때 바로 `sys11_relate_file`에 넣는다(취소해도 남는 쓰레기 행). TOBE는 문서 ID가 확정돼 `updateExpenseApprId`가 불릴 때 넣고, 같은 문서에 이미 연결된 파일은 다시 넣지 않는다(#58).
- A64의 출금계좌별 묶음은 GWT `HashMap`이라 순서가 정해져 있지 않다 → 처음 나온 순서(`LinkedHashMap`)로 한다(#57).
- 금액이 null이면 AS-IS는 NPE(Long 언박싱) → TOBE는 0으로 더한다(#59).
- A65 `%` 폭(`colspan*4.4`)은 GWT 숫자 문자열(`88`, `30.800000000000004`)과 같게 정수일 때 `.0`을 뗀다.
- 호출 화면의 `isManager`(A63 단건 승인자 줄)는 TOBE에 있는 `Pay50_Tab_ExpenseManager`만 있으므로 항상 true (`Pay50_Tab_Expense` 일반 사용자 화면이 변환되면 인자를 추가).
- `Seed`: A63·A64·A69 = 제목 편집 가능·저장 숨김, A63 시행일자 = 발생일자·A64 = 오늘·A69 = 청구일자.
