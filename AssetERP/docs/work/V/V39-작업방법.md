## API
- `POST emp/un-leaves/appr`, `POST emp/un-leaves/month/appr` — 본문 `{ stdYear, classTreeId, ids[] }` → 만든 결재문서 수.
- **AS-IS는 행 모델 전체를 보냈지만 TOBE는 ID만 보낸다.** 서버가 그리드와 같은 조회 SQL 조각(`yearQuery`·`monthQuery`)에 `emp21_un_leave_id IN (…)`을 걸어 다시 읽는다(`selectNoticeYear/Month`, 열은 `UnLeaveNoticeRow`). 순서는 요청한 ID 순서(= 그리드 선택 순서)이고, 연차 지정통보서의 영업일 순환(`workDayIndex`)이 사원 순서에 기대므로 순서가 중요하다.

## 서버 흐름 (`EmpUnLeaveApprService`)
**insertAppr (연차 탭, L159-385)**: 첫 행 구분이 01이면 기준일 = 오늘+10일·`monthDel`=6, 02면 `monthDel`=2. `startDate` = (기준일 해의 회사 휴가결산월 1일) − monthDel개월, `closeDate` = startDate + monthDel개월의 날짜를 **startDate 달의 말일 숫자**로 맞춤. 영업일 = `sys12_calendar` 중 `working_yn='true'`. 행마다: 01 → 통지서(`html1_01`), 그 밖 → 지정통보서(`html1_02`: 영업일을 `ceil(remainDays)`개 순환 배정 → 특별휴가(`emp22_etc_leave.getLeaveDate`)와 겹침·내일 이전 날짜 제외 → 모자라면 뒤 영업일로 채움 → 월별 표, 소수 일수는 첫 달에서 뺌). 결재문서 `apr01_appr.insertApproval`(상태 30·내외부 20·등록일/시행일 오늘 0시) + 결재선 `apr04_appr_step`(00 상신·10·승인 20·오늘 / 대상자≠상신자이면 30 참조·20) + `emp21_un_leave.updateApprId`.

**insertAppr2 (월차 탭, L387-601)**: 사원마다 구분 03(기준일 +10일)·05(+5일) → 통지서(`html2_01`), 04·06 → 지정통보서(`html2_02`). 기간은 사원 행의 생성일 ~ 휴가사용대상 종료일. 영업일은 앞에서부터 `remainDays`개(순환 없음). 특별휴가 종료일은 `closeDate`를 쓴다(연차 탭은 시작일을 씀 — 이상한점 #96).
