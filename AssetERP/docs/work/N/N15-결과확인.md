## 남은 문제
- (2026-10-24 N16 분석 중 정정) 조회창 [전체]가 `callback.execute(null)`을 부르는 것을 닫기로 잘못 구현했던 것을 `onAll`로 고쳤다(tsc 통과). 브라우저에서 [전체] → 직책/부서가 비는지는 일괄 시험에서 본다.
- 항목 7·7-1 브라우저 시험은 일괄 실행에서. 돋보기 두 개(직책 → 부서 비움, 부서), 관리의무생성 확인 흐름(작성내역 있음 → 점검항목 확인 → 삭제 후 재생성), 매뉴얼 작성·복제 버튼의 관리자 노출은 브라우저에서만 볼 수 있어 아직 못 봤다.
- `POST manuals`(매뉴얼 작성·복제)의 실제 쓰기는 DB 함수가 8개 테이블을 바꾸므로 API로 시험하지 않았다. 함수 호출 자체는 rollback SQL로만 확인.
