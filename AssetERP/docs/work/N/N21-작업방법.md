## 공통 절차와 다른 점
- 사원찾기 조회창은 `Emp00_Lookup_SelectSingle`과 다른 SQL(`selectByTdmYn`)·열(조직·직책·사번·성명·발령일, 사원 ID가 행 키)이라 새 부품이다. 같은 이유로 N22(책무이행점검)도 쓸 수 있다.
- `Tdm58_Lookup_ChckApprStep`는 `useGridCrud`를 쓰지 않는다: 원본이 변경이 없어도 저장(전체 행의 순서 다시 매기기)을 누를 수 있고 위로·아래로가 목록 순서를 바꾸기 때문이다. 그래서 UX-03(저장(n))·UX-07(변경 표시)은 넣지 않았다.
- 마감·확정 판단(`fixYn` 등)은 위 그리드 행 값으로 TOBE도 같게 쓴다. 서버는 확정·승인요청 때 `chckOrgId`로 행을 다시 읽어 회사를 검사하고(`ACCESS_DENIED`), 승인요청 중간 실패는 전체 롤백한다.
