## 원본과 다른 점 / 결정 (03 원칙 4·5)
- 파일 삭제: AS-IS `deleteByRoleDigmId`는 실제 파일(`File.delete()`)과 `tdm33` 행만 지우고 `sys10_file` 행은 남긴다. TOBE는 기존 파일 삭제 서비스(`SysFileService.delete`)를 써서 `sys10_file` 행도 지운다 → 아래 "제안"의 고아 행 항목과 같은 성격이라 **승인 대기**(되돌리려면 `deleteFileInfo`에서 `selectAttachIdByFileType` 반복만 빼고 물리 삭제만 하면 됨).
- 새 행(저장 전)의 파일 올리기: AS-IS는 임시 ID로 서버를 불러 오류. TOBE는 "저장 후 진행가능합니다"로 막는다(N12 책무기술서 보기와 같은 안내).
- 조회 SQL의 `sys10_file` LEFT JOIN으로 시스템 생성 파일이 둘 이상이면 같은 책무체계도가 여러 행으로 온다(AS-IS 그대로, 현재 데이터는 없음). 행 ID(`roleDigmId`)가 겹치면 `useGridCrud`가 헷갈리므로 화면이 처음 행만 쓴다(N12 교훈). 제안: N12처럼 JOIN을 빼면 보정이 필요 없다.
- `exceptionList`(`cnclApprDate`·`submitDate`·`endYn`만 바뀌면 저장 검사 건너뜀)는 이 화면 그리드에 그 열이 없어 옮기지 않았다.

## 제안 (승인 대기)
- **책무체계도 삭제 시 파일정보·첨부 정리**: `Tdm32_RoleDigm.delete`는 `tdm32_role_digm`만 지워 `tdm33_role_digm_file`·`sys10_file` 행이 고아로 남는다(AS-IS도 같음. 다음 조회의 `fileCheck`는 첨부 없는 `tdm33` 행만 지운다). N12는 같은 문제를 승인받아 고쳤다(`deleteFilesByParentIds`). 이 화면에도 적용할지.
