## 결정 (사용자 확인 필요)
- **PDF 생성 결과 3분기를 `recreate`가 돌려준다.** AS-IS는 클라이언트가 `Sys10_File.getServerPath`→`CreateTdmCheckJob`→RD→`checkFileStatus`→`fileReName`을 단계마다 부르고 실패 지점별로 분기한다(자료·RD 호출 실패 = `lockRollBack`으로 그 임원 잠금을 되돌리고 다음 건, 파일 확인 실패 = 잠금 그대로 두고 멈춤). 서버 한 호출로 합치면서 `OK`/`RD_FAILED`/`FILE_FAILED` 코드로 같은 분기를 화면이 이어 간다. 기본(`asseterp.rd.pdf-enabled` 꺼짐) 구현은 `RD_FAILED`라서 RD가 없으면 잠금이 걸렸다 풀린다 — AS-IS가 RD 실패 때 하는 일과 같다(N18·N19의 "첫 행에서 멈춤"과 다름: 거기는 잠금 전에 파일을 만들고, 여기는 잠금 후에 만든다)

## 메모
- `Tdm50_TabPage_CheckJob`는 원본이 직책(보고CEO)마다 탭을 새로 만든다. TOBE도 조회마다 탭을 모두 만들어 두고 고른 것만 보인다(antd `Tabs`는 머리글만, 본문은 `display` 토글 — N01 총괄 화면과 같은 틀).
- `selectByCheckYm`의 결재 서브쿼리(`b`)가 작업 ID와 무관하게 `LIMIT 1`이다 — 원본 그대로 옮겼다. 여러 달에 결재가 있으면 다른 달의 결재상태가 보일 수 있는 원본의 모양이다(03 원칙 4, 제안 아님·확인용 메모).
- `pre-create`(원본 `result.fail(-1, …)`)·`createCheckManl`·`deleteChckManl`·`updateEndYn`은 원본이 클라이언트 모델(`jobModel`)을 통째로 받았지만 TOBE는 작업 ID로 서버가 읽는다(N15와 같은 방식).
- `deletePrintByJobTp`가 로그인 사용자 몫 `%CHCK_%` 출력 자료를 지운다(원본 동작). 시험 때 admin 몫 9행이 지워졌다 — 같은 사용자의 다음 출력이 다시 만든다.

## yunhee 0.5.1 수정(042-1·11)이 잘 되었나 — 이 ID에서 판단한 것
- **042-1 `port-sql` 서브쿼리 `t.*` 확장 → 해결.** 같은 모양의 `tdm51_chck_org.selectByRoleId`(바깥 `t.*` + `f_cdnm(…)` 계산 열, 안쪽에 `LEFT JOIN LATERAL`·집계)로 시험했다. 이전 0.5.0 증상(바깥 열이 `ROW_NUMBER` 한 열로 줄고 `--cols` 전부 `⚠ SQL 열 없음`, DTO가 모두 String)이 없어졌다: 안쪽 별칭 12개가 바깥 `t.…`로 확장되고, 계산 열 `org_status_name`도 나오며, DTO는 `Long`(건수·ID)·`String`으로 맞게 나왔다. 내가 열 이름을 `orgStatusCode`로 잘못 준 것만 `⚠ SQL 열 없음`으로 정확히 지적했다(AS-IS 속성명은 `orgStatusCd`). 남은 흠: ① 안쪽 SELECT 본문이 들여쓰기 없이 한 줄씩 평평하게 붙어 나와 가독성이 떨어짐 ② 바깥 `<sql id="chckOrgColumns">`가 쓰지 않는 `t.*` 파생 열(회사·점검년월 등 9열)까지 모두 펼침 — 복사 후 `--cols` 밖은 지워야 함 ③ `f_cdnm(… , #{stdDate})`의 날짜 인자 `CAST(… AS date)`는 안 붙임(042-2의 "숫자 인자 CAST" 제안과 같은 부류) — `sql-check`가 통과시켜 문제는 아니었지만 다른 DB 함수에서는 필요할 수 있다.
- **042-11 `port-save` `--insert-cols` + 자동 채움 안내 → 해결.** `port-save tdm50_chck_job --cols tdm50_check_nm,tdm50_start_date,tdm50_end_date --company-col tdm50_company_id --insert-cols tdm50_check_ym`에서 INSERT에만 `tdm50_check_ym`이 들어가고 UPDATE의 SET에는 빠졌다. `부수 효과` 절에 `자동 채움: tdm50_upd_nm = 로그인 사용자 이름, tdm50_upd_date = 현재 시각`이 한 줄로 나왔다. 남은 흠: ① 안내만 있고 생성된 INSERT·UPDATE에는 `upd_nm`·`upd_date` 열이 안 들어간다(`updName`을 받는 매퍼라면 사람이 더해야 함 — `--auto-fill` 같은 옵션이 있으면 바로 쓸 수 있다) ② `tdm50_end_yn`처럼 INSERT에서 기본값('false')이 필요한 열은 안내가 없다(`UpdateDataModel`은 모델 기본값을 쓰는데 `--insert-cols`로 줄 때만 보임) ③ 날짜 열이 `#{startDate}`(문자열)로 나옴 — `CAST(#{startDate} AS date)`를 사람이 붙여야 한다.
- **같은 0.5.1에 들어가지 않은 것 확인(042-7·042-3·042-12)**: `compare`가 `HeaderGroupMap(`의 `new`를 열로 읽어 `missing: new`를 낸다(042-7, grid02 비교에서 재현). `analysis ui --tobe`의 AS-IS 수는 이번엔 클래스 자신의 수로 나왔다(본 화면 6/10/0 등 — 042-3 "연결 클래스 합산" 증상은 이 화면에서 안 보였다. 연결 클래스가 `--done`에 없어서일 수 있음). `analysis screen --section buttons`는 `점검항목생성`을 `register`로 추천(실제는 `button-types.md`의 "생성 → generate") — 새로 확인한 것이라 yunhee 수정사항 제안 대상이다(사용자 보고에 적음). 훅이 `tail -3 docs/08-회차인계.md`를 막는 문제는 이번에도 겪었다(`Read(offset/limit)`로 우회, 042-12 그대로).
