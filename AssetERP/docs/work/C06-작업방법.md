## 공통 절차와 다른 점
- **실제 문자 발송 없음(사용자 지시).** AS-IS `sendGroupMessage`는 `SendSMSAPIFunction` → `SendSMSAPI.smsGroupSender`(외부 SMS API 호출 + `sms04_group_send_history` 기록)를 부른다. TOBE는 서버 `SmsGroupSendService.sendGroupMessage`가 단체문자를 읽고 `"[Asset-ERP] " + 내용`·수신자 이름(`고객사 + " " + 사원명`)을 만들어 `SmsSender.send`를 부르고, 기본 구현 `DisabledSmsSender`는 **무조건 거절**(`INVALID_INPUT` "SMS 발송 연동이 아직 없어 문자를 발송하지 않았습니다")한다. 따라서 **화면의 [발송]은 지금 항상 이 문구를 보여 주고, 기록(sms04)도 남지 않는다.** 나중에 연동을 만들 때 `SmsSender` 구현을 추가하고 기본 구현을 지운다. AS-IS의 EUC-KR 바이트 변환은 같은 문자열로 돌아오는 동작이라 옮기지 않았다.
- 새 행의 회사·생성자·생성일자는 AS-IS가 클라이언트 `LoginUser`로 채우지만 TOBE는 서버가 계산한다(A27과 같음, `new-row`·INSERT).
- `Sms03_Page_UserListAdmin`의 고객사 콤보는 AS-IS `Collapse` 이벤트(열었다 닫을 때마다)가 아니라 값이 바뀔 때만 조회한다(antd `Select`의 `onChange`).
- AS-IS `setGroupSendId(null)`은 `grid01`을 두 번 비활성화하고 `grid02`는 그대로 둔다(원본 결함 — 같은 동작으로 옮김: 사원 그리드·조회·발송·기타고객사 추가는 막히고 대상 그리드는 열려 있음).
- `retrieve()`의 `TempData.getUserName()` 분기(`kfiamuser` → 회사 1, `idmsuser` → 28000)는 C03과 같이 로그인 ID로 옮겼다.
