## 결정 (사용자 승인 필요 없는 입력 검사 — 05 §6 "DB 오류" 규칙)
- 일자 생성: 년도가 4자리 숫자가 아니면 `INVALID_INPUT "년도를 4자리 숫자로 입력해주세요"`(원본은 `to_date` 오류 문구).
- 기초데이터생성: 고객사를 안 골랐으면 `INVALID_INPUT "고객사를 선택해주세요"`(원본은 `companyId`가 null인 채 실행돼 회사 없는 행이 생김).
- 저장·삭제의 UPDATE·DELETE에 회사 조건을 더했다(05 §6 회사 조건 규칙).

## 제안 (사용자 승인 전에는 반영하지 않음)
- 원본 "생성"은 월을 받아도(`monthComboBox.getCode()`) 서버가 쓰지 않아 **월을 골라 생성해도 그 해 전체가 지워지고 다시 만들어진다** — 영업일·휴일사유를 손으로 고친 값이 모두 사라진다. 확인 문구는 "기존 데이터를 삭제 후 생성합니다"뿐이다.
- 1080·1113이 이 DB에서 admin 회사(0)에 켜져 있지 않아 관리자 전용 버튼(고객사반영·기초데이터생성)을 화면에서 쓸 수 없다. 운영 DB 설정이면 확인 필요.
- 영업일 체크를 눌렀다 다시 눌러 원래 값으로 돌려도 `저장(1)`이 남는다(GXT `getModifiedRecords`와 같은 동작이라 그대로 둠).
