## 의존·제안 (사용자 승인 전 반영 안 함)
- **의존(다른 도메인)**: `Sys09_Lookup_Code`의 사용이력 검사 3종 — `emp.Emp20_Leave.checkSpcLeaveCode`(SpecialLeaveCode), `dcr.Dcr05_DocType.checkDocFormClassCode`(DocFormClassCode), `rpt.Rpt03_Week.checkWeekBizType`(WeekBizType, 999 코드 규칙 포함). 지금은 서버가 그 코드구분을 거절한다(검사 없이 지우지 않으려고). 그 도메인 화면을 변환할 때 같이 옮긴다.
- 저장·삭제·업로드 서버 권한(`ROLE_SYSADMIN`)은 원본에 없는 보강이다(A31과 같음).
- 원본 `FileUpload`는 `companyId`를 클라이언트가 보낸 값으로 쓴다(위조 가능) → 서버는 로그인 회사를 쓴다.
- 그리드 분류 셀 콤보는 원본처럼 화면을 만들 때 한 번만 코드를 불러온다. 분류추가 뒤에는 툴바 콤보만 갱신되고 그리드 콤보는 다시 열어야 새 분류가 보인다(원본 동작 그대로) — 같이 갱신하려면 승인 필요.
- 원본 `preUpdate`의 코드 변경 검사는 `orgCode != modiModel.getCode()`(문자열 참조 비교)라 값이 같아도 다시 입력하면 검사 대상이 된다. 여기서는 불러온 코드와 값을 비교한다(값이 같으면 검사 안 함).
- 업로드 결과: 원본은 "업로드 성공/실패" 문구를 서블릿이 응답 본문에 쓰지만 화면은 보여 주지 않는다. 이번에도 실패 때만 오류를 띄운다.
- UX보강 제안: 파일업로드 전 분류가 '전체'면 막는 안내 대신 버튼을 비활성화하는 방안(UX-05 후보). 승인 전 반영 안 함.
