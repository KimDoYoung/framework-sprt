## 공통 절차와 다른 점
- **조회가 회사 구분 없이 전체 분류**다(원본 SQL에 회사 조건이 없음). 수정·삭제만 로그인 회사 행으로 막았다(보안 보강) — 원본 UpdateDataModel은 id만으로 고치고 `companyId`를 로그인 회사로 바꿔 넣는다(고객사가 공통 분류를 고치면 행이 고객사 것이 되는 부작용). 메뉴가 기초자료(관리자 회사)에만 있어 문제는 없다. 결정(작업기록).
- 새 분류의 id는 저장 때 채번한다(원본은 열기 전 `DBUtil.setSeq`) — 저장 안 하고 닫으면 둘 다 아무것도 남지 않는다.
- 저장 안 한 새 분류의 [삭제]는 서버를 부르지 않는다(원본은 0건 삭제 — 결과 같음).
- 사용 열(`addBoolean`)은 체크박스라 클릭하면 값이 바뀌지만 이 화면에는 저장이 없다(원본도 같음).
