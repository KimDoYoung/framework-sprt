## 범위 (분석에서 정함)

- 한 번에 끝까지 한다. 전자결재 의존은 주석 처리된 코드뿐이라 1단계 분할이 필요 없다.
- 이 화면은 **저장이 있다**(처리여부·처리일·담당자·비고). 서버 `Sch04_List.insertCheck`: 이미 있는 행은 `confirmUpdate`, 조회가 UNION으로 만들어 낸 미처리 건(DB에 없음)은 새 ID로 `insert`.
- H06 `Sch04_Tab_IcsList`(`SchListMapper`·`SchListService.upsert`·`Sch04ListSaveReq`)와 같은 테이블·같은 저장 흐름이라 같은 매퍼/서비스/컨트롤러에 `…Todo…` 메서드로 붙인다(`insert`·`selectById`·`selectNextId` 재사용).
- 열 때 조회하지 않는다(AS-IS `settings()`의 콤보 callback은 문구만 "전체"로 바꾸고 retrieve를 부르지 않음) — [조회]를 눌러야 목록이 나온다.
- 색인의 `E3 toggle.ValueChange … 도달 불가`는 오판: 라디오 둘이 툴바에 직접 붙어 있고 `toggle`에 묶여 있으므로 값이 바뀌면 retrieve()를 부른다.
- 공유구분 콤보(`shareTypeComboBox`)·결재요청/원인문서 열은 원본에서 주석 처리 → 만들지 않는다. `shareType`은 항상 `"1"`(나의 스케줄), `searchText`는 항상 `"%"`.
