## 화면 구성
page-style SGEF (견본 `Fnd01_Tab_FundCode`): 위 Splitter 패널(여백 `20 20 0 20`, 툴바 + 그리드, 간격 8, 요약 두 줄) / 아래 330(최소 330) 편집 폼(라벨 105 오른쪽 정렬, 줄 간격 10, 버튼 줄 위 선). `page-style --compare` 일치.

## 공통 절차와 다른 점
- 서버가 본인·회사 조건을 더한다(AS-IS는 클라이언트가 보낸 사원 ID를 그대로 씀). 삭제 상태 검사·수정 잠금(10·20·30·취소)도 서버가 한다.
- 초과사용 승인요청: 문자 발송은 `SmsSender`. 발송 연동이 없으면 거절하고 승인상태는 바뀌지 않는다(AS-IS도 발송이 안 되면 상태를 안 바꾼다). `sms02_history` 이력 기록은 `SmsSender`가 하지 않아 다음 단계.
- 대결자 지정 내역 삭제 확인창은 AS-IS처럼 예/아니오/닫기 세 갈래로 직접 만든 창이다(화면 단추 수에 [예][아니오] 2개가 더 센다).
- [대결자 지정](`Apr07_Lookup_AltAppr`)은 다음 단계 — 단추는 있고 누르면 안내만 한다.
- 입력 칸 폭은 12 화면우선원칙에 맞춰 줄이 넘치지 않게 flex로 잡았다(AS-IS 사유 500·대직자 590·문서분류 590).
