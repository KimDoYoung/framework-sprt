## SQL 이식
- `selectByText`: 활성 고객사(회사 0 제외)를 `LEFT OUTER JOIN`으로 붙이고, 없는 행·NULL 값은 `COALESCE(…, 'true')`. 행 ID는 `COALESCE(act15_close_check_id, row_number() over())`라 아직 없는 회사는 1..N의 **임시 ID**를 받는다 — 그대로 옮긴다
- `selectById`: 저장 뒤 다시 읽는 용도. 원본은 `act15_close_check.*` + `f_get_company_nm`, 여기서는 `selectByText`와 같은 열로 풀어 DTO 하나로 쓴다(없는 값은 'true' 아님 — 저장한 값 그대로)
- 저장: 원본 `update`는 `selectById(closeCheckId)`가 비면 새 시퀀스를 줘서 INSERT, 있으면 UPDATE(`UpdateDataModel`). 열 13개 + 회사 ID를 쓴다

## 공통 절차와 다른 점
- **저장은 관리자 회사만**(보안 보강, E21·E23과 같음). 원본은 회사 조건 없이 아무 id나 고쳤다 → 제안으로 기록. 조회는 원본 그대로
- 임시 ID(row_number)는 실제 ID(`f_create_seq`, 15자리)와 겹치지 않아 `selectById`로 있고 없음을 가리는 원본 방식을 유지한다
