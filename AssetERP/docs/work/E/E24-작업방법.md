## SQL 이식
- `selectByCompanyId` 둘: `SELECT *`를 DTO 열로 풀고 `f_cdnm('CreditCardCompany'/'CreditCardExcelCode', …, 회사, f_sysdate())` 이름 열 유지. Crd10은 `ORDER BY 카드사코드 collate "ko_KR.utf8"`(E14에서 컨테이너에 로케일 설치됨)·Crd11은 `ORDER BY 위치`. 그대로.
- 저장·삭제: UpdateDataModel 동적 SQL을 명시 SQL로(`pay`처럼 INSERT/UPDATE/DELETE). INSERT의 회사 = 로그인 회사.

## 공통 절차와 다른 점
- **필수·중복 검사는 화면이 하고** 서버는 DB NOT NULL 오류를 막으려고 필수만 같은 문구로 막는다(중복은 원본도 화면만).
- 회사 범위: 조회·저장·삭제 모두 로그인 회사로 고정, UPDATE·DELETE에 회사 조건(다른 회사 행을 못 고침, 보안 보강). 관리자 회사 한정은 두지 않는다 — 원본 조회가 로그인 회사 기준이라 고객사도 자기 카드사를 관리한다.
- Crd11 창의 회사 ID는 화면이 부모 행 값을 보내지만 서버는 로그인 회사를 쓴다(부모 행도 로그인 회사 행이라 같음).
- 원본 `Crd11_Lookup_ExcelCodeAdmin`의 비고는 모델 속성 `text`(DB `crd11_note`).
- `analysis ui`의 Crd11 이벤트는 원본에 E0 없음 → TOBE 주석에도 E0를 달지 않는다.
