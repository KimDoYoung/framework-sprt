## 공통 절차와 다른 점
- E11·E12와 같다: 재생성 실패 서버 사유 추가(TOBE 추가), 조회 회사 범위를 서버가 제한, 원본 `retrieve()`의 `kfiamuser`(회사 1)·`idmsuser`(회사 28000) 하드코딩은 안 옮김
- **E11·E12와 다른 동작**: 실패해도 다음 건으로 진행(원본 `afterComplete.run()`). 진행 메시지는 `[직책 임원]`, 원본의 "데이터 생성중"·"pdf 생성중" 단계 메시지는 서버가 한 번에 처리해 "파일 생성준비중"만 보임
- 원본 `getSumGrid("", 2, 6, 9)`: 6~9번째 열(작성완료일·책무·책무세부·관리의무)을 합산 — **점검항목 열은 합계에서 빠져 있고 "건수" 묶음은 점검항목·아이콘 열까지**(원본의 인덱스 어긋남으로 보임, 그대로 옮김). 작성완료일(날짜) 합계는 의미가 없어 칸을 비움(원본 표시는 미확인)
- `setChecked(SelectionMode.SINGLE)`인 점검항목 그리드는 `MultiGrid`에 `rowSelection` `singleRow`+체크박스로 덮어씀
- 동적 셀(`addDynamicCell`, 값이 있을 때만 아이콘) 공통 부품이 없어 `pages/tdm/tdmGridCells.tsx`에 임시로 둠 — 공통 후보(작업기록 제안)
- 화면이 상신건(결재 10·20·30)만 조회하고 상신하면 `lockYn`이 켜지므로 **이 화면의 점검항목 조회창엔 [등록][삭제]가 사실상 나오지 않는다**(이 DB: 결재상태 30인 29건이 모두 잠금, 잠금 안 된 65건은 결재 전(00)이라 화면에 안 나옴). 그래서 [등록][삭제]와 비잠금 분기는 화면에서 확인할 수 없다(결과확인 항목 7)
