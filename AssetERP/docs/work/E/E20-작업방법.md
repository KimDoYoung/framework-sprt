## 공통 절차와 다른 점
- **쓰기(저장·삭제·엑셀업로드·미일치내역 조회)는 관리자 회사(SYSADMIN)만** — 원본엔 서버 검사가 없지만 이 데이터는 관리자 회사 것이고 기초자료 메뉴가 관리자 전용이다. Sch10은 로그인 회사 대신 관리자 회사(0)에 쓴다(관리자가 회사를 골라 로그인해도 조회 SQL이 보는 회사와 같게).
- **`sch14_ipo_mismatch` ID는 18자리**(DB 함수가 만든 것, 27건 모두 2^53 초과) → JS 숫자로 받으면 끝자리가 틀어져 저장이 404가 된다. 이 ID만 JSON 글자로 내려 보낸다(`ToStringSerializer`). 다른 테이블 ID는 15자리라 해당 없음(제안: 전역 정책 — 작업기록).
- **`Com50_Lookup_StkItem`의 더블클릭 → confirm()은 VIEW에서만 묶었다.** 원본은 EDIT에서도 묶어 셀 편집(더블클릭)과 겹치면 창이 닫힌다 — 사용자 확인 대기(결과확인).
- 종목명이 비면 서버가 막는다(`sch10_item_nm` NOT NULL — DB 오류 방지, 05 §6). 엑셀의 시장구분·종목명·발행기관코드가 비면(원본은 NPE) 몇 번째 행인지 알린다.
