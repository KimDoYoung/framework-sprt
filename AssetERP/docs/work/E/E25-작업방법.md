## SQL 이식
- `selectBySearchText`: `SELECT *` + `f_cdnm('EmpBenefitType', …)` + `f_get_account_nm(…)`를 DTO 열로 풀었다. 검색은 `UPPER(CONCAT(emp55_benefit_cd)) LIKE UPPER(searchText)` — **이름이 아니라 코드**를 찾는다(원본 그대로). ORDER BY 없음(원본 그대로).
- `insertInitData`: 열 목록 없는 `INSERT … SELECT`를 열 순서대로 적었다(E08과 같음). 기존 행은 지우지 않는다(중복 코드가 생길 수 있음 — 원본 동작).
- `selectBySlipYn`: `SELECT *` + 계정명 앞 `(사용X)`를 DTO 열로 풀었다. 조건 `use_yn='true'`와 `slip_yn='true'`라 `(사용X)`는 실제로 붙지 않는다(원본 그대로 둠).

## 공통 절차와 다른 점
- 회사 범위: 왼쪽은 로그인 회사. 오른쪽은 `companyId`를 받되 **다른 회사는 관리자 회사만**(E08과 같음, 서버가 검사). 저장·삭제 SQL에 회사 조건을 더했다. 기초데이터생성은 관리자만.
- `Sys01_Lookup_Company`에 `multi`/`onMultiResult` 추가(11 §4·05 §5 갱신).
- 원본은 고객사마다 서비스를 따로 부르고 하나라도 실패하면 그 메시지만 띄운다. TOBE는 한 번의 POST로 한 트랜잭션(전부 성공 또는 전부 취소) — 결과는 같고 실패 시 일부만 복사되는 상태를 막는다(제안, 아래 작업기록).
- 계정코드 칸은 원본이 `getSelectedItem()`(선택 행)에 쓰지만 TOBE는 돋보기를 누른 행에 쓴다(돋보기가 행을 선택하므로 같음).
- 미사용 칸은 `addBoolean`이라 편집 가능(`{editable: true}`).
