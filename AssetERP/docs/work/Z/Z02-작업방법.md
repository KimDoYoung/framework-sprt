## API (새 8개)
- `GET bbs/notices/manage` (selectByCompanyIdPaging·Total, `systemNoticeYn`은 불러오기 창만) · `GET bbs/notices/next-id` · `PUT bbs/notices/manage`(Bbs02_Notice.update + Bbs03_Target.update — 새 공지 INSERT/기존 UPDATE, 공지번호 채번, 새 대상자 INSERT) · `DELETE bbs/notices/manage/{id}`
- `GET bbs/notices/{id}/targets`(selectByNoticeId, 공지일 기준) · `DELETE …/targets`(체크한 대상자) · `DELETE …/targets/all`(deleteAllTarget)
- `GET emp/addr-book-groups/list`(getList) · `GET emp/addr-book-groups/{parentId}/select-items`(selectByParentId 전체 열) — 그룹선택 창
- 댓글 `deleteMasterStr`(항상 ✕) 필드 추가(기존 API 응답에 열 1개)

## SQL 이식
`bbs02_notice.selectBbsByCompanyId`·`selectByCompanyIdPaging/Total`, `getNoticeNo`, 저장은 UpdateDataModel을 `port-save`로 INSERT/UPDATE로 풀어 쓴 것(공개 `true` 고정, 작성자 = 로그인), `bbs03_target.selectByNoticeId`(공통 `emp00With` 재사용 — `personId`·`transId`를 null로 넘겨야 `<if test>`가 돈다), `insert`, `deleteAll`. 그룹선택 `emp57_addr_book_group.getList`·`selectByParentId`(전 열). 원본 `SELECT bbs.* AS bbs02_comment_cnt`는 CTE가 이미 만든 열이라 뺐다.

## 공통 절차와 다른 점 (원본과 다른 점)
- 새 공지는 AS-IS가 [등록]에서 그리드에 빈 행을 먼저 넣지만, 여기서는 저장할 때 그리드에 넣는다(견본 SGP와 같다). 닫기만 하면 아무것도 남지 않는다.
- 관리자용 첨부파일 창 `Bbs02_Lookup_File.open(Long)`은 `Bbs15_Lookup_File`(E10, 같은 소스의 복사본)을 재사용한다.
- 개별 대상자 [삭제]는 저장된 행만 서버에서 지우고, 이번에 더한 행은 그리드에서만 뺀다. 아무것도 체크하지 않으면 "삭제할 행을 선택하세요."(05 §8).
