## 공통 절차와 다른 점
- **page-style**: `yunhee page-style --compare`는 GG 일치지만 원본은 좌우 분할(West 270)이라 `page-style-check GG`(세로 Splitter·SearchBar 요구)가 ✗. 세로 Splitter로 바꾸면 원본 레이아웃과 달라지므로(03 원칙 12) 원본 배치를 따르고 새 SID를 제안한다(GGH 선례, 결과확인 13).
- 12 준원칙: 원본 테두리 박스(`setBorders`)는 두지 않는다(선 최소화), 왼쪽·오른쪽 사이 간격 12.
- 상세 창의 본문은 목록 행이 아니라 열 때 `selectById`로 읽는다(목록이 본문을 싣지 않기 위해, 원본 목록은 `SELECT *`).
- 버튼 type: [수정] `change`(ColorButtonBottom 매핑 없음, 후보 `view`보다 의미가 가까움), [첨부파일 등록(n)] `attach`, [첨부파일 확인(n)] `view`, [이동] `move`.
- 게시물 수정·삭제 서버 작성자 검사는 원본에 없는 추가(#189) — 화면이 이미 [수정][삭제]를 작성자에게만 보이는 규칙이므로 같은 동작.
- 분류 그리드 삭제는 원본이 선택한 줄을 지운다(체크 삭제 아님) — `useGridCrud.deleteChecked` 대신 `removeRows`.
