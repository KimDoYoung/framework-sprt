# 01j. 변환목록 (준법감시 — 임직원매매 준감인)

`01i-변환목록.md` 다음에 이어지는 상태판이다. 상태는 ID가 속한 파일에만 적는다. ID는 `J` 접두사(J01~J09)로 01a의 A·B·C, 01b의 D, 01c의 E, 01d의 F, 01g의 G, 01h의 H, 01i의 I와 겹치지 않는다.
ID 하나의 기록은 `work/{ID 첫 글자}/{id}-작업방법.md`, `…-작업기록.md`, `…-결과확인.md`(예: J03 → `work/J/`).

- 상태: `대기` → `분석` → `백엔드` → `프론트` → `확인` → `완료`, 또는 `보류`(사유를 비고에).
- **다음 작업은 아래 표에서 상태가 `대기`인 첫 줄**(01a·01b·01c·01d·01g·01h·01i가 끝난 뒤). 순서는 사용자 지정(2026-10-20).
- 패키지는 도메인별(`biz.flt`). 하위 클래스(팝업·조회창)는 분석 단계에서 `yunhee analysis screen <화면> --list`로 확인해 같은 ID에서 함께 한다. 다른 도메인 컴포넌트(예: 전자결재 편집창 `Apr01_Edit_ApprDoc`)는 링크만 있으므로 01d·01g처럼 **1단계만** 할지 분석 때 정한다.
- 메뉴 열의 번호는 이 ID가 대표로 삼는 메뉴다. 같은 클래스가 여러 메뉴에 걸리면 나머지는 비고에 적고, 결과확인 항목 9(메뉴 여러 개)에서 같이 확인한다.
- 이 목록은 사용자가 준 클래스 목록을 `docs/as-is/src/menus.md`에서 찾아 만들었다(2026-10-20). 모두 메뉴 `준법감시 > 11. 임직원매매(준감인)`에 속한다.
- 01i(`10. 임직원매매`, 임직원용)의 짝이다. `TrListAdmin`·`BookListAdmin`은 01i의 `TrList`(I08)·`BookList`(I09)와 서버·SQL이 겹칠 가능성이 크고, `Violate`는 I10 `ViolateUser`와 짝이다. 먼저 끝낸 ID의 공통 부품·API를 분석 때 재사용 여부를 확인한다.
- 줄·서비스·테이블 수는 분석 단계에서 채운다.
