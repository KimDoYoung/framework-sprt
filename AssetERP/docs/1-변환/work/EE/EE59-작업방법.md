## API / SQL
`POST /api/auth/password/change`·`/extension` (로그인 전이라 permit-all, `application.properties` `permit-all-paths`에 `/api/auth/password/**`). SQL 그대로: `checkPassword`·`checkPasswordRule`(`f_password_rule`)·`extension`, 저장은 이미 있는 `SysPasswordMapper`(`selectLastSeq`·`updatePassword`·`insertPassword`) 재사용. 새 `AuthPasswordMapper.xml`.
- 규칙 안내 문구, 메시지("현재 비밀번호와 동일한 …", "[변경 비밀번호]와 [비밀번호 확인]이 일치하지 않습니다.", 규칙 위반은 `f_password_rule` 사유 그대로, "비밀번호 변경이 완료되었습니다", "비밀번호 만료기한이 3개월 연장되었습니다") 원본 그대로.

## 공통 절차와 다른 점
- **보안 보강(인증 없는 API라서)**: AS-IS `insert`/`extension`은 검사 없이 누구나 호출했다. TOBE는 서버가 ① 비밀번호가 있는 계정은 현재 비밀번호(또는 인증번호 확인 표시)가 맞아야 바꾸고 ② 틀리면 로그인 실패와 같은 횟수로 세어 5회에 잠그고(빈 칸은 세지 않음) ③ [3개월 후 변경]에도 현재 비밀번호를 요구한다. 비밀번호가 **비어 있는 계정(최초/관리자 초기화)** 은 AS-IS처럼 현재 비밀번호 없이 설정할 수 있다(아래 제안 참고).
- 규칙 검사(`f_password_rule`)와 [변경]/[확인] 불일치 검사 순서: AS-IS는 규칙 → 불일치, TOBE는 불일치(화면) → 규칙(서버). 메시지는 같다.
- 현재 비밀번호와 같은 새 비밀번호 거부는 서버가 현재 비밀번호를 확인한 뒤에 한다(L218-220).
- 호출처 연결: `LoginPage`의 로그인 오류 `PASSWORD_CHANGE_REQUIRED`(만료=modi, 비어 있음=init)가 안내 확인창 뒤 이 창을 연다(AS-IS status 98/99, L538-561). AS-IS의 "만료 임박 경고 → 계속 로그인"(L493-515)은 TOBE 로그인이 만료 시 거부만 하므로 해당 없음.
