# EE75 Ics31_Lookup_Confirmer (확인자 선택창) — 작업방법

AS-IS: `client/vi/ics/Ics31_Lookup_Confirmer.java(150줄)` + 호출처 `Ics31_Tab_ComplianceWrite.fixChk()`(L518) + 서버 `ics.Ics30_Compliance.selectConfirmer`·`ics.Ics32_RelateAppr.selectApprStatus`·`ics.Ics31_ComplianceWrite.updateFixYn`. 출처: 미변환 목록 Category G-26.

## 제출 흐름 (Ics31_Tab_ComplianceWrite 변경)
[제출] → 미체크 보기 끄고 재조회 → 검사(미완료·이미 제출) → **확인자 선택창** → 확인자로 `PUT ics/compliance-writes/fix {fixYn:true, writeIds, confirmerId, stdDate, cycleType}` → 서버: 그 확인자가 이 분기(월)의 부서장 준수확인서(`ics32_appr_type='2'`)를 이미 상신해 결재 중·완료(10·20·30)면 "해당 확인자는 이미 준수확인서의 제출을 마친 상태입니다. 확인바랍니다." 거절(AS-IS는 화면이 `selectApprStatus`를 먼저 불러 status -1이면 같은 메시지) → 아니면 제출일시+확인자 저장. [제출취소]는 확인자 없이 바로(제출일시만 비움, 확인자는 남김 — AS-IS SQL 그대로).

## API / SQL
새 API 1개(`GET …/confirmer`, `IcsComplianceWriteController`)와 `PUT …/fix` 본문에 `confirmerId`·`stdDate`·`cycleType` 추가. 매퍼 `IcsComplianceWriteMapper`: `selectConfirmer`(AS-IS 그대로 — 이전 확인자 → `f_get_confirmer_limit(…,'0020')` 부서장 → 준법감시인(등급 120). 날짜 비교만 `::date`) · `countApprStatus`(`ics32_relate_appr.selectApprStatus`, apprType 2는 V28 추가 열) · `updateFixYn`에 확인자 열(`ics31_confirmer_id`, 제출일 때만).
