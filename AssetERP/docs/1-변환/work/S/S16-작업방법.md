## SQL 이식 주의
- 원본 `sys12_calendar.workDayPerson`은 `sys12_company_id = 1`로 고정이고 `retireDate` 분기가 있다 → 그대로.
- `insertLatestInfo`는 열 이름 없는 `INSERT … SELECT`다(pay11 열 순서 의존) → `port-sql --raw`로 그대로.
- 급여 계산은 DB 함수(`f_calc_4insure_nps·hi·ltc·ei`, `f_calc_income_tax`, `f_calc_local_tax`, `f_create_4insure_adjust_pay`, `f_create_4insure_adjust_modi`)가 한다 — 함수는 건드리지 않고 SELECT로만 부른다.
- 생성은 사원마다 트랜잭션 하나(원본은 한 서비스 호출 = 한 트랜잭션, 예외 시 status -1 "데이터를 불러올수 없습니다. 관리자에게 문의해주세요").

## 분석에서 확인한 세부 (구현 때 그대로 쓴다)
- 서버 `Pay10_Month.insert`(L243-614): 사원마다 ① `workDayPerson`(퇴직 trans 900이면 retireDate = transDate) ② `selectByPayDatePersonId`로 이미 있으면 건너뜀(항목 생성도 건너뛰되 **4대보험 연말정산(221/231/241)은 payCode 01이면 항상 시도**, 금액 0이면 insert 안 함) ③ annualYn "true": `pay10_month.insert`(monthId=f_create_seq, workDay, totalWorkTime=workDay×8, stdMonth) 후 연봉정보(`pay01_annual.selectByApprStatus`, 결재완료 30) 있으면 payCode별 항목 — 01: 110(기본급+연장)·111(중식)·112(차량)·113(양육)·190(기타 etc01+etc02) 각 >0이면, 210 NPS·220 HI·230 LTC·240 EI·250 소득세·260 지방세는 DB 함수로; 02: 130 상여급 0원(기본+연장 >0); 03: 일할(`dd / 월말일`) 110·111·112·113 (long으로 내림); 04: 191 특별수당 0원. annualYn "false": `pay10_month.insert` 후 payCode 01이면 `insertLatestInfo`(전월 최근 급여 복사, 221/231/241 제외).
- `insertModel`의 extendWorkTime·nightWorkTime·holidayWorkTime은 null로 insert된다(원본 그대로). 소득세는 `f_calc_income_tax(:monthId)`(항목 먼저 넣은 뒤라 순서가 중요 — 210~240 다음 250, 260).
- `Pay11_MonthItem.updateList`(지급): updateModel(upsert) → 삭제 → 250/260 재계산(`updateItemAmt` upsert, 없으면 item_type을 pay20_item에서). `getInsureAdjustModi`(공제): updateModel/삭제마다 항목코드가 221/231/241이면 `f_create_4insure_adjust_modi(personId, insureCode 2/3/4, payDate)`를 부르고 결과가 'Y'가 아니면 그 문구로 실패(-1).
- `Pay10_Month.deleteAll`: 행마다 pay11·pay12·pay13·pay14 deleteByMonthId, payCode 01·03이면 pay32 deleteByDate(personId, date), 그리고 insureCode 2·3·4 `getInsureAdjustModi` 'Y' 확인, 마지막에 pay10_month 행 삭제(`UpdateDataModel.deleteModel`).
- `checkAppr`: 결재 진행(pay05+apr01 10·20·30)이면 "결재진행중인 급여구분입니다", 분개 있으면 "발생된 전표가 존재합니다. '발생업무 회계처리' 화면에서 전표삭제 후 진행하세요" — `Pay10_Lookup_Insert`는 payCode 03이면 검사 건너뜀.
- `Pay11_TabPage_MonthItem.enabled`: 같은 checkAppr 결과가 실패면 [행 추가][행 삭제][저장]×2·[소득세 재계산]을 비활성(근로시간·비고·임금계산방법·납부상세는 그대로). `retrieve`는 itemType 1/2 두 그리드를 따로 읽고 삭제 목록(`deleteList1·2`)은 저장 때 서버로 보낸다.
- `Pay10_Lookup_Insert`: 530×370 "생성 구분", 지급구분(PayMonthCode 콤보)·지급일자·기준연월(빈칸 "YYYY.MM", 지급일자를 바꾸면 yyyy.MM으로 채움)·라디오(연봉정보 true/전월급여, **지급구분 이름이 "급여"일 때만 활성**), 안내 문구, 필수 검사 "구분값은 필수입력 항목입니다"·"급여지급일은 필수입력 항목입니다" → `Emp01_Lookup_TransDate.open(true, cb)` → 서버 insert → 성공(status>0) "생성이 완료되었습니다" 뒤 닫기, 실패 "데이터를 불러올수 없습니다. 관리자에게 문의해주세요".
