## 결정
- 기준년월은 열릴 때 **이번 달**(J06은 한 달 전). 원본 `settings()`가 `LoginUser.getToday()`의 달을 쓴다.
- 탭은 활성 탭만 그리고 탭을 바꿀 때 새로 조회한다(원본은 탭을 모두 만들어 두지만 조회 시점은 같다).
- 상신 문서 조회는 `linkCode`를 서버 상수(A72)로 두었다. 다음 단계에서 [문서보기]·[결재요청]이 같은 코드를 쓰므로 파라미터로 열지 않았다.

## 의존 / 다음 단계
- **2단계**: [결재요청](`Dcr01_Lookup_Class`·`Dcr30_Link.selectByLinkCode`→`docClass` API는 I02 때 이미 있음 → RD 첨부파일 생성 `Sys99_Print.insertRdCeoReport`+`Sys10_File.getServerPath` → `Apr01_Edit_ApprDoc.insertLinkApprovals`)과 [문서보기](`Apr01_Lookup_ApprLink`·`Apr01_Edit_ApprDoc.retrieveApproval`). 전자결재 편집창이 J01·J02·J06·I02~I05와 같은 의존이라 한 번에 만들 후보.
- 원본 RD 첨부파일은 RD 서버가 만든 xlsx를 문서에 붙이는 흐름이다. TOBE에서는 서버가 만든 xlsx를 `sys10_file`로 저장해 붙이는 식이 되므로 전자결재 단계에서 정한다.

## 제안 (사용자 승인 전 반영 안 함)
- `yunhee analysis sql`이 `--param transCode=100`을 숫자로 보내 `CASE types integer and character varying cannot be matched`가 난다. `"transCode='100'"`처럼 따옴표를 직접 붙여야 문자열이 된다 — 문자열 파라미터 지정 방법을 `--help`에 적거나 `s:` 접두사를 지원하면 좋겠다(yunhee 수정사항 제안).
- `yunhee compare`는 배포 직후 첫 호출이 0건으로 나올 수 있다(이번에 `accounts` 한 번). 재호출로 13건이 나왔고 `--log`의 SQL은 처음부터 13건이었다.
