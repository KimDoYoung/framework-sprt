## SQL 이식
- 모든 SQL은 IDMS-IC에서 `analysis sql … -o code`로 옮겼다. `SELECT a.*`는 DTO 열로 풀었다(`accountColumns` 조각 공유: 계정명·상위계정명·속성명·차대명은 원본 서브쿼리/`f_cdnm` 그대로).
- `selectByCompanyId`: 검색은 `계정코드||계정명||COALESCE(계정명2)||COALESCE(영문명) LIKE`(대소문자 구분, 원본 그대로), `ORDER BY act01_print_seq`. 기존 `selectBySlipYn`(E25 조회창)은 그대로.
- `insertAdminAccountCode`·`act14_link.insert`: 열 목록 없는 `INSERT … SELECT`를 열 순서대로 적었다. `act14_link.insertUpdate`는 4열만 넣는다(조회순서 비움).
- **`updateAdminAccountCode`는 `act01_print_seq = #{printSeq}`인데 원본이 `printSeq`를 안 넘겨 NULL이 된다** → 같은 결과로 `NULL`을 적었다(원본 동작, 아래 제안).
- `act14_link.insert`의 조회순서는 `MAX(seq)+1`이라 같은 계정의 첫 연결은 NULL, 이후도 NULL — ▲▼를 눌러야 1부터 매겨진다(원본 동작).

## 공통 절차와 다른 점
- 회사 범위: 저장·삭제·연결정보는 로그인 회사만(SQL에 회사 조건을 더했다, 05 §6). 트리(`tree`)의 다른 회사·복사 창 고객사 목록·복사는 **관리자 회사만** 서버가 검사한다(원본은 버튼 노출만 막았다).
- 필수 검사 4종·목적/내용 필수는 원본이 화면에서만 했다 → 서버도 같은 문구로 막는다(INVALID_INPUT).
- 엑셀다운로드: AS-IS는 `sys99_print`에 쌓고 RD 리포트로 만든다 → E10과 같이 서버가 같은 조회 결과를 RD 출력 열 순서(계정코드·계정과목·상위계정과목·속성·차대·전표·금감원·전표(금)·계정과목(보고서용)·계정과목(금감원용)·계정영문명·내용)로 xlsx에 쓴다. RD 양식과 같은지는 확인 못 함.
- 선택 없는 삭제: 원본은 안내 뒤에도 확인창을 띄운다(아무 것도 지우지 않음). TOBE는 안내에서 멈춘다.
- ▲▼는 원본이 선택된 행을 옮기지만 ▲▼ 셀을 누르면 그 행이 선택되므로 누른 행을 옮긴다.
- 연결 그리드 추가는 계정코드 칸의 값으로 한다(저장 전에도 추가된다 — 원본 그대로, 계정코드가 비면 서버가 막는다).
- 트리: 서버가 전위 순서 평평한 목록을 주고, 화면이 `parentCode`로 부모 ID를 찾아 `useTreeGrid`에 넘긴다. 트리 열은 계정과목(`getTreeGrid(2)`).
