## 공통 절차와 다른 점
- 원본 [등록]은 `GridInsertRow`로 그리드에 임시 행을 먼저 넣고 창을 연다(닫기에서 행 제거). TOBE는 임시 행을 넣지 않고, 저장이 성공하면 목록을 다시 조회한다(I06과 같은 결정).
- 변경(MODI) 창의 편집값은 복사본이다 — 원본은 모델 자체를 고치므로 저장하지 않고 닫아도 그리드 행이 화면에서만 바뀌어 보인다. TOBE는 닫으면 버린다.
- 원본 [삭제]는 `delete2`가 서버에서 행마다 `insertFloorTrBook`을 부르고 실패하면 그 행에서 멈춘다(앞 행 삭제는 이미 반영) → TOBE는 한 트랜잭션이라 실패하면 모두 되돌린다.
- 원본 종목 칸은 `LookupTriggerField`로 주식시세 적용 종목유형이 아니면 글자 입력도 된다. TOBE는 같은 동작을 `Input` + 돋보기(`addonAfter`)로 만들었다(11이 쓰지 말라는 `readOnly + suffix` 조합이 아니라 직접 입력용이라 `LookupInput`으로는 못 만든다).
- 종목유형 콤보의 'I' 가지(신고대상 아닌 종목유형만)는 원본이 서버 SQL `targetYn` 가지로 하지만, TOBE는 기존 `item-types` API의 `targetYn` 열로 화면에서 거른다(결과 같음, 새 SQL 없음).
- 거래구분 콤보 "전체"의 값은 `%`(원본 `CommonComboBoxField(…, "%", "전체")`)이고 서버는 `LIKE COALESCE(trType,'%')`로 받는다.
