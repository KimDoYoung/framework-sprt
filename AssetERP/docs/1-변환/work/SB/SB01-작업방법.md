# SB01 배치 호출 골격 (BatchMain 진입점·인증) — 작업방법

AS-IS `/BatchMain?actionCode=…`(서블릿, 외부 cron 호출, 인증 없음, 27개 분기)를 옮기기 위한 **공통 골격**이다. 분기(작업) 자체는 SB02~에서 `BatchAction` 구현체로 하나씩 추가한다. 설계 결정은 `../../서블릿-변환목록.md` §2-7, 이관 항목은 `../../../4-재설계/README.md`.

## AS-IS → TOBE

| AS-IS | TOBE | 비고 |
|:---|:---|:---|
| `BatchMain.service()` — `actionCode` 파라미터로 if/else 분기 (L3919-4044) | `BatchController` `GET·POST /api/v1/batch/{actionCode}` → `BatchService` → `BatchAction`(분기 하나 = 구현체 하나) | 분기를 `@Component`로 추가하면 자동 등록. 없는 코드는 AS-IS 문구 `작업구분(x)을 확인할 수 없습니다.` |
| 파라미터 `companyId·worker·ifCode·stdDate·startDate·closeDate·sendDate·year·data` (`request.getParameter`) | `BatchReq` record (이름 그대로, 모두 문자열·선택) | 날짜 형식은 AS-IS와 같게 각 작업이 해석 |
| 응답: 본문에 결과 문구 한 줄 (`setResult`) | `ApiResponse<BatchRes>`(`message`에 같은 문구) | 03 TOBE 규칙(ApiResponse). cron은 URL·키 헤더를 어차피 바꾼다 |
| 오류 시 `insertNoticeLog("BatchMain."+actionCode, "error(-1)", message…)` → `sys97_notice_log.insert` | `BatchNoticeLogService.error` (`REQUIRES_NEW`, 실패해도 던지지 않음) + `BatchNoticeLogMapper` | AS-IS SQL 그대로(`sys97_proc_nm·notice_msg·err_msg·note`) |
| 인증 없음 | **서버 간 API key + 호출 IP 제한**: `BatchApiKeyFilter` + 별도 보안 체인(`@Order(1)`, `/api/v1/batch/**`) | JWT·테넌트 필터를 타지 않는다 |

## 인증 규칙 (`BatchApiKeyFilter`)
1. `asseterp.batch.enabled=false`, API key 비어 있음, 허용 IP 비어 있음 중 하나면 **전부 거절**(기본 거절).
2. 호출 IP = `request.getRemoteAddr()`. `X-Forwarded-For`는 위조 가능해서 쓰지 않는다(`docs/log-설계.md`). 허용 목록은 IP 또는 CIDR.
3. 헤더(`asseterp.batch.api-key-header`, 기본 `X-Batch-Api-Key`)의 키를 고정 시간 비교.
4. 모두 맞으면 `ROLE_BATCH` 인증을 붙여 체인을 진행하고, 끝나면 인증 정보를 지운다. 거절은 `403 ACCESS_DENIED`. 어느 조건에서 걸렸는지는 응답 메시지(비활성/허용되지 않은 주소/키 불일치)와 서버 로그 WARN에 남기되 키 값은 어디에도 쓰지 않는다.

## 설정 (`asseterp.batch.*`)
| 키 | 기본 | 뜻 |
|:---|:---|:---|
| `enabled` | `${ASSETERP_BATCH_ENABLED:false}` | 끄면 모두 거절 |
| `api-key` | `${ASSETERP_BATCH_API_KEY:}` | **소스에 두지 않는다.** 운영은 환경변수 |
| `api-key-header` | `X-Batch-Api-Key` | |
| `allowed-ips` | `${ASSETERP_BATCH_ALLOWED_IPS:}` | 쉼표 구분 IP/CIDR |

개발 프로필(`t3600`·`omen`·`test`)만 `enabled=true`, 더미 키 `dev-batch-key`, 허용 `127.0.0.1,::1,172.16.0.0/12`(docker 대역)를 둔다.

## 다음 ID가 이 골격에 작업을 붙이는 법
```java
@Component
public class Sch04InsertAction implements BatchAction {
    public String actionCode() { return "sch04Insert"; }
    public String run(BatchReq req) { /* AS-IS BatchMain.sch04Insert를 옮긴다. @Transactional은 필요한 서비스에 */ return "…완료.. commit"; }
}
```
- 같은 `actionCode`가 둘이면 기동이 실패한다.
- 실패는 `BusinessException`(또는 RuntimeException)으로 던지면 서비스가 `sys97_notice_log`에 남기고 그대로 전파한다.

## 이번에 하지 않은 것 (다음 ID로)
- `IcamBatchRunner`의 프로필 선택(`disabled`/`simulated`/`real`)은 ICAM 연계 ID에서 한다 — 지금 `DisabledIcamBatchRunner`만 있다.
- 03 원칙 1(asseterpdb만, 테이블 생성 금지) 때문에 ICAM 시뮬레이터용 `icam_sim` 스키마는 **사용자 승인이 필요**하다. ICAM 연계 ID 시작 전에 방식(별도 DB·스키마·메모리 시뮬레이터)을 사용자에게 다시 묻는다.
