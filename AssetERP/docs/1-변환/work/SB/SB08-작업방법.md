# SB08 BatchMain `alarm` — 작업방법

골격은 `SB01-작업방법.md`. 이 ID는 `BatchAction` 구현체 `AlarmAction`(`biz.batch.action`)다. 알림 규칙은 `biz.batch.notice.BatchNoticeService`(SB08~SB10 공유).

## AS-IS → TOBE
- 원본: `BatchMain.alarm L190-273` (`/BatchMain?actionCode=alarm`)
- 처리: 사용 중인 회사마다 `sch06_alarm.insertAlarmTarget`(알람 예정내역 sch07 생성) → 안 보낸 메일 알람(`selectByAlarmType("1")`, 알람 일시 >= 지금-1일, 전송일시 없음)마다 사원 이메일이 있으면 앱알림(제목 "알림", 본문 알람 메시지), 회사 메일 발송 설정이 켜져 있고 이메일이 있으면 `sch07_alarm_record.updateInfo`(보낸 곳·보낸 시각) + 메일(제목 "[알림] Asset-ERP")
- 호출: `GET·POST /api/v1/batch/alarm` (파라미터 없음)
- 결과 문구(그대로): `알람 메세지 전송 작업완료.. commit`
- **발송 시점**: AS-IS는 반복하다가 바로 보내서 뒤에서 롤백돼도 이미 간 알림은 돌이킬 수 없다. TOBE는 AA01과 같이 **커밋된 뒤** `NoticeSender`(`AprNoticeService.dispatchAfterCommit`)로 보낸다. 실패는 로그만(AS-IS도 예외를 삼킴).
- 앱알림은 수신 차단(`emp92_sms_notice`) 확인(`AprNoticeMapper.count*Blocked`), 메일·SMS는 회사별 발송 설정(`asseterp.notice.mail-companies`·`sms-companies`) 확인 — AA01과 같은 부품.

## SQL 이식
`BatchNoticeMapper.xml` — 원본 SQL 그대로(원본 위치는 파일 머리 주석). 알람 예정내역 생성(`insertAlarmTarget`, 300줄)과 `selectEmp` 조각은 본문 그대로, 다른 조회는 `SELECT *` 대신 쓰는 열만 적고 조건·정렬은 그대로, `flt10_tr.getTotalCount`는 목록 크기만 필요해 `COUNT(*)`로 바꿨다.
