## SQL 이식
- 4개 매퍼(`BmtInfoMapper`·`BmtHistoryMapper`·`BmtPcHistoryMapper`·`BmtRelateApprMapper`). 원본이 `bmt10_info.*`·`bmt11_history.*`처럼 `.*`로 뽑는 곳은 T20에서 같은 이름 열이 모호해진 전례가 있어 **그리드가 쓰는 열만 별칭으로 명시**했다(03 원칙 4 예외 아님 — 결과 열·행은 같다, `compare` 행 수 일치).
- 날짜 열 `bmt10_apply_date`·`bmt10_retire_date`·`apr01_reg_date`는 timestamp라 `::date`로 받는다(그리드는 `yyyy-MM-dd`).
- `selectByCompanyId`의 `checkYn == false` 가지(`:baseDate <= COALESCE(retire, 99991231)`)는 `<if test="!checkYn">`.
- 쓰기 SQL은 `UpdateDataModel`의 동적 INSERT/UPDATE/DELETE를 명시 SQL로 옮겼다(화면이 바꾸는 열만). **로그인 회사 조건을 UPDATE·DELETE·재조회에 더했다**(보안 보강, 이전 ID들과 같은 방식).
- `selectById`는 `person_name`을 NULL로 둔다(원본 `selectById`에 사용자 서브쿼리가 없다).

## 공통 절차와 다른 점
- (12 원칙·11 §4a) 편집창 3개의 폭을 AS-IS보다 넓혀(640·680) 스크롤을 피하고, 모달은 위에서 20만 띄웠다. 머리 아래 선·푸터 위 선·라벨 오른쪽 정렬은 EditModal 규격.
- 상세이력 창 삭제: 고른 행이 없으면 확인창을 띄우지 않고 아무것도 하지 않는다(원본은 빈 목록으로 서버를 부름).
- 수정 편집창에서 [삭제]한 뒤 원본은 `selectRetrieve(infoId)`로 그 행을 다시 읽으려 해 결과가 없다(NPE로 추정). TOBE는 목록에서 그 행을 뺀다.
- 전산장비 조회창(`Bmt10_Lookup_InfoList`)은 원본이 `searchText`를 보내지 않아 SQL의 `ILIKE NULL`이 되어 목록이 비는 것으로 보인다(원본 확인 불가 — 이상한점 #136). TOBE는 검색어 없음을 `%%`(전체)로 보낸다 → **원본과 다름, 사용자 승인 필요**.
- `Ast01_Lookup_ClassTree.search()`는 이름에 검색어가 든 모든 노드를 `select(…, keepExisting=true)`로 고른다(GXT 단일 선택이라 마지막 노드만 남음) → TOBE는 마지막 노드를 고른다.
