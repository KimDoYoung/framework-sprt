## 공통 절차와 다른 점
- 잠금 뒤의 PDF 생성은 AS-IS 클라이언트가 단계마다 서비스를 부르는 것을 서버가 한 번(`recreate`)에 하고 결과 코드로 분기를 돌려준다(`RD_FAILED` = lockRollBack 대상, `FILE_FAILED` = 멈춤). 같은 이유로 `Sys10_File.getServerPath`의 `filePath == null || startsWith("c:")` 검사는 서버 저장 경로 설정(`asseterp.upload.dir`)으로 대신한다
- 진행 창의 마지막 문구 "N개의 파일이 전부 잠금 및 생성이 완료되었습니다."는 일부가 실패해도(RD 실패 → 잠금 되돌림) 원본처럼 그대로 나온다 — 작업기록 "제안"
- 묶음 헤더·합계 행의 열 번호는 N19의 "확인 필요"와 같은 읽기(행번호 0번 포함)로 했다 — 합계 행은 딱 맞고 묶음은 완료~진행상태에 걸린다(작업기록)
