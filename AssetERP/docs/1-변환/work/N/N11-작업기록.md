## 원본과 다른 점 / 결정 (03 원칙 4·5)
- 인사정보 창 검색: AS-IS `KeyPress`는 아무 키나 누를 때 조회하지만 TOBE는 `SearchBar` 규칙(Enter/[조회]).
- 수정창 저장 뒤 창을 닫지 않는 것, 그리드 행만 바꾸는 것은 AS-IS(L270-287 `hide()` 없음) 그대로.
- 상신 아이콘의 "6월 22일 이후 상신" 확인(L144-168)은 `dayjs().isBefore('2026-06-22')`로 옮겼다(지금은 지난 날짜라 뜨지 않는다).
- `BeforeStartEdit`(E6)는 yunhee가 "도달 불가"로 표시했지만 `GridBuilder`가 `editing.addBeforeStartEditHandler`로 연결하므로 구현했다. AS-IS는 안내만 하고 편집은 막지 않아 그대로 안내만 한다(제안 참고).

## 제안 (03 원칙 5 — 승인 전 반영 안 함)
- **책무배분일 편집 차단**: 상신 진행·완료(10/20/30) 행의 책무배분일은 안내만 뜨고 실제로는 고칠 수 있다(AS-IS 그대로). 편집 시작을 막으면 안내 문구("수정할 수 없습니다")와 동작이 맞는다.
- **직책배정 삭제 시 tdm35 정리**: `Tdm30_RoleAllc.delete`는 tdm34만 지우고 tdm35(확정책무)는 남겨 고아 행이 쌓인다. 같이 지우면 좋다.
- **`current_setting('app.current_user')`**: AS-IS tdm35 INSERT·tdm02 UPDATE가 DB 세션 변수로 등록자를 넣는데 TOBE는 이 변수를 세팅하지 않아 `#{updName}`으로 바꿨다. 다른 매퍼에도 같은 SQL이 있으면 점검 필요.
- **부품 제안**: `dynamicIconCell`(값이 허용 목록일 때만 아이콘 — AS-IS `addDynamicCell` 일반형)이 `dynamicViewCell`(E13)과 합쳐 세 번째 사용 → `components/grid`로 올릴 후보.
- **RD 연동 전제**: 책무기술서 RD 뷰어(`rdApi.buildUrl`)는 `rv`의 `companyId`·`personId`를 로그인 값으로 덮어쓰는데(`RdService.rv`), AS-IS `viewRd`는 `personId`에 **임원의 personId**를, `reportPersonId`에 로그인 값을 넣는다. RD 대책 때 임원 값을 다른 키로 받는지 정해야 한다.
