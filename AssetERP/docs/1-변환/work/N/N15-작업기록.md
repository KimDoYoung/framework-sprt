## 원본과 다른 점 / 결정 (03 원칙 4·5)
- 저장 뒤 목록을 다시 조회한다(`reloadAfterSave`). AS-IS는 바뀐 행만 갱신하지만 새 행의 작성현황·완료여부 계산 열을 맞추려고 한 것.
- 새 행(ID ≤ 0)은 `has-duties`를 부르지 않고 PASS — TOBE의 임시 음수 ID는 서버에 없으므로.
- `createDuty`·`createDirectManl`은 화면의 모델 대신 id만 보내고 서버가 저장된 행을 읽는다(화면이 미저장 변경이 있으면 막으므로 값이 같다).
- `createDirectManl`은 서버도 관리자만 허용(AS-IS는 버튼 숨김만). 03 원칙 4의 예외가 아니라 "관리 화면 권한"(05 §6, A15) 전례.
- 매퍼에서 `current_setting('app.current_user')`를 `#{updName}`으로 바꿨고(`insertDuties`·`insertDutyOrgs`), DB 함수 `f_create_tdm_manual`은 `set_config('app.current_user', …, true)`로 같은 트랜잭션에 값을 넣는다 — TOBE는 이 설정을 하지 않아 함수가 만드는 행의 등록자가 비는 것을 막으려는 것이다(DB는 안 건드림).
- `f_create_tdm_manual`이 던지는 DB 예외는 AS-IS처럼 "매뉴얼 생성 실패. 관리자에게 문의하여 주십시오", 'Y'가 아닌 반환값은 그 문자열을 그대로 보여 준다.
- `[전체]`는 원본이 `callback.execute(null)` 뒤 닫는다(Tdm20 L162-167, Org00 L148-153). 처음에는 yunhee 이벤트 줄이 `→ hide()`로만 표시해 닫기로 구현했다가(결과확인 통과 후) N16 분석 중 원본을 열어 발견, 같은 날 `onAll` prop으로 고쳤다: 직책 [전체] = 직책 비움, 부서 [전체] = 부서 비움. 영향은 N15뿐(`allButton` 사용처가 N15만).
- 관리의무생성 버튼 등 3개는 `generate` type — yunhee는 `save`/미등록으로 표시했다.
