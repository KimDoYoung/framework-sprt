## 공통 절차와 다른 점
- **`f_get_tdmInsuffPossibleYn`이 이 DB에 없다**(`pg_proc`에 `f_get_tdm*`는 5개뿐, AS-IS 매퍼 `tdm54_chck_insuff.selectPossibleYn`만 부른다). 03 원칙 1상 만들 수 없어 사용자에게 물었고(2026-10-25) "검사 생략하고 진행"으로 정했다. 이 검사는 조치완료 시 "책무이행점검 승인 진행중입니다. 점검마감 후 완료하세요."를 내는 것(주석: 최종 점검년월의 승인요청 전까지만 조치완료 가능)이라, **그 사이에도 조치완료가 통과한다**. DB에 함수가 생기면 `TdmChckInsuffMapper`에 SQL 한 줄과 서비스 한 분기를 더하면 된다.
- 서버가 조치내역을 다시 읽는다. AS-IS는 화면 모델(`statusCode`·`companyId`·`chckInsuffId`·조치 열)을 그대로 믿었다 — TOBE는 ID와 조치 열만 받아 서버가 행·회사·상태를 정한다(정상 화면 흐름에서는 같은 값). 읽기 전용 판정(부서·상태)은 화면이 하고, 서버는 회사만 확인한다(AS-IS와 같다).
- 조치기록 저장 성공 메시지는 `useDeferredCrud.commit`의 "저장이 완료되었습니다"(AS-IS `GridUpdate`는 메시지 없음 — 05 §8 사용자 결정과 같은 방향).
