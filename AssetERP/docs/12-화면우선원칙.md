# 12. React 화면 우선 원칙 (준원칙)

사용자 결정(2026-10-30). **절대원칙(03)은 아니지만 그에 준해서** 화면(페이지·조회창·편집창)을 만든다. 03 원칙과 부딪히면 03이 이긴다(예: 원칙 12 "원본 화면이 정답"). 이 문서의 원칙으로 AS-IS의 모양이 달라지면 그 사실을 `{id}-작업방법`의 "공통 절차와 다른 점"에 적는다. 원칙 자체를 바꾸는 것은 사용자만 한다.
함께 쓰는 문서: 화면 배치 `page-style.md`(SID), 그리드 모양 `grid-style.md`(GID), 모달 모양 `modal-style.md`(MID), 공통 부품 사용법 `11-프론트부품.md`. 견본과 이 원칙이 어긋나면 견본을 이 원칙에 맞게 고칠지 사용자에게 묻는다(예: STP 견본의 안쪽 `padding 10`).

## Page
1. 스크롤이 생기지 않도록 margin과 padding을 조절한다.
2. box line이 여러 줄 생기지 않도록 한다. (선은 최소화 — 영역 구분은 배경색으로)
3. 여러 개의 label과 input이 있을 때 row와 row 사이 간격은 8 정도로 한다.
4. label과 input은 right 정렬을 우선으로 한다. label과 input box 사이 간격은 8 정도로 한다.
5. 페이지의 시작점, 즉 탭 안에 보이는 첫 번째 element의 위치가 left 20, top 20을 넘지 않게 한다.
6. 년도(yyyy)가 들어가는 입력의 폭은 80으로 한다.

## LookupModal / EditModal
1. header 아래 라인, footer 위에 라인을 둔다.
2. 최대한 스크롤이 생기지 않도록 한다. 모달 자체의 width·height를 늘리든지, grid인 경우 cell width를 줄인다.

## 적용 메모 (U18에서 확인한 것)
- 1·5: 안쪽 블록마다 `padding`을 겹쳐 두면 첫 요소가 20을 넘는다 — 바깥 여백 20만 두고 블록 사이는 `gap 8`.
- 2: 박스 두 개가 맞닿으면 테두리가 두 줄이 된다 — 음수 `margin`으로 겹치거나 한쪽 테두리를 뺀다.
- 그리드 수평 스크롤: 열 폭을 비율(`flex`) + 값·제목 길이로 계산한 최소 폭으로 쓴다(`grid-style.md` grid-SUM). 숫자가 잘리면 안 된다.
- 모달의 검색 줄이 줄바꿈되면 모달 폭을 키운다(문서분류 조회창 500 → 580).
- 구분이 필요한 영역은 선 대신 연한 배경색(`#f5f5f5`)을 쓴다. 선택 행의 색을 가리는 셀 배경은 쓰지 않는다.
- 이 원칙을 적용한 화면: U18 `Biz01_Tab_EntertmExpenseReport`, `Dcr30_Move_DcrClass`.
