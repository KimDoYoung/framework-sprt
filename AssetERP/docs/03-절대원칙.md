# 03. 절대원칙

어떤 지시·문서보다 우선한다. 원칙과 부딪히는 상황이면 작업을 멈추고 사용자에게 묻는다. 원칙을 바꾸는 것은 사용자만 할 수 있고, 바꾼 날짜와 이유를 아래 "변경 이력"에 남긴다.

## 데이터

1. **DB는 asseterpdb 하나만 쓴다.** 테이블·컬럼·함수·인덱스를 만들거나 바꾸지 않는다. 화면에 필요한 것이 DB에 없으면 그 ID는 `보류`하고 이유를 적는다.
2. **확인 작업은 데이터를 바꾸지 않는다.** 저장 API 시험은 같은 값 PUT처럼 결과가 원래와 같은 방식으로 하고, 시험용으로 만든 행은 그 세션 안에 지운다. 그 사실을 `{id}-결과확인`에 적는다.

## 원본

3. **원본을 통째로 읽지 않는다.** 색인(`docs/as-is/src`)에서 필요한 파일과 줄 범위를 찾고 그 줄만 연다. 색인에 없으면 색인을 다시 만들거나 grep으로 찾는다.
4. **AS-IS 동작을 그대로 옮긴다.** SQL, 그리드 컬럼의 순서·폭·제목, 버튼, 메시지, 처리 순서를 바꾸지 않는다. asseterpdb에서 SQL이 돌지 않아서 고치는 경우만 예외이며, 그때는 원래 SQL과 고친 이유를 `{id}-작업방법`에 남긴다.
5. **개선은 하지 않고 제안만 한다.** 더 나은 방법이 보이면 `{id}-작업기록`에 "제안"으로 적고 사용자 승인 전에는 반영하지 않는다.
12. **원본 화면이 정답이다.** AssetERP는 오래 유지보수·보완된 상용 서비스다. ① 테이블 CRUD가 이미 원본에서 동작하고 있고, ② 화면은 그리드 중심이다 — 그리드는 단순 보기(선택 → 하위 탭·팝업)와 편집 CRUD(셀 편집·행 추가·저장·삭제) 두 가지로 쓰인다.
    - TOBE는 새로 설계하지 않는다. 원본의 **레이아웃(툴바·그리드·하위 탭·분할), 버튼(개수·순서·문구), 이벤트(E0~En 전부), 그리드(종류·선택 방식·편집 컬럼·컬럼 순서/폭/제목), 메시지, 저장 SQL**을 그대로 따라간다.
    - 그리드 종류는 원본 `GridBuilder` 설정으로 정한다: `setChecked(...)` 없으면 단일 선택(`SingleGrid`), 있으면 체크박스(`MultiGrid`), 컬럼에 편집기 인자(`new TextField()` 등)가 있으면 셀 편집(`CellEditGrid`+`useGridCrud`). 행번호는 `setRowNumHidden(true)`가 아니면 보인다.
    - 결과확인에서 **클래스마다(탭·팝업 포함) 버튼 수·이벤트 수·그리드 수를 색인과 대조**한다(06 항목 10). 하나라도 모자라면 그 ID는 `완료`가 될 수 없다. 단계로 나눠 하는 경우에도 모자란 것은 대조표에 "다음 단계"로 남긴다.

13. **그리드 헤더 클릭 정렬은 만들지 않는다.** 사용자가 특별히 요청한 그리드만 정렬을 켠다. 공통 그리드(`BaseGrid`)의 기본은 `sortable=false`이다.

14. **UX보강(`10-UX보강.md`)은 원칙 4·5·12의 예외다.** 기능·데이터·SQL은 원본과 같게 두고, 10의 등록표에 `부품완료`로 등록된 항목만 **공통 부품으로만** 적용한다(화면마다 따로 넣지 않는다). 항목 추가·승인은 사용자만 한다 — 에이전트는 좋은 UX가 보이면 원칙 5처럼 `{id}-작업기록`에 "UX보강 제안"으로 적는다.

## TOBE

6. **패키지·네이밍·레이어는 `../../docs/TOBE-Framework.md`를 따른다** (`kr.co.kfs.asseterp`).
7. **OMS 코드를 복사하지 않는다.** `../../OMS`와 `../../docs/OMS-convert.md`는 비교와 참고만 한다. 참고한 경우 출처를 `{id}-작업기록`에 적는다.
   - 예외: 기반(B04~B08 — 로그인·프레임·공통 그리드·배포)은 OMS에서 가져온다. 범위는 `07-기반이식.md`의 표로만 정한다.

## 진행

8. **세션 하나에 ID 최대 3개(묶음 세션).** 묶는 조건: ① 01 "우선 순서"상 연속이거나 같은 도메인·같은 구조(예: 짝/복제 화면) ② 각 ID가 작다(클래스 1~2개, 새 API 3개 이하). 큰 화면(탭 3개+, 팝업 다수, 공통 부품 신설)은 단독 세션.
    - ID는 **순서대로 하나씩 끝까지**(작업방법→구현→결과확인→작업기록→01 상태) 마치고 다음으로 간다. 두 ID를 동시에 펼쳐 섞지 않는다.
    - 컨텍스트가 무거워지면(빌드 실패 반복, 재작업 2회+) 남은 ID는 다음 세션으로 넘긴다.
9. **기록이 끝나야 끝난 것이다.** 01의 상태, `{id}-작업기록`, `{id}-결과확인`을 갱신하기 전에는 다음 ID로 넘어가지 않는다.
10. **공통 방법은 공통 문서에서 고친다.** 여러 화면에 해당하는 절차·체크리스트를 바꿔야 하면 ID 파일이 아니라 05·06을 고치고, 공통 프론트 부품의 사용법은 11을 고치고, 고친 사실을 `{id}-작업기록`에 적는다.
11. **결과는 확인한 것만 적는다.** 실행하지 않은 확인을 "통과"로 적지 않는다. 못 한 항목은 `미확인`과 이유를 적는다.
15. **공통 프론트 부품은 `11-프론트부품.md`로 쓰고, 소스를 통째로 읽지 않는다.** 화면을 만들 때 쓰는 부품(그리드·훅·버튼·검색·폼·조회창)의 props·반환값·함정은 11에 있다. 부품 소스(`components/`·`hooks/`)와 참고 화면은 11에 없는 동작이 필요할 때만 `yunhee outline`·`analysis tobe`로 줄을 찾아 그 줄만 읽는다. 부품을 새로 만들거나 props·동작을 바꾼 ID는 **같은 ID 안에서** 11의 해당 절과 05 §5 등록표를 함께 고친다 — 하나라도 빠지면 그 ID는 `완료`가 될 수 없다(06 항목 12).

16. **조회창·팝업은 UX-05·06을 따른다. 팝업은 조회창(LookupModal)과 편집창(EditModal)으로 나눈다.** 검색해서 고르는 창(사원찾기 등)은 `LookupModal`, 값을 입력해 저장하는 편집창(`*_Edit_*`)은 11 §4a의 EditModal 규격(견본 `Chk02_Edit_DailyList`)으로 만든다. 사용자가 조회창을 열면 ① 안쪽 첫 번째 글자 입력칸에 **커서가 가 있고**(UX-05), ② 목록에서 **체크박스를 정확히 누르지 않아도 행 아무 곳이나 클릭하면 선택**된다(UX-06). 새 조회창·팝업은 모달을 antd `Modal`이 아니라 `LookupModal`로 쓰고, 체크박스 다중 선택 그리드는 `<MultiGrid rowClick>`으로 쓴다(단일 선택은 `SingleGrid`). 화면마다 `autoFocus`·`rowSelection`을 따로 넣지 않는다. 예외는 삭제·저장용 체크를 쓰는 CRUD 그리드 — 행 클릭이 삭제 대상을 바꾸므로 `rowClick`을 쓰지 않는다. 내용·부품 위치는 `10-UX보강.md` UX-05·06, 사용법은 11 §4를 본다.
17. **그리드 [등록]은 항상 맨 아래에 빈 행을 만들고, 필요하면 스크롤해서 보여 준다.** 원본 `GridInsertRow`의 기본은 선택 행 아래이지만(맨 아래 고정은 3개 화면뿐) 사용자가 맨 아래로 통일하기로 했다(IM-03, 원칙 5의 승인된 개선). 새 행은 선택하지 않고 `firstEditField`만 편집을 시작한다. 위치는 `useGridCrud`의 `insertAt`('last' 기본 / 'first' / 'afterSelected')로만 바꾼다 — 화면에서 행을 직접 끼워 넣지 않는다. `useGridCrud`를 못 쓰는 화면은 `setRows(prev => [...prev, row])` 뒤 `ensureIndexVisible`로 같게 한다.
18. **화면 레이아웃에서 스크롤바가 2개 생기지 않게 한다 — 높이를 `99%` 같은 값으로 줄여 피하지 않는다.** 테두리(`border`)나 `padding`이 있는 `div`가 `height: '100%'`이면 반드시 `boxSizing: 'border-box'`를 함께 쓴다(전역 리셋이 없어 `div`는 기본 `content-box`라, 테두리·여백만큼 부모보다 커져 antd `Splitter.Panel`(기본 `overflow: auto`) 같은 부모에 바깥 스크롤바가 생긴다). 여백은 원본 값(보통 20)을 유지한다. 화면 전체 높이는 뷰포트에 맞추고(no-scroll body) 스크롤은 그리드 안쪽 가상 스크롤만 남긴다. 확인은 화면을 열어 스크롤바가 하나도 없는지, 창 높이를 바꿔도 그리드 아래가 잘리지 않는지 본다. 그래도 남으면 `99%`로 줄이지 말고 부모에 `overflow: 'hidden'`이나 안쪽을 `flex: 1; min-height: 0`으로 바꾼다. 방법은 11 §5.

19. **정렬 collation은 AS-IS와 같은 `COLLATE "ko_KR.utf8"`를 쓴다.** AssetERP 운영 DB의 정렬이 ko_KR.utf8이므로 TOBE 매퍼도 같아야 결과 순서가 같다. `ko-KR-x-icu`로 바꾸지 않는다. 로컬 DB 설치는 05 §6, 기존 매퍼의 일괄 수정 목록은 `docs/work/collation-일괄수정.md`.
20. **그리드 셀은 모두 세로 가운데다.** AS-IS는 전 컬럼이 vertical center이므로 `BaseGrid`의 `vCenter`가 기본 true다(`.gb-vcenter`, `grid.css`). 가로 정렬은 셀의 `text-align`을 따른다. 화면마다 따로 정렬을 넣지 않고, 예외가 필요하면 `vCenter={false}`로만 끈다.
21. **조회창 모달 폭은 열 폭 합계로 손으로 정한다.** `gb.*` 열 폭 합계(행번호·선택 열 약 60 포함) + 안쪽 여백·스크롤바 약 130을 `width`로 쓴다. 합계가 약 1120을 넘으면 모달을 더 키우지 않고 스크롤을 허용한다. AS-IS 폭보다 작게 하지 않는다. 자동 계산 부품은 만들지 않는다(11 §4).
22. **모든 `_Tab_` 화면은 변환 때마다 page-style을 참조·비교한다.** ① 시작: `yunhee page-style <원본.java>`로 AS-IS SID를 확인하고 `docs/page-style.md`의 같은 SID 상세·견본(`docs/page-style/{SID}/`)을 본다. **page-style에 견본이 있으면 그 견본을 샘플(뼈대)로 삼아 화면을 만든다** — 같은 도메인의 다른 완료 화면을 먼저 베끼지 않는다. 견본에 없는 부분(원본 고유 요소)만 다른 화면·11 문서를 참고해 더한다. 견본을 열지 않고 만들었으면 그 ID는 `완료`가 될 수 없다. ② 표에 없으면(`미분류` 포함) **작업을 이어가기 전에 사용자에게 알리고** 새 SID로 표에 먼저 등록한다. ③ 확인: `yunhee page-style --compare <원본.java> <TOBE.tsx>`가 `일치`인지 본다(판별기가 `미분류`만 내는 새 스타일은 사유를 결과확인에 적는다). 결과는 `{id}-결과확인.md` 항목 13에 적는다. 하위 탭·팝업 클래스(`_TabPage_`·`_Lookup_`)는 대상이 아니다.
