# 반영 대장

AS-IS 변경 한 건 = 한 줄. 규칙(종류·상태·절차)은 `README.md`.
새 줄은 맨 아래에 붙인다. 지운 줄은 없다(잘못 넣었으면 `해당없음` + 비고).

## 칸

| 칸 | 쓰는 법 |
|:---|:---|
| 키 | `CH-0001`부터 차례로. 커밋 메시지에 쓴다 |
| 발견일 | 대장에 넣은 날 (`2026-11-11`) |
| AS-IS 커밋 | 짧은 해시 · 날짜 · 제목 앞부분 (`ff05be9ff 11-05 책무이행점검 증빙…`). 여러 커밋이 같은 단위를 바꿨으면 마지막 것 |
| 종류 | `DB` `SQL` `LOGIC` `MODEL` `UI` `NEW` `ETC` |
| 단위 | 파일 + SQL ID 또는 메서드. `sys99_print.xml#selectPrintList`, `Apr01_Appr.java#update()`, 화면 UI는 클래스명 |
| 변경 요약 | 무엇이 바뀌었나 한 줄 (`WHERE에 use_yn='true' 추가`) |
| 영향 화면 | 이 단위를 쓰는 화면번호(많으면 대표 3개 + 개수, 예 `#1029 #1033 #1452 외 12`). 번호 없는 공통부품은 여는 화면 번호 |
| TOBE 대응 | 고칠(고친) TOBE 파일·매퍼 id·메서드 |
| 상태 | `대기` `해당없음` `반영` `보류` `넘김` |
| 처리일 | 상태를 `대기`에서 바꾼 날 |
| 비고 | 해당없음·보류·넘김 이유, 확인 방법(`compare` 일치, 테스트 이름), TOBE 커밋 |
