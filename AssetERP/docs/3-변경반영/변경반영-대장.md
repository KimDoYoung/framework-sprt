# 변경반영 대장

AS-IS 변경 한 건 = 한 줄. 규칙(종류·상태·절차)은 `README.md`.
새 줄은 맨 아래에 붙인다. 지운 줄은 없다(잘못 넣었으면 `해당없음` + 비고).

## 칸

| 칸 | 쓰는 법 |

## 첫 대장 (2026-11-11)

- 범위: 기준선(`docs/baseline.json`, 완료 화면 421개, 기록 2026-10-16~11-05) → AS-IS `3aabbd415`(11-10). 색인도 같은 커밋.
- 만든 방법: `drift --all --done-only --base baseline -o json`의 바뀐 파일 129개를 AS-IS `git diff -w`의 hunk 단위로 **SQL ID·메서드**에 매달고, 화면 색인(서비스 → 서버 메서드 → SQL ID)과 AS-IS 호출(`mapperName + ".id"`, `<include refid>`, 클라이언트 `"dom.Class.method"` 문자열)을 따라 쓰는 화면을 찾았다. TOBE 대응은 TOBE 소스에서 AS-IS 이름(주석·같은 id)을 찾은 것(**후보** — 반영할 때 확인). 새 파일·DB 스크립트는 `git log --since=2026-10-16`. 스크립트는 수정사항054 `drift-unit`이 생기기 전의 임시 방편.
- 결과 248건:

  | 종류 | 대기 | 해당없음 |
  |:---|---:|---:|
  | DB (함수 스크립트) | 3 | |
  | SQL | 98 | 1 |
  | LOGIC | 47 | 6 |
  | MODEL | 29 | |
  | UI | 50 | |
  | NEW (새 파일) | 14 | |

- 대장 순서: 완료 화면이 쓰는 것(DB → SQL → LOGIC → MODEL → UI → NEW) → 쓰는 완료 화면을 못 찾은 것(CH 뒤쪽 `대기`, 비고 "확인 필요"·"완료 화면 밖") → 자동 `해당없음`.
- **drift가 놓친 것 39건**(비고 "drift가 못 잡음"): 완료 화면이 실제로 쓰는데 색인의 그 화면 파일 목록에 없어 `drift`가 "동일"로 본 것. 원인은 색인이 `new ServiceRequest("…")`·변수에 담은 서비스 이름 호출을 못 따라감 → 수정사항054에 보탤 것.
- 공통 파일 잡음이 걸러진 예: `apr01_appr.xml`은 95화면을 "변경"으로 만들었지만 실제 단위는 SQL 몇 개, `Sys99_Print.java`는 출력 메서드 몇 개.
- 메뉴 번호가 없는 새 화면(`Sys55_Tab_MenuGuideCompany` 등)은 로컬 DB(`sys06_menu`)에 아직 메뉴가 없는 것.
