# ORG-BZ-0003 조직을 다른 상위 조직 밑으로 옮긴다 (조직개편)

> **한 줄 요약** — 조직개편으로 `운용관리팀`이 운용본부에서 경영지원본부로 간다. 고객사 관리자가 #1028 이력 창에서 **[상위조직변경]**으로 새 상위 조직을 고르고, **새 변경일**로 저장한다. 이력이 한 줄 더 생기므로 그 날짜 전에는 옛 본부 밑에, 그 날부터는 새 본부 밑에 보인다.

| 항목 | 내용 |

| 누가 | 고객사 관리자 — `kalpa/admin/1111` |
| 언제 | 조직개편 때 |
| 먼저 있어야 하는 것 | ORG-BZ-0001(옮길 조직과 새 상위 조직) |
| 다음 이벤트 | 소속 직원 발령은 EMP 쪽(조직을 옮겨도 직원 발령은 그대로 그 조직을 가리킨다) |
| 실제 실행 | kalpa, 2026-11-10 — 시험 팀 `10210 운용관리팀`을 2026-11-12자로 경영지원본부 밑으로 옮긴 뒤 ORG-BZ-0005로 지움 |

## 업무 규칙 · 주의

- 변경일을 원래 이력과 **같게 두고 저장하면 옛 이력이 덮여** 처음부터 새 본부 소속이었던 것처럼 된다(ORG-BZ-0002의 규칙과 같다). 개편이면 새 날짜로 저장한다.
- 이동 창에서 **지금 상위 조직과 같은 조직**을 고르면 "동일한 조직은 등록할 수 없습니다".
- ⚠ 원본도 같음 — **자기 자신(또는 자기 하위 조직)을 상위로 고르는 것은 막지 않는다.** 원본 검사(`Org02_Edit_Info` L105-114)는 "지금 상위와 같은가"만 보고, 서버도 상위 조직이 이 회사에 있는지만 본다. 자기 자신을 고르고 저장하면 그 날짜부터 그 조직이 트리에서 **사라진다**(루트에서 내려가는 트리에 걸리지 않음). 실행에서 확인했고(`PUT`이 200, 2026-11-11 기준 트리에서 빠짐), 그 이력을 지워 되돌렸다(ORG-BZ-0005 "이력 삭제"). TOBE는 원본 그대로 두었다 — 막을지는 재설계 대상.
