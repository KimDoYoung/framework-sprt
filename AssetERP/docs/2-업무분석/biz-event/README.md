# 업무 이벤트(BizEvent) — 무슨 일이 생기면 어느 화면에서 무엇을 하나

AssetERP 업무를 **화면 단위가 아니라 "현실에서 일어나는 일"(비즈니스 이벤트) 단위**로 정리한다.
"이 화면이 왜 비어 있지?"의 답은 대개 "앞선 이벤트가 아직 안 일어났다"이다. 이벤트를 차례로 따라 하면 데이터가 생기고 화면이 채워진다.

- ID: `{도메인}-BZ-{4자리}` (예: `SYS-BZ-0001`). 도메인 안에서 업무가 일어나는 순서로 번호를 매긴다. 지운 번호는 다시 쓰지 않는다.
- 진행: 도메인을 하나씩 한다. SYS 이벤트 목록과 ORG·EMP 첫 이벤트까지 정리했다(2026-11-09). SYS 0001~0022(2026-11-10), ORG 0001~0005, EMP 0001~0014(2026-11-10)을 실행했다. EMP 0015~0024는 1차 목록이다. kalpa에는 EMP 업무 메뉴 29개를 2026-11-10에 열었다(S1 상품엔 없음) — [EMP 흐름도](EMP/EMP-업무흐름.md#가상-회사-kalpa의-메뉴-범위) SYS 권한(0004~0006)까지 실행했다. 다음은 직원이 쓰는 업무 도메인(예: 근태·결재).
- 무대: 가상 회사 **kalpa · kova · igo**(각 회사 관리자 `admin`/`1111`, 직원은 `사번`/`Kalpa1234!` — 직원 비밀번호는 본인이 설정해야 하므로 `1111`이 아니다. [규칙](../README.md#비밀번호-규칙-2026-11-09-결정). 직위 사장·부장·과장·사원). 이벤트를 실제로 돌려서 회사를 만든다. 처음부터 다시 하려면 `tools/delete-company-db-data.sh <회사ID> --all`(먼저 `tools/db_dump_backup.sh`).

## 읽는 법

지나온 이벤트(ID·이름·실행 상태)와 시나리오 SNRO-001은 [`00-이벤트대장.md`](00-이벤트대장.md)에 고정해 둔다.

| 파일 | 내용 |
|:---|:---|
| 이 README | 이벤트 목록(아래 표) |
| [`00-이벤트대장.md`](00-이벤트대장.md) | 실행해 본 이벤트의 ID·이름 표와 시나리오 SNRO-001(회사 개설) |
| [`00-도메인Map.md`](00-도메인Map.md) | 도메인 사이 흐름 — "이 도메인이 비어 있으면 어느 도메인부터" |
| `{DOM}/{DOM}-업무흐름.md` | 그 도메인 안의 이벤트 흐름도, 화면번호 → 이벤트 찾기 |
| `{DOM}/{ID}-{사건}.md` | 이벤트 상세: 누가·먼저 있어야 할 것·따라 하기(화면번호·버튼·그림)·DB에 남는 것·결과가 보이는 화면·규칙 |
| `{DOM}/img/` | 상세 문서의 화면 그림(`yunhee screen-capture`로 찍은 것) |

로그인 표기는 `회사/아이디/비밀번호`다. 회사는 주소의 서브도메인이다: `admin/admin/1111` = http://admin.localhost:8082/AssetERP 에서 admin·1111.

```bash
cd AssetERP/backend && yunhee run "gradle test --tests '*Bz*'"
```
