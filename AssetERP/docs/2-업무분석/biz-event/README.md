# 업무 이벤트(BizEvent) — 무슨 일이 생기면 어느 화면에서 무엇을 하나

AssetERP 업무를 **화면 단위가 아니라 "현실에서 일어나는 일"(비즈니스 이벤트) 단위**로 정리한다.
"이 화면이 왜 비어 있지?"의 답은 대개 "앞선 이벤트가 아직 안 일어났다"이다. 이벤트를 차례로 따라 하면 데이터가 생기고 화면이 채워진다.

- ID: `{도메인}-BZ-{4자리}` (예: `SYS-BZ-0001`). 도메인 안에서 업무가 일어나는 순서로 번호를 매긴다. 지운 번호는 다시 쓰지 않는다.
- 진행: 도메인을 하나씩 한다. **지금은 SYS만** 정리했다(2026-11-09). 다음은 ORG(조직) → EMP(사원).
- 무대: 가상 회사 **kalpa · kova · igo**(각 회사 관리자 `admin`/`1111`, 직위 사장·부장·과장·사원). 이벤트를 실제로 돌려서 회사를 만든다. 처음부터 다시 하려면 `tools/delete-company-db-data.sh <회사ID> --all`(먼저 `tools/db_dump_backup.sh`).

## 자동 시험

이벤트 상세 끝의 `시나리오 데이터`(yaml)와 같은 순서로 서비스를 부르는 시험이 `backend/src/test/java/kr/co/kfs/asseterp/biz/scenario/`에 있다. asseterpdb에서 실제로 쓰고 끝나면 롤백한다.

```bash
cd AssetERP/backend && yunhee run "gradle test --tests '*Bz*'"
```
