# APR-BZ-0002 결재자가 결재문서를 승인·반려한다

> **한 줄 요약** — 결재 차례가 된 결재자(또는 합의자)가 결재문서를 열어 [승인](의견 입력) 또는 [반려](사유 입력)를 누른다. **결재선 순서대로**만 진행되고, 모든 결재·합의가 승인되면 문서는 `완료(30)`, 한 명이라도 반려하면 `반려(40)`가 된다. 차례가 아닌 사람·참조자는 단추가 꺼진다. 앞 결재자는 다음 사람이 처리하기 전까지 [승인취소]를 할 수 있다.

| 항목 | 내용 |
|:---|:---|
| 누가 | 결재선의 결재자·합의자(부장 `kalpa/201`·`202`, 사장 `kalpa/100`), 참조자(과장 `302`)는 열람만 |
| 언제 | 수시 |
| 먼저 있어야 하는 것 | APR-BZ-0001(상신된 문서) |
| 다음 이벤트 | 완료(30) → 업무 화면이 결과를 쓴다(휴가 잔여 등). 반려(40) → APR-BZ-0003 |
| 실제 실행 | kalpa, 2026-11-12, API. 화면 눈 확인 `대기` |
| 메뉴 | 결재문서 창(#1018 결재내역에서 문서를 연다). 합의·참조는 같은 창 |

## 업무 규칙 · 주의

- **차례**: 상신자 다음부터 seq 순서대로. 앞 단계가 `대기`면 다음 사람은 [승인]·[반려]가 꺼진다. 서버 [승인] 호출도 `canConfirm`을 다시 확인한다(`confirmCheck` 먼저 → 결재의견 창).
- **같은 사람이 이어서 나오면 한 번에**: 002·003이 둘 다 부장(201)인 문서에서 201이 승인하자 두 줄이 함께 `승인(20)`이 됐고 004(사장)만 대기였다(문서 `결재중(20)`). 합의는 다른 사람이 끼면 거기서 멈춘다.
- **문서 상태 계산**: 결재·합의·인감 줄 중 `대기`가 있으면 20, `반려`가 있으면 40, 모두 승인이면 30. **[승인취소]로 모두 대기로 돌아가도 문서 상태는 `결재중(20)`으로 남는다**(원본 `clearApprStepId`도 단계만 고침 — 같음).
- [승인취소]는 내 뒤 사람이 아직 처리하지 않았을 때만(`nextTurnCheck`), [승인]은 앞 사람이 취소하지 않았을 때만("이전 결재권자의 결재가 취소되어 결재를 진행할 수 없습니다.").
- 완료·반려 문서에는 결재 단추가 없다. 완료 문서에는 "추가정보·열람자 지정", 반려 문서에는 폐기 신청(APR-BZ-0003)이 열린다.
- 인감(40) 단계·대결자는 이번에 안 다뤘다(대결은 APR-BZ-0005).
- ⚠ 서버는 열람 권한을 보지 않는다 → APR-BZ-0001 후보 B. 결재선 위조는 후보 A.
- 안 한 것: 화면 눈 확인, 인감 단계 승인, 대결 승인, 결재선 수정·오타수정 단추, 결재의견(댓글), 공람 지정, 승인 후 알림 실제 도달, 광고심사 광고대장 기록.
