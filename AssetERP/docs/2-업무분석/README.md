# 업무분석

## 개요

- 업무분석이란 ASIS의 소스를 분석하여 각 도메인별 업무의 흐름을 분석한 후 그것이 TOBE에 적절히 적용되었는지를 판단한다.
- 업무분석 결과 TOBE의 구현이 적절하지 않은 경우 이를 판별하여 사용자에게 문서로서 보고를 한다.
- 보고는 명확하게 시나리오를 갖고 보고되어야 한다.
- 보고는 UI의 흐름과 DB의 변경을 함께 보고되어야 한다.


## 파일 및 폴더

- 파일들
    - README.md : this file, '업무분석' task에 대한  전반적인 설명
- 폴더들

    - biz-event : 업무를 "현실에서 일어나는 일"(비즈니스 이벤트, ID `SYS-BZ-0001` 꼴) 단위로 정리한 시나리오. 이벤트 목록·도메인별 흐름도·이벤트 상세(따라 하기·DB에 남는 것·그림)와 자동 시험(`backend/src/test/.../biz/scenario/`). 도메인 하나씩 진행(2026-11-09 SYS부터). 읽는 법은 그 폴더 `README.md`

## 가상의 회사를 생성하여 시나리오를 만든다.

- kalpa,kova,igo 3개의 id로 가상의 회사를 만든다.
- 3회사의 admin 계정은 admin/1111이다.
- 3회사는 사장, 부장, 과장, 사원 4계층으로 한다(아래 "직원·조직·메뉴 규칙").

### 직원·조직·메뉴 규칙 (2026-11-09 결정, kova·igo에 적용)

가상 회사는 **직급 4개**(사장·부장·과장·사원)만 둔다. 사번에 직함을 넣는다.

| 사번 | 직함(직위/직책) | 이름 | 소속 |
|:---|:---|:---|:---|
| 100 | 사장 / 대표이사 | 김사장 | 회사 |
| 201 | 부장 / 본부장 | 박부장 | 경영지원본부 |
| 202 | 부장 / 본부장 | 정부장 | 운용본부 |
| 301 | 과장 / 팀장 | 김과장 | 경영지원본부 |
| 302 | 과장 / 팀장 | 박과장 | 운용본부 |
| 401 | 사원 / 팀원 | 김사원 | 경영지원본부 |
| 402 | 사원 / 팀원 | 최사원 | 운용본부 |

- 사번 규칙: 직함 번호(`1xx` 사장 · `2xx` 부장 · `3xx` 과장 · `4xx` 사원) + 순번. 직원 7명, 조직은 회사 1 + 본부 2(경영지원본부 10100, 운용본부 10200).
- 메뉴 출발지: **가장 작은 회사 `prod_s1`**(SYS-BZ-0003 메뉴 복사). 상품 코드 `S1`. 관리자 `admin` 메뉴 59개, 직원은 사원 12개·사장·부장 15개·과장 30개(2026-11-09).
- 권한: 권한그룹 `임원`(경영관리 > 조직 및 사원관리 메뉴 5개)을 사장·부장에게, 과장에게는 `경영 관리자`를 준다. 사원은 기본권한(`일반 사용자`)만.
- 회사: `kova` (주)코바 220-81-22222, `igo` (주)아이고 220-81-33333. 한 번에 만들기: `tools/create-virtual-company.sh <회사ID> "<회사명>" <사업자번호>`(먼저 `tools/db_dump_backup.sh`, 다시 만들려면 `tools/delete-company-db-data.sh <회사ID> --all`).
- **kalpa는 예외다.** 규칙을 정하기 전에 만들어서 출발지가 전체 메뉴를 가진 시험 회사 `kfstest`(메뉴 656개, 관리자 395개)이고 사번이 1001·1101…이다. 같은 규칙으로 맞추려면 kalpa를 지우고 다시 만든다.

### 비밀번호 규칙 (2026-11-09 결정)

| 계정 | 비밀번호 | 이유 |
|:---|:---|:---|
| 각 회사 관리자 `admin` (`sys02_user`, KFS admin이 SYS-BZ-0002에서 발급) | **`1111`** | 관리자 계정은 비밀번호 규칙을 거치지 않는다 |
| KFS 관리자 `admin/admin` | **`1111`** | 〃 |
| 직원(사원, 사번으로 로그인) | **`Kalpa1234!`** | 직원은 등록해도 비밀번호가 비어 있어(`PASSWORD_INIT_REQUIRED`) **본인이 설정해야** 로그인된다. `f_password_rule`이 `1111`을 거부한다(8자리 이상·반복문자 2회 제한; 영문+숫자 10자리 이상 또는 영문+숫자+특수문자 8자리 이상) |

- 직원 비밀번호는 SYS-BZ-0012(비밀번호 초기화·설정)에서 `POST /api/auth/password/change`로 정한다. 시험용 지름길(DB에 `sys25_password` 직접 입력)은 쓰지 않는다.
- `Kalpa1111!`는 쓸 수 없다(`1111` 반복문자 → "반복문자는 2회로 제한됩니다.", 2026-11-09 실행으로 확인). 같은 형태로 규칙을 통과하는 `Kalpa1234!`로 정했다.
- 회사 이름이 kova·igo여도 직원 비밀번호는 `Kalpa1234!`로 같다(외우기 쉽게).
