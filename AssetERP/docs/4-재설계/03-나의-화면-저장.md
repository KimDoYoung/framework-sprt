# 03 나의 화면 저장 (구현 2026-11-11, 화면 확인 대기)

> **구현에서 계획과 달라진 점**
> - TopBar의 옛 "화면 레이아웃"(브라우저 저장)·"글꼴" 버튼을 지웠다(사용자 지시). 아이콘은 화면번호 칸 **앞**. 옛 메뉴의 "기본 레이아웃으로 초기화"도 함께 없어졌다.
> - 조회 응답은 `{ presets: [...], props: {...} }`(목록을 바로 준다). 저장 응답은 저장한 목록.
> - 같은 이름 덮어쓰기는 확인창 대신 **패널 안 안내 + [덮어쓰기] 버튼**(팝업 위 팝업을 피함). 삭제도 행 안에서 "삭제할까요? [예][아니오]".
> - `PUT …/me/props`는 만들지 않았다(사용자 설정 탭 때).
> - (2026-11-11 2차, 사용자 확인 후) 아이콘을 화면번호 입력칸 **안 맨 오른쪽 동그라미**로 옮김(패널 열림 중엔 툴팁 숨김). **이름 바꾸기**(연필 아이콘, 행 안에서 Enter 확인·Esc 취소) 추가 — §7 "나중에"에서 당김. 복원할 때 성공 메시지는 띄우지 않는다(빠진 화면이 있을 때만 안내).
> - **버그(치명)·수정**: antd Popover는 닫힐 때 내용을 마지막 모습(open=true)으로 붙잡아 두어, 패널을 한 번 연 뒤에는 패널의 키 처리기가 남아 `Esc`·숫자키(숫자패드)를 전역에서 가로챘다 → Popover `destroyOnHidden` + 처리기에서 실시간 열림 여부(`liveOpenRef`) 확인.
> - 파일: backend `SysUserPropsController`·`SysUserPropsService`·`SysUserPropsMapper`(+xml)·dto `UserPropsRes`·`UserPropsRow`·`MyScreenPreset`·`MyScreenLayoutSaveReq`, frontend `api/userProps.ts`·`components/MyScreenPanel.tsx`·`TopBar.tsx`·`MainFrame.tsx`(`getCurrentLayout`·`applyMyScreen`).

AS-IS에는 없다. 지금 열어 둔 탭·분할 배치를 이름 붙여 저장하고, 목록에서 골라 한 번에 복원한다(증권 HTS의 "화면 저장"과 같다).
사용자가 다른 앱(kiwi8)에서 이미 구현해 쓰던 기능을 옮긴다. 2026-11-11 사용자 결정.

## 1. 결정 사항

| 항목 | 결정 |
|:---|:---|
| 이름 | **나의 화면 저장** |
| 대상 | **로그인한 모든 사용자** (사원·회사관리자·KFS 관리자) |
| 저장 위치 | 서버 DB — 새 테이블 `sys90_user_props` (사용자당 1행) |
| 여는 방법 | TopBar 화면번호 칸 **바로 옆 아이콘 버튼** + **`F9`** |
| 개수 | 한 사람당 최대 10개 (`1`~`9`, `0` 바로 선택) |
| 라이브러리 | 쓰지 않는다 (antd·flexlayout 그대로) |

### AS-IS 테이블을 쓰지 않고 새 테이블을 만드는 이유
- 사원 개인 화면 설정을 담는 AS-IS 테이블이 없다. `emp01_person`에 개인 설정 열(`emp01_theme_cd`, `emp01_menu_fix_yn`)이 있지만 짧은 코드값뿐이다.
- `emp01_person`에 열을 붙이면 안 된다: 트리거 `emp01_person_backup()`이 **행이 바뀔 때마다** `empbak01_person`에 행 전체를 복사한다 → 화면 배치를 저장할 때마다 인사 변경 이력이 쌓인다.
- `sys02_user`는 회사관리자 전용이라 사원이 없다.
- Strangler Fig 동안 AS-IS가 같은 DB를 쓴다. AS-IS가 모르는 새 테이블은 AS-IS에 영향이 없다.
- 메모리 원칙 "AS-IS 테이블 사용"은 AS-IS에 있는 업무 데이터에 대한 것이다. 이 기능은 AS-IS에 없는 재설계 기능이라 예외.

## 2. 테이블

```sql
-- docs/4-재설계/ddl/sys90_user_props.sql (TOBE가 추가한 테이블의 DDL은 이 폴더에 둔다 — 새 관례)
CREATE TABLE sys90_user_props (
    sys90_user_id           numeric      NOT NULL,   -- 세션 userId: 사원 emp01_person_id(양수), 회사관리자 -sys02_user_id(음수)
    sys90_company_id        numeric      NOT NULL,   -- 회사ID (참고·정리용)
    sys90_my_screen_layout  text,                    -- JSON: 나의 화면 저장 목록
    sys90_props             text,                    -- JSON: 그 밖의 사용자 설정 (TopBar 배경색, 글꼴 …) — 사용자 설정 탭에서 채운다
    sys90_reg_dt            timestamp    NOT NULL DEFAULT now(),
    sys90_upd_dt            timestamp    NOT NULL DEFAULT now(),
    CONSTRAINT sys90_user_props_pk PRIMARY KEY (sys90_user_id)
);
COMMENT ON TABLE  sys90_user_props IS '사용자 설정 (TOBE)';
COMMENT ON COLUMN sys90_user_props.sys90_user_id          IS '세션 사용자ID (사원 emp01_person_id, 회사관리자 -sys02_user_id)';
COMMENT ON COLUMN sys90_user_props.sys90_company_id       IS '회사ID';
COMMENT ON COLUMN sys90_user_props.sys90_my_screen_layout IS '나의 화면 저장 (JSON)';
COMMENT ON COLUMN sys90_user_props.sys90_props            IS '사용자 설정 (JSON)';
```

- 키는 `UserPrincipal.userId`(`biz/auth/dto/UserPrincipal.java:20`, `LoginAccount.sessionUserId()`)를 그대로 쓴다 — 사원은 양수, 회사관리자는 음수라 겹치지 않는다. 시퀀스가 필요 없다.
- KFS 관리자가 admin 테넌트에서 다른 회사를 골라도 `userId`는 같으므로 자기 목록을 그대로 쓴다.
- JSON을 DB 안에서 검색할 일이 없어 `jsonb`가 아닌 `text`.
- 행은 처음 저장할 때 만든다(`INSERT … ON CONFLICT (sys90_user_id) DO UPDATE`). 행이 없으면 빈 목록.

### `sys90_my_screen_layout` JSON

```json
{
  "version": 1,
  "presets": [
    { "name": "3계좌와 종목상세", "model": { "...": "flexlayout Model.toJson()" }, "savedAt": "2026-11-11T09:30:00+09:00" },
    { "name": "관심종목", "model": { } }
  ]
}
```

- 배열 순서 = 목록 순서 = 바로 선택 번호(1번째 → `1` … 10번째 → `0`).
- `model`은 지금 브라우저에 자동 저장하는 값(`MainFrame.tsx`의 `appSettingsStorage.set('flexlayout_model', newModel.toJson())`)과 같은 형식 → 복원 코드를 같이 쓴다.
- `version`은 나중에 형식이 바뀔 때를 위해 둔다.

## 3. 동작

### 목록 (아이콘 클릭 또는 `F9`)
kiwi8 그림과 같은 드롭다운 패널: 제목 "나의 화면" · 오른쪽 위 **[현재 배치 저장]** · 번호 붙은 목록 · 행에 마우스를 올리면 휴지통 · 맨 아래 안내 `↑↓ 이동 · Enter 적용 · 1-9,0 직접 선택`.

| 키·동작 | 결과 |
|:---|:---|
| `↑`·`↓` | 선택 이동 |
| `Enter` 또는 행 클릭 | 그 배치로 복원하고 목록 닫기 |
| `1`~`9`, `0` | 그 번호로 바로 복원 |
| 휴지통 | 확인 후 삭제 ("'관심종목'을 삭제할까요?") |
| `Esc` / 바깥 클릭 | 닫기 (키보드 계획 04의 Esc 양보 규칙 — 목록이 먼저 쓴다) |
| `F9` (목록이 열린 상태) | 닫기 (토글) |

### 현재 배치 저장
- 이름 입력 칸(기본값: 지금 활성 탭 제목) → 저장.
- 같은 이름이 있으면 "덮어쓸까요?" 확인 후 그 자리(번호 유지)에 덮어쓴다. 새 이름이면 목록 끝에 추가.
- 이미 10개면 "10개까지 저장할 수 있습니다. 하나를 지운 뒤 저장하세요."
- 이름: 앞뒤 공백 제거, 1~30자.

### 복원
- 지금 열린 탭을 모두 닫고 저장된 배치로 바꾼다(MyPage 탭은 늘 유지). 확인창은 띄우지 않는다 — 고른 것 자체가 의사표시.
- **권한이 빠진 화면은 열지 않는다**: 저장 후 메뉴 권한이 바뀌었거나 화면이 없어졌을 수 있다. 지금 사용자 메뉴에 있는 탭만 남기고, 빠진 것이 있으면 `열 수 없는 화면 N개는 빠졌습니다` 안내. (백엔드 API는 따로 권한을 검사하므로 보안이 아니라 사용성 문제)
- 복원 결과는 지금처럼 브라우저 자동 저장에도 반영된다(다음 접속 시 마지막 배치).

### 서버 저장 실패
저장·삭제 API가 실패하면 목록을 바꾸지 않고 오류 메시지. 목록은 열 때마다 서버에서 다시 읽는다(사무실·집 PC 간 일치).

## 4. 구현 위치

### backend (`kr.co.kfs.asseterp.biz.sys`)

| 무엇 | 이름 |
|:---|:---|
| 컨트롤러·서비스·매퍼 | `SysUserPropsController` · `SysUserPropsService` · `SysUserPropsMapper` (+ `mapper/sys/SysUserPropsMapper.xml`) |
| 조회 | `GET /api/v1/sys/user-props/me` → `{ myScreenLayout: {...}, props: {...} }` (행 없으면 빈 값) |
| 나의 화면 저장 | `PUT /api/v1/sys/user-props/me/my-screen-layout` — 본문 = `presets` 배열 전체. 서비스에서 10개·이름 중복·이름 길이 검사 후 upsert |
| 사용자 설정 | `PUT /api/v1/sys/user-props/me/props` — 이번에는 API 자리만(사용자 설정 탭에서 쓴다). 만들지 여부는 구현 때 판단 |

- 대상 사용자는 **항상 토큰의 `userId`** — 요청 본문·경로로 다른 사람 ID를 받지 않는다(남의 설정을 고칠 수 없게).
- 저장 크기 제한: `my_screen_layout` 본문 1MB 초과 거부(배치 10개 기준 넉넉).
- `ApiResponse<T>`, `BusinessException`, DTO는 record — `docs/TOBE-Framework.md` 규칙대로.
- 동시 저장(두 PC)은 나중 것이 이긴다. `upd_dt` 비교는 1차에서 뺀다.
