# 01v. 변환목록 (전자결재 편집창 `Apr01_Edit_ApprDoc`: Apr)

`01u-변환목록.md` 다음, `01w-변환목록.md` 앞에 놓이는 상태판이다(사용자 결정 2026-10-30). 상태는 ID가 속한 파일에만 적는다. ID는 `V` 접두사(V01~V04) — 01a~01z 중 안 쓴 유일한 글자다.
ID 하나의 기록은 `work/{ID 첫 글자}/{id}-작업방법.md`, `…-작업기록.md`, `…-결과확인.md`(예: V01 → `work/V/`).

- 상태: `대기` → `분석` → `백엔드` → `프론트` → `확인` → `완료`, 또는 `보류`(사유를 비고에).
- **다음 작업은 아래 표에서 상태가 `대기`인 첫 줄**. 이 표는 메뉴 화면이 아니라 **창**(`Apr01_Edit_ApprDoc`)이라 `화면번호`가 없다(—). 이 창을 여는 화면은 emp·fnd·flt·sys·ics·act 등 20여 곳이며 지금은 모두 "다음 단계" 안내다(`grep -rl Apr01_Edit_ApprDoc frontend/src`).
- **왜 나눴나** (W05 2단계 ⓓ 분석, `work/W/W05-작업기록.md`): 클래스 52개(본체 5864줄·버튼 21·이벤트 35, `Apr03_Page_Relate` 2181줄·이벤트 23·그리드 6, 하위 창 40여 개). 문서를 열면 내 차례 판정으로 [승인][반려][상신취소][삭제] 같은 쓰기 단추가 상태·사용자별로 켜지므로 읽기 전용만 따로 떼면 AS-IS와 달라진다(03 원칙 4·12). 본문은 `Com10_FormMapping.selectByLinkCode`로 링크코드마다 HTML을 만든다(`getHtmlContent` 계열 20여 종).
- 각 ID는 **단독 세션**(03 원칙 8). 앞 ID가 `확인` 이상이어야 다음으로 간다. 하위 클래스는 `yunhee analysis screen Apr01_Edit_ApprDoc --list`로 나눠 각 ID에 배정하고, 분석 때 이 표 비고에 클래스 목록을 적는다.
- 재사용: 연관문서 창·불러오기 창·문서분류 확인 창(W05 ⓑ·ⓒ), 문서분류 선택 `Dcr30_Move_DcrClass`, 연관펀드/일임 API `apr/apprs/{id}/relate-funds·relate-advs`, 도장 `Apr10_*` 조회창, 인감·날인 `Apr16_*`.
