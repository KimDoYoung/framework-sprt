# 01w. 변환목록 (고유자산·예금관리: Ast/Sch/Bmt/Act)

`01u-변환목록.md` 다음에 이어지는 상태판이다. 상태는 ID가 속한 파일에만 적는다. ID는 `W` 접두사(W01~W23)로 01a~01u의 다른 접두사와 겹치지 않는다.
ID 하나의 기록은 `work/{ID 첫 글자}/{id}-작업방법.md`, `…-작업기록.md`, `…-결과확인.md`(예: W03 → `work/W/`).

- 상태: `대기` → `분석` → `백엔드` → `프론트` → `확인` → `완료`, 또는 `보류`(사유를 비고에).
- **다음 작업은 아래 표에서 상태가 `대기`인 첫 줄**(01a~01u가 끝난 뒤). 순서는 사용자 지정(2026-10-29).
- **화면번호 열**: 사람들은 화면번호로 소통하므로 `sys06_menu.sys06_menu_no`(4자리)를 `화면번호` 열에 적는다.
- 묶음은 사용자가 준 목록의 빈 줄 기준으로 1개이다: `W01~W23`. 순서는 사용자가 준 목록 순서 그대로다.
- 패키지는 도메인별(클래스 접두사 기준, 예: `biz.emp`, `biz.ast`). 소스 색인은 `{도메인}/screens/`. 하위 클래스(팝업·조회창)는 분석 단계에서 `yunhee analysis screen <화면> --list`로 확인해 같은 ID에서 함께 한다. 다른 도메인 컴포넌트(예: 전자결재 편집창 `Apr01_Edit_ApprDoc`)는 링크만 있으므로 **1단계만** 할지 분석 때 정한다.
- 같은 클래스가 여러 메뉴에 걸리면 나머지는 비고에 적고, 결과확인 항목 9(메뉴 여러 개)에서 같이 확인한다.
- 이 목록은 사용자가 준 클래스 목록을 `sys06_menu`에서 찾아 만들었다(2026-10-29, 23개, 전부 사용 중 메뉴).
- 다른 목록에도 있는 클래스: 같은 클래스라도 메뉴(화면번호)가 다르면 각각 ID를 둔다. 먼저 변환한 쪽의 API·화면을 재사용한다.
- 급여·카드·경비·연봉성 화면은 개인정보·민감정보가 있을 수 있다. 분석 때 `sys06_sensitive_info_yn`·`sys06_personal_info_yn`을 확인해 권한 처리를 정한다.
- 이미 변환한 같은 접두사 클래스의 API·조회창은 분석 때 먼저 확인해 재사용한다. 줄·서비스·테이블 수는 분석 단계에서 채운다.
