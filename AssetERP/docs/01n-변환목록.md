# 01n. 변환목록 (책무관리 — Tdm)

`01m-변환목록.md` 다음에 이어지는 상태판이다. 상태는 ID가 속한 파일에만 적는다. ID는 `N` 접두사(N01~N29)로 01a의 A·B·C, 01b의 D, 01c의 E, 01d의 F, 01g의 G, 01h의 H, 01i의 I, 01j의 J, 01k의 K, 01l의 L, 01m의 M과 겹치지 않는다.
ID 하나의 기록은 `work/{ID 첫 글자}/{id}-작업방법.md`, `…-작업기록.md`, `…-결과확인.md`(예: N03 → `work/N/`).

- 상태: `대기` → `분석` → `백엔드` → `프론트` → `확인` → `완료`, 또는 `보류`(사유를 비고에).
- **다음 작업은 아래 표에서 상태가 `대기`인 첫 줄**(01a·01b·01c·01d·01g·01h·01i·01j·01k·01l·01m이 끝난 뒤). 순서는 사용자 지정(2026-10-20).
- 패키지는 도메인별(`biz.tdm`). 소스 색인은 `tdm/screens/`. 하위 클래스(팝업·조회창)는 분석 단계에서 `yunhee analysis screen <화면> --list`로 확인해 같은 ID에서 함께 한다. 다른 도메인 컴포넌트(예: 전자결재 편집창 `Apr01_Edit_ApprDoc`)는 링크만 있으므로 01d·01g처럼 **1단계만** 할지 분석 때 정한다.
- 메뉴 열의 번호는 이 ID가 대표로 삼는 메뉴다. 같은 클래스가 여러 메뉴에 걸리면 나머지는 비고에 적고, 결과확인 항목 9(메뉴 여러 개)에서 같이 확인한다.
- 이 목록은 사용자가 준 클래스 목록을 `docs/as-is/src/menus.md`에서 찾아 만들었다(2026-10-20). 모두 대메뉴 `책무` 아래이고 묶음은 `00. 대시보드`(N01~N03), `01. 기본정보`(N04~N10), `02. 책무구조도`(N11~N14), `03. 부서책무매뉴얼`(N15~N19), `04. 책무이행점검`(N20~N24), `90. 책무관리현황`(N25~N29)이다. 순서는 사용자가 준 목록 순서 그대로다(메뉴 순서와 일부 다름).
- 29개로 큰 도메인이다. `Tdm` 화면은 임원·책무·직책 마스터(`01. 기본정보`)를 서로 참조할 가능성이 크므로, `01. 기본정보` 쪽 API·부품을 다른 ID가 재사용하는지 분석 때 확인한다. 대시보드(N01~N03)는 다른 화면의 집계를 읽을 수 있어 뒤로 미루는 편이 나을 수 있다 — 순서 조정은 사용자 결정.
- 줄·서비스·테이블 수는 분석 단계에서 채운다.
