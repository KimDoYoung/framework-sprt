# 10. UX보강

원본을 그대로 옮기는 원칙(03 원칙 4·5·12)의 **유일한 UX 예외**를 모아 두는 등록표다(03 원칙 14). 사용자 결정 2026-10-15.
사용자는 진행하면서 이 표에 항목을 계속 추가한다. 다른 문서(03·05·06·CLAUDE.md)는 이 파일만 가리키고 항목 내용을 옮겨 적지 않는다.

## 정의

- **UX보강** = 기능·데이터·SQL·메시지 흐름은 원본과 같고, **공통 부품 안에서만** 사용성을 높이는 것.
  화면 코드는 부품을 쓰기만 하고, 화면마다 따로 UX를 바꾸지 않는다.
- 판정: 원본의 위젯·버튼·처리 순서가 바뀌면 UX보강이 아니라 **개선**이다 → 03 원칙 5(제안 후 사용자 승인). 승인된 개선은 아래 "관련 개선" 표에 둔다.
- 표기는 띄어쓰기 없이 `UX보강`, 항목 ID는 `UX-NN`.

## 항목 추가하는 법 (사용자)

1. 아래 등록표 끝에 행을 하나 더한다. ID는 다음 번호(`UX-NN`), 상태는 `제안`, "이름"과 "동작"만 채워도 된다.
2. 에이전트가 부품을 만들거나 고치는 작업(01 B표의 ID)에서 "부품"·"화면에서 쓰는 법"·"06 대조 처리"를 채우고 상태를 `부품완료`로 바꾼다.
3. 그 뒤로 변환하는 화면은 `부품완료` 항목을 적용한다(05 §2 프론트). 이미 끝난 화면은 "끝난 화면 일괄 적용" 표의 ID로 한꺼번에 적용한다.

상태 값: `제안`(아직 부품 없음 — 화면에 적용하지 않음) / `부품완료`(새 화면에 적용) / `보류`(이유를 동작 칸에).
