# OMS 전환 사전작업 계획 (토큰 절약 + 품질)

## Context
AS-IS Asset-OMS(`~/workspace26/Asset-OMS`, GWT/GXT, 패키지 `myOms`, Java 548개 / 매퍼 XML 37개 / 화면 177개)를
`OMS/`(init-sprt.sh 골격)에 Spring Boot + React로 전환한다. 목적은 AssetERP 전환에 무엇이 필요한지 가늠하는 것이다.
결정 사항: **DB는 로컬 asseterpdb**, **메뉴는 DB(sys06_menu) + role 기반**,
**asseterpdb에 없는 테이블을 쓰는 화면은 전환하지 않는다**(테이블을 새로 만들지 않음).

핵심 원칙: 화면마다 원본을 읽고 규칙을 다시 추론하는 비용을 없앤다.
→ (1) 색인으로 "무엇을 읽을지"를 고정하고, (2) 변환 규칙과 레퍼런스 화면을 한 번만 만들어서
   이후 화면은 "레퍼런스처럼 변환"으로 짧게 지시한다.

조사로 확인한 사실:
- `tools/src-index.py`는 원래 `myApp`으로 고정되어 있었다 → 2026-10-01 앱 패키지 자동 탐지로 수정(OMS 색인 가능).
- OMS 매퍼가 쓰는 테이블 69개 중 8개는 asseterpdb에 없다:
  `mst01_fund, mst02_sec, mst06_broker, mst07_account, mst08_market, tgt01_model, tgt02_model_detail, sys06_menu_down`
  → 이 테이블을 쓰는 화면(mst, tgt 계열 등)은 전환 범위에서 제외한다.
- OMS 프레임 클래스는 `client/app/`에 있다: `LoginPage, MainFrame, MenuOpener, MenuGrid, MyPage, StatusBar, LoginUser`.
- OMS `doc/`에는 CRUD 패턴 문서가 이미 있다: `crud_pattern_1.md`, `crud_pattern_2.md`, `OMS-그리드베이스-CRUD.md`, `구현내용정리.md`.
  모든 ID는 seq 함수로 얻는다(OMS CLAUDE.md 규칙).
- `security-test/`는 이미 AS-IS 테이블 기반 로그인으로 전환되어 있다(`docs/asis-db-연동.md` §7.2).
  JWT 쿠키, Redis, STOMP, Tenant 모듈은 `common.*`에 있다.

### P2. DB 정합성 (asseterpdb 기준)
- 없는 테이블 8개는 옮기지 않는다. 색인(P1)에서 이 테이블을 쓰는 화면을 찾아 제외 목록으로 만든다.
- **OMS SQL이 asseterpdb에서 그대로 도는지 확인한다.** DB는 docker 안의 localhost asseterpdb로 고정한다(omsdb는 쓰지 않는다).
  OMS 매퍼 SQL의 컬럼을 asseterpdb(`docs/as-is/db` 또는 `EXPLAIN`)와 대조해서 차이를 `docs/as-is/oms/schema-diff.md`에 적는다.

### P3. 변환 규칙서 1장: `docs/OMS-convert.md`
화면마다 다시 추론하지 않도록 AS-IS → TOBE 대응을 고정한다(짧게, 표 위주).
- 호출: `ServiceRequest("dom.Cls.method")` + `ServiceResult` → `GET/POST /api/v1/{domain}/{resource}` + `ApiResponse<T>`
- 서버: `myOms.server.{dom}.{Cls}#method(SqlSession, req, res)` → `{Domain}Controller/Service/Mapper`
  - 매퍼 XML은 **SQL을 그대로 옮기고**, 파라미터 Map은 record DTO로 바꾼다.
- 세션: `LoginUser` 필드 → JWT claim 또는 `SecurityContext` 대응표. 회사(tenant)는 `TenantResolver`로 얻는다.
- ID 채번: seq 함수 규칙은 insert SQL을 그대로 옮기면 지켜진다.
- UI: GXT `GridBuilder` CRUD(조회/초기화/저장/행추가/삭제/등록, Enter로 아래 행 이동, 음수 임시 ID)
  → AG Grid 공통 CRUD 훅/컴포넌트 1벌. OMS `doc/crud_pattern_*.md`를 요약해 반영한다.
  - 검색 폼, 팝업 편집 → antd Form, Modal
- 기존 `docs/TOBE-Framework.md` 네이밍/레이어 규칙을 참조한다(중복 기재하지 않음).

### P4. 범위와 우선순위 목록: `docs/as-is/oms/scope.md`
- 화면 177개(sys 96, emp 29, practice 27, org 10, mst 8, tgt 4, pln 3)를 **프레임 / 공통 / 업무 / 연습(practice)**으로 분류한다.
- 1차 범위: 로그인, 회사, 사용자, 메뉴, role(sys·org·emp 핵심) + 업무 대표 화면 1~2개(asseterpdb에 있는 테이블만 쓰는 화면 중에서 고름).
- 8개 테이블을 쓰는 화면은 "제외(테이블 없음)"으로 표시한다.
- practice 화면은 제외 후보로 두고 확정은 사용자가 한다.
- 각 행에 AssetERP 전환 시사점(공통화 가능 여부)을 한 줄씩 적는다. 이것이 최종 목적인 "가늠"의 산출물이 된다.

### P5. `OMS/CLAUDE.md` + 메모리
- `OMS/CLAUDE.md`(짧게): 원본 위치, 색인 경로(`docs/as-is/src/`, OMS로 생성했을 때), 규칙서, 레퍼런스 화면, DB=asseterpdb, 검증 커맨드.
- 메모리: OMS 전환 방침(DB 결정, 레퍼런스 화면 방식)을 project 메모리로 저장한다.
  `asis-source-location`에는 OMS 색인 경로를 추가한다.

## 토큰 운용 습관
- 화면 1개 = 세션 1개(`/clear`)로 한다. 지시에는 색인 파일 경로, 규칙서, 레퍼런스 화면만 넘긴다.
- 원본은 색인이 가리키는 파일·줄만 연다. GWT UI 코드(레이아웃 세부)는 스크린샷 1장이 더 싸다.
  AS-IS OMS 화면 스크린샷을 `docs/asis-oms/`(git-ignored)에 두는 것을 권장한다.
- 반복 패턴(CRUD 훅, 검색 폼)은 2번째 화면에서 공통 컴포넌트로 추출한다. 3번째부터 비용이 줄어든다.
